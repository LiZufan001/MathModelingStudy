# 03｜迁移手册：抽检、返工循环、随机策略评价与鲁棒决策

> 目标：以后遇到的题可能不是电子产品，也可能叫供应商验收、设备维修、返工再制造、医疗筛查、网络重传、质量控制。只要结构是“检测有成本、漏检有损失、失败后可能回流”，这套方法都能迁移。

---

# 1. 先识别题型骨架

这类题通常包含四种元素：

### 1.1 隐藏质量状态

对象有好 / 坏、合格 / 不合格，但不检测就不知道。

### 1.2 检测动作

检测不是免费的，但能减少下游风险。

### 1.3 加工与传播

上游缺陷会影响下游成品；即使上游正常，加工本身也可能引入缺陷。

### 1.4 失败后的反馈

次品可能：

- 报废；
- 拆解；
- 维修；
- 重新检测；
- 回到前一道工序；
- 被客户退回后再次处理。

只要同时出现“检测 + 反馈循环”，就应该立刻警觉：

> **这不是单次静态成本比较，而是一个随机动态决策系统。**

---

# 2. 第一条条件反射：统计参数和随机状态必须分开

假设次品率是 `p`。

有两种完全不同的不确定性：

## 参数不确定性

真实 `p` 不知道。

抽样得到 `k/n`，只是关于 `p` 的信息。

## 过程随机性

即使真实 `p=0.1` 已知，下一件零件到底坏不坏仍然随机。

很多模型把两者混在一起：

```text
抽样得到 p_hat=0.12
→ 从此把 p=0.12 当常数
→ 模拟生产
```

这样会丢掉参数估计误差。

正确的层次是：

\[
\text{data}\rightarrow\text{distribution/confidence set of }p
\rightarrow\text{production randomness given }p.
\]

这在任何“先估计、后决策”问题中都适用。

---

# 3. 第二条条件反射：抽样方案是“停止规则”，不只是样本量公式

题目如果说：

- 尽量少抽；
- 达到某个置信度就接收 / 拒收；

优先想到**序贯抽样**。

统一框架：

```text
状态 = (n, k)

每来一个新样本：
    更新 n, k
    若证据支持坏批次 → 停，拒收
    若证据支持好批次 → 停，接收
    否则 → 继续
```

对于二项质量数据：

\[
X\sim Bin(n,p).
\]

可以用：

- 精确二项单侧检验；
- Clopper–Pearson 单侧区间；
- SPRT；
- 贝叶斯后验概率停止。

---

## 3.1 什么时候选精确二项

适合：

- 样本量不太大；
- 需要容易解释；
- 题目直接给置信度；
- 不想依赖正态近似。

## 3.2 什么时候选 SPRT

适合：

- 真正强调平均检测次数小；
- 可以定义“可接受质量”与“不可接受质量”两个水平；
- 有明确 I/II 类错误控制。

例如：

\[
p_G=0.08,\qquad p_B=0.12.
\]

而不是逼着算法无限精细地区分 9.999% 与 10.001%。

---

# 4. 第三条条件反射：先算策略空间有多大

如果有 `d` 个二进制决策，总策略数是：

\[
2^d.
\]

先算它，再决定搜索方法。

经验上：

| 策略规模 | 首选 |
|---|---|
| `2^d` 很小 | 全枚举 |
| 中等但目标可精确计算 | 整数规划 / DP / branch-and-bound |
| 中等且单次评价带仿真 | 粗枚举 + ranking & selection |
| 极大、黑箱、非光滑 | GA / SA / ACO / 贝叶斯优化等 |

永远不要从“题目复杂”直接跳到“遗传算法”。

复杂的是**流程**，不一定是**策略空间**。

---

# 5. 第四条条件反射：有反馈回路就想到状态模型

如果流程是 DAG：

```text
零件 → 半成品 → 成品 → 结束
```

很多期望值可以直接递推。

一旦出现：

```text
成品 → 拆解 → 半成品 → 再装配
```

就有回路。

常用工具升级为：

- 吸收马尔可夫链；
- Markov reward process；
- 更新过程 / renewal reward；
- 离散事件模拟；
- MDP（如果动作还能随状态动态变化）。

---

# 6. Markov reward：小流程时最干净的解析框架

固定策略 `π` 后，若状态集合不大：

\[
V_\pi(s)=r_\pi(s)+\sum_{s'}P_\pi(s,s')V_\pi(s').
\]

矩阵形式：

\[
V=r+PV,
\]

所以：

\[
(I-P)V=r.
\]

解出 `V` 就得到：

- 期望成本；
- 期望收入；
- 期望返工次数；
- 期望检测次数；
- 期望达到吸收状态时间。

适用条件：

- 状态能清楚枚举；
- 概率转移规则稳定；
- 不需要跟踪海量个体库存。

---

# 7. 离散事件模拟：复杂多工序时最通用

模拟器不应该写成“为了得到答案的一段脚本”，而应该写成一个**数字实验台**。

输入：

```text
policy
quality_parameters
cost_parameters
random_scenario
initial_inventory
```

输出：

```text
revenue
purchase_cost
inspection_cost
assembly_cost
disassembly_cost
replacement_loss
sold_count
scrap_count
rework_count
final_profit
```

这样同一评价器可以被：

- 全枚举；
- GA；
- 灵敏度分析；
- 鲁棒优化；
- 参数校准

反复调用。

---

# 8. 生产质量传播的通用概率公式

如果一个成品需要多个输入全部合格，而且即使输入全合格，加工仍有条件缺陷率 `r`：

设进入工序的输入合格概率为 `q1,...,qm`，则成品合格概率：

\[
P(G)=\left(\prod_{i=1}^{m}q_i\right)(1-r).
\]

次品概率：

\[
P(B)=1-\left(\prod_{i=1}^{m}q_i\right)(1-r).
\]

这个公式可以递归用于多层装配。

特别注意：

> 题目里的“半成品/成品次品率”如果定义为“输入均合格条件下仍产生次品的概率”，就不能和上游次品率简单相加。

---

# 9. 检测动作的经济本质：花钱购买信息与风险过滤

对一个零件：

- 不检测：省检测费，但次品可能进入后续昂贵工序；
- 检测：增加当前成本，但减少未来失败概率。

检测的净价值可以粗略想成：

\[
\text{检测价值}
\approx
\text{避免的期望下游损失}
-
\text{检测成本}.
\]

下游损失可能包括：

- 无效装配成本；
- 后续检测；
- 拆解；
- 报废；
- 客户退换；
- 信誉损失。

这解释了一个可迁移规律：

> **越靠前的低成本检测，可能阻断越多后续损失；但如果后面已经有廉价而有效的集中检测，前端重复检测又可能浪费。**

---

# 10. 拆解 / 维修动作的经济本质：残值与未来机会

是否拆解不应只比较：

```text
拆解费 vs 零件购买价
```

而应比较：

\[
\text{回收材料的继续使用价值}
-
\text{拆解费}
-
\text{重新检测/加工成本}
\]

与直接报废的价值。

因此拆解价值取决于：

- 回收零件中正品比例；
- 零件购买价格；
- 拆解费；
- 回收后是否要检测；
- 后续装配价值；
- 当前库存是否短缺。

如果库存过剩，回收材料的边际价值可能很低。

这就是为什么更真实的模型往往需要库存状态，而不是只看单位价格。

---

# 11. 客户退货不是普通次品处理，它多了一层“服务义务”

市场流出的次品与厂内检出的次品不同。

它通常意味着：

1. 已经发生销售；
2. 客户要求换一件合格品；
3. 发生物流 / 信誉等损失；
4. 原次品又回到企业处理。

所以一次市场漏检的成本不是简单的：

\[
\text{replacement loss}
\]

而是一个完整后果链。

建模时要明确题面“调换损失”是否已经包含替换产品本体成本。2024 B 题附录明确说：

> 调换损失是“除调换次品之外”的额外损失。

因此替换产品本身的生产资源不能漏掉。

这种“损失字段是否已包含本金”问题，在保险、售后、维修、违约成本题中都很常见。

---

# 12. 第五条条件反射：随机目标函数不能像确定函数那样比较

假设两个策略真实期望利润只差 0.2 元，但单次利润标准差有 20 元。

跑 100 次仿真后，样本均值仍有标准误：

\[
SE=\frac{20}{\sqrt{100}}=2.
\]

此时看到：

```text
A = 52.4
B = 52.8
```

完全不足以证明 B 更好。

因此随机策略评价必须有：

- 重复次数 `R`；
- 均值；
- 标准差；
- 标准误；
- 置信区间。

---

# 13. Common Random Numbers：策略比较中的神器

这是最值得从仿真优化中迁移的方法之一。

假设要比较 A、B。

普通做法：

```text
A 用随机场景 A1...AR
B 用另一组 B1...BR
```

更好的做法：

```text
场景1同时跑 A、B
场景2同时跑 A、B
...
```

即：

\[
D_r=Y_r(A)-Y_r(B).
\]

如果两策略都受到“这一批原材料总体偏好 / 偏坏”的共同影响，差值会消去大量环境噪声。

然后直接对：

\[
\bar D
\]

做置信区间。

适用于：

- 仓储策略比较；
- 生产策略；
- 排队系统；
- 维修策略；
- 路径策略在随机交通下比较。

---

# 14. Ranking & Selection：当候选很多时，计算资源应该花在“难分的前几名”上

65,536 个策略没必要一开始每个都跑 100,000 次。

可以：

### Stage 1

所有策略各跑 100~500 个共同场景，粗略估计。

### Stage 2

淘汰明显差的 99%。

### Stage 3

前几十名增加到几千 / 几万次。

### Stage 4

对前几名做成对差值 CI。

这个思想叫：

> **把仿真预算分配给“排名不确定性最高”的候选。**

它比“所有策略一样多重复”更有效率。

---

# 15. 什么时候 GA 真正值得用

不是“二进制变量就用 GA”，而是满足下面几项时：

- 决策位很多；
- `2^d` 已无法枚举；
- 目标函数不可导；
- 目标由模拟器输出；
- 变量有强交互；
- 不容易建立精确 MILP / DP。

如果要用 GA，至少做三件事：

1. 多随机种子独立运行；
2. 保留精英；
3. 在小规模子问题上和穷举真值对照。

这样才能说明：

> GA 不只是“能跑”，而是“确实能稳定找到高质量解”。

---

# 16. 启发式算法的正确定位：搜索器，不是证明器

GA、SA、ACO 通常能提供：

- 高质量候选；
- 快速搜索；
- 非光滑黑箱下的实用方案。

但不能自然提供：

- 全局最优证明；
- 最优性 gap；
- 统计显著性。

所以论文语言应该写：

> “获得当前设置下的最优候选 / 稳定高质量策略。”

而不是自动写：

> “证明该策略为全局最优。”

如果策略空间本身可枚举，就最好直接补上精确基线。

---

# 17. 第六条条件反射：鲁棒性不是“参数上下浮动10%”就结束

先问参数是哪一种不确定：

### 单个标量参数

例如只有一个原材料次品率未知，可以画一维策略切换曲线。

### 多个参数独立/相关变化

例如 8 个供应商 + 3 道工序，必须考虑参数向量：

\[
\mathbf p=(p_1,\ldots,p_d).
\]

如果所有 `p_i` 一起升降，只是在高维空间看一条对角线。

更好的方法：

- 单参数 one-at-a-time 敏感性；
- 拉丁超立方抽样；
- 联合后验抽样；
- 最坏置信区域；
- Sobol / 方差分解（参数更多时）。

---

# 18. 决策鲁棒性最好用“后悔值”衡量

设某真实参数 `p` 下，最优策略价值为：

\[
V^*(p)=\max_\pi V(\pi,p).
\]

固定使用标称策略 `π0`，后悔值：

\[
R(\pi_0,p)=V^*(p)-V(\pi_0,p).
\]

如果：

```text
参数变化后 π0 不再第一
但只比第一少赚 1%
```

它可能仍然非常鲁棒。

反过来，如果一个策略在 90% 情景里第一，但剩余 10% 会巨亏，企业未必愿意采用。

所以至少报告：

- 平均 regret；
- 最大 regret；
- 95% 分位 regret。

---

# 19. “策略稳定区域”比一张最优策略表更有用

假设检测成本 `c` 和次品率 `p` 改变。

求：

\[
\pi^*(p,c).
\]

然后把平面划成区域：

```text
区域A → 前端检测
区域B → 只中间检测
区域C → 前端+末端全检
区域D → 不拆解
```

这就是**策略相图 / policy map**。

企业真正需要的不是：

> “p=0.1 时答案是 111...0...”

而是：

> “供应商质量恶化到什么程度，我应该切换检测策略？”

这比单点最优更能支持管理决策。

---

# 20. 参数后验 + 决策：一个非常实用的贝叶斯版本

如果某节点检测 `n` 件，发现 `k` 个次品，给 `p` 一个 Beta 先验：

\[
p\sim Beta(a,b).
\]

则后验：

\[
p|data\sim Beta(a+k,b+n-k).
\]

然后：

```text
for outer scenario = 1...M:
    从每个节点的 Beta 后验抽 p_i
    for policy:
        给定 p 向量评价生产利润
```

最终可以算：

\[
E[V(\pi,\mathbf p)|data].
\]

这把：

- 抽样；
- 参数估计；
- 生产决策

自然连成一个整体。

不要求一定用贝叶斯，但这个结构非常清楚。

---

# 21. 检测样本量和生产决策可以统一成“信息价值”

继续检测的成本是明确的。

继续检测的收益是：

> 参数更准 → 少选错策略 → 减少未来损失。

定义当前数据 `D` 下最优预期价值：

\[
V(D)=\max_\pi E[V(\pi,p)|D].
\]

再采一个样本后的期望价值：

\[
E[V(D+X)|D].
\]

样本信息价值：

\[
EVSI=E[V(D+X)|D]-V(D).
\]

当：

\[
EVSI < c_{test}
\]

时停止检测。

这是“尽可能少检测”的一个更高级定义：

> 不是统计上能不能再更准，而是再准一点还值不值钱。

# 22. 代码层面最重要的设计：随机数和业务逻辑分离

推荐：

```python
scenario = generate_scenario(seed, parameters)
result = simulate(policy, scenario, costs)
```

而不是：

```python
simulate(policy):
    内部到处 random.random()
```

前者允许：

- 所有策略共享同一情景；
- 完全复现；
- 单元测试；
- 调试同一随机世界下策略差异。

后者会让每次运行都漂，难以定位 bug。

---

# 23. 模拟器必须有“事件日志模式”

普通批量运行只输出汇总。

但调试时应该能打开：

```text
event 001: purchase part1 cost +4
002: inspect part1 cost +2 -> good
003: purchase part2 cost +18
004: assemble cost +6
005: product bad
006: final inspection cost +3
007: disassemble cost +5
008: recover part1 good
...
```

拿一个极小批次逐事件核账。

如果没有这种审计能力，复杂返工模拟出现利润异常时几乎没法查。

---

# 24. 推荐的验证层级

## Level 1：确定性极端情形

- `p=0`；
- `p=1`；
- 检测费=0；
- 拆解费极大。

## Level 2：小规模手算

只 1~2 套材料，枚举所有质量状态，与代码对照。

## Level 3：概率统计验证

例如模拟生成 1,000,000 个 Bernoulli，检查次品比例是否在统计误差内。

## Level 4：策略关系验证

把某项检测成本降到 0，最优策略不应反而更少检测（除非存在其他耦合，需要解释）。

## Level 5：搜索器验证

小维数时用穷举真值检查 GA / ACO 能否找回最优。

# 25. 报告结果时，最好同时给四种指标

不要只给“利润”。

建议：

### 经济指标

- 总利润；
- 单位产品利润；
- 总成本；
- 收入。

### 质量指标

- 出厂次品率；
- 市场退换率。

### 流程指标

- 检测次数；
- 拆解次数；
- 平均返工次数；
- 材料利用率。

### 风险指标

- 利润标准差；
- 95% CI；
- 亏损概率；
- CVaR / regret。

这样一个策略即使平均利润略高，但退货率和利润波动极大，也能被识别出来。

# 26. 比赛现场的算法选择树

```text
拿到生产决策题
│
├─ 是否有未知质量参数？
│   ├─ 是 → 二项/贝叶斯/序贯抽样
│   └─ 否
│
├─ 流程是否有返工回路？
│   ├─ 否 → 期望值递推 / DP / MILP
│   └─ 是
│       ├─ 状态少 → Markov reward / 吸收链
│       └─ 状态多 → 离散事件模拟
│
├─ 策略空间大小？
│   ├─ 小 → 穷举
│   ├─ 中 → branch-and-bound / 粗枚举+精评
│   └─ 大 → GA/SA/ACO/其他黑箱优化
│
└─ 参数来自抽样？
    ├─ 是 → 联合不确定性 + 鲁棒/后悔值
    └─ 否 → 普通敏感性分析
```

# 27. 90 分钟快速建模清单

如果比赛现场第一次看到类似题，先完成：

### 前 20 分钟

- 画流程图；
- 标所有成本、收入、回边；
- 列决策变量；
- 计算策略数。

### 20~40 分钟

- 明确质量传播概率；
- 明确抽样假设；
- 选利润比较口径；
- 判断解析 / 仿真路线。

### 40~70 分钟

- 写最小可用评价器；
- 用 `p=0` 等极端情况验算；
- 小规模策略穷举。

### 70~90 分钟

- 做第一张参数—策略关系图；
- 决定后续是扩大模拟、增加算法，还是先修评价器。

最危险的做法是：前 90 分钟都在讨论“用 GA 还是 ACO”，却没有一个能正确算利润的函数。

# 29. 什么时候不应该用蒙特卡洛

蒙特卡洛不是越复杂越高级。

若：

- 过程没有循环；
- 状态概率可以精确递推；
- 策略很少；

那么直接解析期望往往更好：

- 无随机误差；
- 速度快；
- 可解释；
- 更容易证明。

因此正确顺序是：

> **能解析就解析；解析状态爆炸再模拟。**

而不是：

> “题目有概率 → 蒙特卡洛。”

# 30. 什么时候不应该用遗传算法

若搜索空间只有几万、几十万，而且策略评价便宜：

> 直接枚举。

若模型能写成混合整数线性规划：

> 先试成熟求解器。

若阶段结构清楚、有最优子结构：

> 试动态规划。

GA 最适合：

- 黑箱；
- 非光滑；
- 大组合空间；
- 精确结构难利用。

“算法名多”不等于建模水平高。

# 31. 从 2024 B 可以带走的 12 条通用经验

1. 接收抽样是决策问题，不只是估计问题。
2. “尽量少抽”优先想到序贯停止。
3. 条件次品率与上游缺陷必须按概率树组合。
4. 返工让流程从 DAG 变成带环状态系统。
5. 小状态用 Markov reward，大状态用仿真。
6. 成本分类记账比一个大公式更不易出错。
7. 先算 `2^d` 再决定用不用启发式算法。
8. 随机目标必须报告估计误差。
9. 共同随机数能显著提高策略比较效率。
10. 鲁棒性应评价后悔值，而不只看“策略有没有变”。
11. 多参数不确定性不能只沿一条共同变化曲线检查。
12. 抽样量最终可以由信息价值和检测成本共同决定。

# 32. 最终模型记忆

以后再看到类似题，可以在脑中直接调用这条链：

\[
\boxed{
\text{抽样推断}
\rightarrow
\text{状态/事件模拟}
\rightarrow
\text{策略枚举或搜索}
\rightarrow
\text{统计比较}
\rightarrow
\text{鲁棒/后悔分析}
}
\]

再补一句最关键的工程原则：

> **优化器只能放大评价器的能力，也会放大评价器的错误。先把“一个策略到底值多少钱”做可信，再谈怎么搜索最优策略。**
