# 01｜从题目到模型：需求、价格、补货与商品组合

> 本文故意先不照着复旦获奖论文走，而是从官方题面重新建模。目标不是押中某个算法名，而是建立一套以后遇到“销量预测 + 动态定价 + 订货 + 商品组合”时可直接复用的思考框架。

---

## 0. 先把四问翻译成人话

官方题目给了四类数据：商品—品类映射、三年销售流水、三年批发价、近期损耗率。四问实际上是逐层加难：

### 问题1：先看懂市场

要回答两件事：

1. 不同蔬菜品类、不同单品的销量本身有什么规律？
2. 它们彼此是一起涨跌、互相替代，还是可能互补？

这不是简单算一张 Pearson 相关系数矩阵。销售量同时受**星期、季节、节假日、是否上架、价格、批发成本、促销、缺货**等因素影响。如果两个品类都在周末卖得多，原始相关系数很高，并不代表二者存在真正的互补关系。

### 问题2：品类层面做“价格 + 补货”联合决策

未来 7 天，每个品类都要决定：

- 补多少货；
- 卖多少钱；
- 批发价还未知，需要预测；
- 价格会反过来改变需求；
- 需求本身也不确定。

因此本质是**带价格敏感需求的随机库存/收益管理问题**。

### 问题3：从品类总量下钻到具体 SKU

除了利润最大化，还突然加入两个很典型的运营约束：

- 一共只能卖 27–33 个单品；
- 只要选择某单品，至少陈列 2.5 kg。

这会把问题变成：

> **商品组合选择（0-1） + 单品补货量（连续） + 单品价格（连续） + 品类需求满足约束。**

也就是一个混合整数、非线性甚至随机的联合优化问题。

### 问题4：承认现在的数据还不够

题目不是让你“再列几个变量”，而是要说明：

> **缺什么数据 → 它修复模型中的哪个盲区 → 为什么会改善决策。**

---

# 1. 这道题最关键的概念：销量 ≠ 真实需求

很多数模论文在这里第一步就滑过去了。

数据库里看到的是实际成交销量 `Sales`，但真正想建模的是潜在需求 `Demand`。

两者可能满足：

```text
Sales = min(Demand, 可售库存)
```

而且还受到是否上架、价格、折扣和营业时间影响。

例如某种菜某天只卖了 2 kg，至少可能有三种解释：

- 顾客只想买 2 kg；
- 顾客想买 10 kg，但店里只有 2 kg；
- 这天根本没有正常上架，所以销量低。

三种情况写进时间序列后长得一样，但经营含义完全不同。

因此，全题最好从一开始就区分：

- `Y_it`：观察到的销量；
- `D_it`：潜在市场需求；
- `Q_it`：可销售库存/订货量；
- `P_it`：售价；
- `C_it`：批发成本。

有库存数据时，可以显式处理截尾需求；本题没有完整库存轨迹，所以至少在论文中要承认：

> **我们用销量近似需求，这是数据限制下的代理假设；若存在明显缺货，这个代理会低估真实需求。**

这句话比“销量就是需求”严谨很多。

# 2. 数据应该怎样整理

## 2.1 先构建一张“日 × 单品”的主表

销售流水是交易级数据，先按天汇总：

```text
日期
单品编码
品类
正常销量
折扣销量
退货量
销售额
成交均价
交易笔数
```

再拼接：

```text
当日批发价
近期损耗率
星期几
月份
节假日标签
是否周末
```

对于问题2，再向上聚合成“日 × 品类”；问题3则保留单品粒度。

## 2.2 退货与负销量必须先检查

销售流水若存在“退货”类型，不能简单把所有销量字段求和。

应先明确字段符号：

- 若退货记录本身是负数量，可以直接净额汇总；
- 若退货记录仍为正数量，就应根据销售类型转成负值；
- 同时可以单独保留退货率，作为问题4未来建模的数据线索。

## 2.3 “没有销售记录”不能一律填 0

一天没有某 SKU 的销售记录，可能是：

- 有货但没人买；
- 当天没进货；
- 季节性停售；
- 临时缺货；
- 数据缺失。

所以最合理的做法不是凭空把所有缺口统一处理，而是先构造一个**可售状态**变量。题目没有每日库存/上架表，因此只能使用近似规则，例如：

- 长期连续不出现：更像未经营/季节退出；
- 短暂缺口且前后都正常销售：可能是临时缺货或偶发缺失；
- 在问题3中，以 6 月 24–30 日有批发价格或销售活动作为 7 月 1 日候选 SKU 集，是一种可解释的运营近似。

## 2.4 品类价格不能简单平均

假设一个品类今天卖：

- 100 kg 的白菜，3 元/kg；
- 1 kg 的精品菜，30 元/kg。

简单均价是 16.5 元，完全失真。

更合适的是销量加权价格指数：

```math
P_{c,t}=\frac{\sum_{i\in c}P_{i,t}Y_{i,t}}{\sum_{i\in c}Y_{i,t}}
```

批发成本也类似：

```math
C_{c,t}=\frac{\sum_{i\in c}C_{i,t}Y_{i,t}}{\sum_{i\in c}Y_{i,t}}
```

再定义成本加成率：

```math
m_{c,t}=\frac{P_{c,t}-C_{c,t}}{C_{c,t}}
```

不过要注意：如果销量权重本身被价格影响，这个指数也是内生的，只能作为品类层面的经营指标，不能自动获得因果解释。

# 3. 问题1：分布规律与相互关系怎么分析才不流于“画图 + 相关系数”

## 3.1 第一层：描述销量分布

对每个品类、主要 SKU，至少计算：

- 日均销量、中位数、标准差；
- P10 / P25 / P75 / P90；
- 变异系数 `CV = std/mean`；
- 零销量天数比例；
- 销量最高的月份/星期；
- Top SKU 销量占比。

如果单品非常多，不应该 251 个单品每个都画一张图。更适合先按销量贡献筛选：

- 累计贡献 80% 的主力 SKU；
- 长尾 SKU 用总体统计描述。

### 一个值得额外算的指标：集中度

例如品类内部 SKU 份额：

```math
s_i=\frac{\text{SKU }i\text{销量}}{\text{该品类总销量}}
```

可算 HHI：

```math
HHI=\sum_i s_i^2
```

这样能区分：

- 一个品类是否由少数爆款主导；
- 还是销量分散到很多单品。

这会直接影响问题3的商品组合策略。

---

## 3.2 第二层：找时间结构

把日销量序列拆成：

```text
长期趋势 + 周周期 + 年周期 + 节假日 + 随机波动
```

可以使用：

- STL；
- Prophet；
- Fourier + 回归；
- GAM；
- SARIMA。

这里算法名不是重点，重点是：**先把共同时间效应剥掉。**

例如花叶类和辣椒类都在周末上涨，则原始相关可能很高：

```math
Corr(Y_{leaf},Y_{pepper})>0
```

但去掉星期、月份等因素后，对残差：

```math
r_{i,t}=Y_{i,t}-\hat{Y}^{time}_{i,t}
```

再计算：

```math
Corr(r_i,r_j)
```

才更接近“同一天额外买了 A 时，B 是否也额外卖得多”。

---

## 3.3 第三层：相关不等于替代/互补

两个 SKU 销量负相关，不能立刻写：

> “它们是替代品。”

因为负相关还可能来自：

- 上市季节相反；
- 供应周期不同；
- 一个贵的时候另一个恰好便宜；
- 上架策略不同。

真正研究替代/互补，更应该看**交叉价格效应**。

例如：

```math
\ln D_{i,t}
=\alpha_i+\beta_i\ln P_{i,t}
+\gamma_{ij}\ln P_{j,t}
+\text{time effects}+\varepsilon_t
```

其中：

- `β_i < 0`：自身价格越高，需求越低；
- `γ_ij > 0`：j 涨价后 i 卖得更多，可能替代；
- `γ_ij < 0`：j 涨价后 i 也卖得少，可能互补。

本题数据未必足以做强因果识别，但至少可以把“销量相关”与“经济意义上的替代/互补”分开。

---

## 3.4 单品太多时怎么降维

可以把 SKU 按以下特征聚类：

```text
平均销量
波动率
季节性强度
价格水平
毛利率
损耗率
零销量比例
```

聚出例如：

- 高频稳定主力；
- 强季节性；
- 高价低量；
- 高损耗；
- 长尾低频。

这比单纯按蔬菜名称分类，更能为问题3提供经营意义。

# 4. 问题2：为什么它不是普通“预测未来销量”题

官方要求同时给：

- 未来一周补货量；
- 定价策略；
- 收益最大。

如果先预测销量 `D_t`，再把价格当成优化变量，会出现逻辑冲突：

> 你预测需求时假设了一个价格，优化后价格变了，原来的需求预测就失效了。

所以必须写成：

```math
D_{c,t}=D_{c,t}(P_{c,t},X_t)
```

其中 `X_t` 是日期、星期、节假日、季节等外生因素。

---

# 5. 先预测“自然需求基线”，再估价格弹性

一种比赛里非常好解释的结构是：

```math
\ln D_{c,t}=\mu_c(t)-\epsilon_c\ln P_{c,t}+u_{c,t}
```

其中：

- `μ_c(t)`：如果价格保持正常水平时，由趋势/星期/季节/节假日产生的需求基线；
- `ε_c>0`：价格弹性；
- `u`：不可解释的随机需求波动。

也可以用半对数：

```math
D_{c,t}=\mu_c(t)+\beta_cP_{c,t}+u_{c,t},\quad \beta_c<0
```

如果历史可识别价格区间很窄，线性模型反而比高阶模型更稳。

## 5.1 为什么要先剥离时间效应

批发价本身也有季节性。

比如夏天：

- 某菜供应多，成本下降；
- 同时消费者需求也可能上升。

如果直接回归：

```math
销量 ~ 售价
```

就会把季节同时作用在价格和销量上的影响混进去。

正确思路是：

1. 先用日期特征解释大部分自然需求；
2. 再在剩余部分识别价格效应；
3. 或者在一个统一回归里同时放入时间和价格。

---

# 6. 批发成本也要预测，而且必须与需求预测分开

商超在前一晚做决策时，第二天批发价还未知。

因此要预测：

```math
\hat C_{c,t}
```

它可以用：

- Prophet；
- SARIMA；
- ETS；
- XGBoost + 日期特征。

验证时必须使用**时间滚动验证**：

```text
训练到 T → 预测 T+1…T+7
训练到 T+7 → 再预测下一周
```

不能随机切 80% / 20%，否则未来数据会泄漏进训练集。

---

# 7. 把需求不确定性放回补货模型：报童模型视角

蔬菜最大的经营特征是：

- 少订：缺货，丢失利润；
- 多订：当天卖不完，损耗严重。

这正是经典 **Newsvendor（报童模型）** 结构。

假设价格 `p` 已定，需求随机变量为 `D(p)`，订货量为 `q`。

若未售出商品残值为 `v`（完全报废时 `v=0`），单位成本为 `c`，则：

```math
\Pi(p,q,D)
=p\min(D,q)
+v(q-D)^+
-cq
```

求：

```math
\max_{p,q}\ E[\Pi(p,q,D(p))]
```

这比直接令：

```math
q=预测销量
```

更符合题面“需求不确定 + 易损耗”的经营本质。

如果考虑打折品：

- 正常销售部分价格 `p`；
- 品相下降可按 `dp` 打折；
- 严重损耗报废。

就可以用多段残值近似。

---

# 8. 固定价格时，最优订货量的直觉

经典报童模型中：

```math
F_D(q^*)=\frac{C_u}{C_u+C_o}
```

其中：

- `C_u`：少订 1 kg 的缺货损失；
- `C_o`：多订 1 kg 的过量损失。

如果售价高、缺货代价大，就应该订到需求分布更高的分位数；
如果损耗高、残值低，就应该保守订货。

这条直觉在写结果分析时特别好用：

> “不是预测 100 kg 就订 100 kg，而是看缺货成本与滞销损耗的相对大小决定安全分位数。”

---

# 9. 价格和订货量怎样联合优化

因为需求分布随价格变化：

```math
D(p)=\mu(p)+\sigma(p)Z
```

可采取比赛中较稳的两层算法：

### 外层：枚举/搜索价格

在历史价格附近给出可信区间：

```math
p\in[0.85p_{last},1.15p_{last}]
```

### 内层：给定价格求最优订货量

根据预测需求分布，用报童分位数或场景模拟求 `q*`。

最终选择：

```math
p^*=\arg\max_p E[\Pi(p,q^*(p))]
```

只有 6 个品类时，不一定非用复杂启发式算法。

一个稳定的离散价格网格 + 场景模拟往往更透明：

```text
每个价格候选
  → 预测需求分布
  → 求订货量
  → 计算期望利润
  → 选最大
```

若加入很多连续变量，再考虑模拟退火等算法。

---

# 10. 未来 7 天不能把“模型自己的预测”当成真实历史

如果 7 月 1 日还没发生，就不知道真实销量。

做 7 月 2 日预测时有两种正规方式：

### 方式A：一次性多步预测

在 6 月 30 日的信息集上直接预测 7 天。

### 方式B：滚动经营模型

真实运行中：

```text
7/1 结束
→ 得到真实销量/库存/价格
→ 更新模型
→ 再决定 7/2
```

但在比赛离线计算 7 天方案时，不能把 7/1 的“模型预测销量”无条件当成新真实观测，再继续训练，否则会形成**自生成数据反馈**。

如果必须滚动模拟，应明确写成场景模拟，而不是当成实际历史。

# 11. 问题3：先明确候选集合

官方要求：

> 根据 2023 年 6 月 24–30 日的可售品种，给 7 月 1 日方案。

因此先定义候选 SKU 集：

```math
\mathcal I=\{i:\text{6/24--6/30期间可售}\}
```

实际筛选可以参考：

- 最近一周是否有批发报价；
- 是否有成交记录；
- 是否存在损耗率信息。

不要把历史上出现过但近期已经退出供应的 SKU 一股脑加入优化。

# 12. 问题3的核心变量

对每个 SKU `i`：

```math
x_i\in\{0,1\}
```

表示是否上架。

```math
q_i\ge0
```

表示补货量。

```math
p_i\ge0
```

表示售价。

官方约束直接变成：

```math
27\le\sum_i x_i\le33
```

以及：

```math
q_i\ge2.5x_i
```

还需要一个上界：

```math
q_i\le M_ix_i
```

否则 `x_i=0` 时仍可能出现正补货。

`M_i` 可以取历史合理需求上界，而不是随便一个巨大常数。

---

# 13. “尽量满足各品类需求”要数学化

官方不是只让利润最大，还写了：

> 在尽量满足市场对各品类蔬菜商品需求的前提下。

可以设品类 `c` 的预测需求为 `D_c`：

```math
\sum_{i\in c}q_i\ge \rho_cD_c
```

例如 `ρ=0.9`。

也可以用软约束，把未满足需求加入罚函数：

```math
\max \; E[Profit]
-\lambda\sum_c(D_c-\sum_{i\in c}q_i)^+
```

软约束往往更自然，因为“尽量满足”本来就不是绝对必须满足。

---

# 14. 问题3为什么是商品组合问题，而不只是“给每个 SKU 算价格”

假设两个 SKU 都属于花叶类：

- A 毛利高，但销量很小；
- B 毛利一般，但是引流主力；
- C 与 B 高度替代；
- D 损耗特别高。

如果只逐 SKU 独立优化，可能同时选入大量互相替代的商品，浪费有限货架。

更合理的目标是：

```math
\max \; \text{总期望利润}
+\text{需求覆盖价值}
-\text{损耗风险}
-\text{冗余替代惩罚}
```

这才体现 27–33 个品种限制的意义。

---

# 15. 单品层价格—需求关系应该比品类层更谨慎

单品数据更稀疏、噪声更大。

常见问题：

- 某 SKU 只在特定季节出售；
- 价格只有少量档位；
- 缺货造成销量截断；
- 名称带编号的可能来自不同供应来源；
- 高价可能恰好对应高品质批次。

所以不要强迫每个 SKU 单独拟合一个复杂弹性曲线。

更稳的做法有：

### 层级模型

```math
\beta_i\sim N(\beta_{category(i)},\tau^2)
```

让样本少的单品向品类平均价格弹性收缩。

### 或者直接做分组弹性

对销量少的 SKU 使用品类弹性，对主力 SKU 再估独立弹性。

这是典型的 **hierarchical modeling / partial pooling** 思路。

# 16. 问题3求解算法怎么选

如果需求函数近似线性、利润函数可转为二次形式：

- 0-1 选品 + 连续补货 → MIQP / MINLP；
- 规模只有几十个 SKU，可以尝试商业求解器或开源求解器。

如果模型中含复杂预测器，目标函数无法解析：

- 遗传算法；
- 模拟退火；
- 粒子群。

都可以。

但启发式算法必须加：

1. **可行性修复**：保证 27–33 个、最小 2.5 kg、品类需求约束；
2. **多次随机重启**；
3. 报告最优/均值/标准差；
4. 与简单基线比较。

不能只写“遗传算法适合复杂问题，所以用了遗传算法”。

---

# 17. 问题4：应该补采什么数据

下面这些数据，每一项都对应本题的一个结构性盲区。

| 需要补采的数据 | 能解决什么问题 |
|---|---|
| 每日开店库存、补货量、闭店剩余库存 | 区分“销量低”与“缺货导致卖不出来”，恢复真实需求 |
| 缺货时点 / OOS 记录 | 修正需求截尾，识别潜在销售损失 |
| 每批次入库时间与保质/鲜度 | 建模随库存年龄变化的损耗与折价 |
| 当日实时供应商报价、可供量、交货可靠性 | 建模采购成本不确定性与供应约束 |
| 货架/冷库容量，最好按体积 | 把问题3的“27–33个”升级成真实空间约束 |
| 客流量、天气、温度、降雨 | 提升短期需求预测，尤其是日级预测 |
| 促销、会员券、活动标签 | 防止把促销造成的销量变化误认为普通价格弹性 |
| 竞品价格 | 识别替代需求和真正的价格敏感度 |
| 商品产地、品质等级、供应商 | 解释同名编号单品之间的质量/价格差异 |
| 退货原因与报损原因 | 区分质量问题、价格问题、供应问题 |

问题4写得好不好，就看有没有做到：

> **数据 → 参数 → 模型结构 → 决策改善**

而不是堆名词。

# 18. 模型验证：不要只看 R² / RMSE

这题至少有三层验证。

## 18.1 预测验证

使用 rolling-origin：

```text
训练到 t
→ 预测 t+1…t+7
→ 往前滚动
```

指标：

- MAE；
- RMSE；
- MAPE / WAPE；
- 区间覆盖率。

## 18.2 关系验证

价格弹性应该：

- 符号合理；
- 在不同时间窗口大致稳定；
- 去掉极端促销后不发生离谱翻转；
- 只在历史支持的价格范围内使用。

## 18.3 决策验证

最终最重要：

> 如果把历史某几周当作“未来”，用模型做订货和定价，理论利润是否比简单基线更高？

基线可以是：

```text
价格 = 上一日价格
补货 = 过去7日平均销量
```

或者：

```text
固定成本加成率 + 昨日销量补货
```

比较：

- 利润；
- 缺货率；
- 损耗率；
- 服务水平。

这叫 **decision backtesting**。

数模比赛里能做到这一层，论文可信度会明显高于只报告预测误差。

# 19. 这道题最容易犯的 10 个错误

1. 把实际销量无条件当成真实需求。
2. 缺失销售记录全部填 0。
3. 直接对原始销量做品类相关性，没去掉共同季节效应。
4. 看到销量负相关就宣布“互相替代”。
5. 用简单平均价格代表整个品类。
6. “先预测销量，再优化价格”，但价格改变后不重新预测需求。
7. 预测 100 kg 就机械补 100 kg，完全忽略需求不确定性和损耗。
8. 时间序列用随机 train/test split。
9. 遗传算法跑一次就宣称最优。
10. 只用 RMSE 证明模型有效，不回测实际利润。

# 20. 比赛现场的推荐路线

如果这题第一次出现在你面前，我会按下面顺序推进。

### 第 1 小时：清数据 + 建主表

先完成：

```text
交易流水 → 日×SKU → 日×品类
```

核对：

- 单位；
- 退货；
- 折扣；
- 缺失；
- 批发价；
- 类别映射。

### 第 2 小时：问题1 + 为问题2准备特征

画：

- 品类销量时序；
- 周/月季节图；
- 去时间效应后的相关矩阵；
- 主力 SKU 分布。

同时得到品类价格指数和成本指数。

### 第 3–5 小时：问题2核心闭环

```text
时间需求基线
+
价格效应
+
成本预测
→
价格敏感的随机需求
→
联合优化价格和补货
```

先做 6 个品类，保证闭环跑通。

### 第 6–8 小时：问题3

- 定义近期候选 SKU；
- 建 0-1 选品变量；
- 27–33 个约束；
- 2.5 kg 最小陈列；
- 品类需求服务约束；
- 求解并检查所有约束。

### 最后：问题4 + 回测 + 敏感性

重点分析：

- 价格弹性变化；
- 损耗率变化；
- 需求预测误差；
- 27/30/33 个品种限制对利润的影响。

# 21. 如果要做成一篇“稳”的论文，结构应该这样

```text
1 问题重述
2 数据处理
   2.1 日级销量构造
   2.2 价格/成本指数
   2.3 缺失、退货、异常
3 问题1：销量分布与关系
   3.1 时间规律
   3.2 去时间效应相关
   3.3 单品结构与聚类
4 问题2：品类层联合定价补货
   4.1 成本预测
   4.2 价格敏感需求
   4.3 随机补货利润模型
   4.4 7日策略
5 问题3：单品组合
   5.1 候选集
   5.2 混合整数模型
   5.3 求解与约束验收
6 问题4：新增数据
7 回测、敏感性与模型评价
```

不要按照“我们先用了模型A，再用了模型B，再用了算法C”的工具流水账写。

# 22. 本题真正应该形成的条件反射

以后看到：

> “未来销量 + 定价 + 补货 + 最大利润”

第一反应不是 Prophet，也不是遗传算法，而应该是：

```text
价格是否会改变需求？
↓ 是
需求模型必须把价格作为决策变量的一部分
↓
需求是否随机？
↓ 是
补货不能直接等于点预测
↓
是否易腐/有残值？
↓
报童/随机库存结构
↓
是否还有选品/容量限制？
↓
加入0-1商品组合变量
```

这就是 2023 C题最值得迁移的建模骨架。
