# 02｜高教社杯论文深度拆解：哪些地方真正强，哪些地方不能照抄

> 分析对象：复旦大学曹宇轩、黄瑞、秦一天《基于历史数据的蔬菜类商品定价与补货决策模型》，当前仓库保存的是**赛后正式发表版**，不是赛时原始提交稿。
>
> 本文的原则仍然是：**学它为什么能拿最高奖，但不把获奖等同于每一步都严谨。**

---

# 1. 先说结论：这篇论文真正强在哪里

如果只记“Prophet + 模拟退火 + 遗传算法”，就把最有价值的部分记丢了。

它最值得学的有四点。

## 1.1 它看到了“预测模型和优化模型必须耦合”

论文在引言中明确指出：

> 销量和价格相互影响，因此预测模型与优化模型应当相互耦合，而不是简单先后关系。

这是全题最重要的结构判断。

很多普通方案会写成：

```text
预测未来销量
→
预测批发价
→
给一个成本加成率
```

但如果价格是商超自己决定的，那么价格一变，销量预测也应当跟着变。

复旦方案把价格作为 Prophet 的外生变量，再在优化过程中反复调用需求预测器，这个结构方向是正确的。

## 1.2 品类价格没有使用简单均价

论文意识到品类内部 SKU 结构会变：

- 单品进入/退出；
- 各 SKU 销量占比改变；
- 高低价 SKU 混合。

因此使用**销量加权的品类销售价格指数和批发价格指数**。

这是非常值得迁移的数据工程细节。

## 1.3 它主动把“算法的可信作用域”限制在历史价格附近

论文没有把模拟退火包装成“万能全局最优”。相反，它指出：

> 线性价格—需求关系只在较小价格波动范围内有效，因此离上一日价格很远的数学全局最优可能没有实际意义。

于是使用较小扰动、较低初始温度，寻找上一日定价附近的局部最优。

这背后的真正思想是：

> **模型只在数据支持的局部区域可信，所以优化也应该待在这个区域。**

比“启发式算法很高级”重要得多。

## 1.4 问题3不是简单逐 SKU 算价格，而是加入选品约束

论文把：

- 是否上架 `x_i`；
- 补货量 `y_i`；
- 定价 `z_i`；
- 27–33 种；
- 最小陈列 2.5 kg；
- 品类需求满足度；

放进一个统一优化框架，再用遗传算法求解。

这才真正回应了“销售空间有限”的经营含义。

# 3. 数据预处理：优点与隐藏风险

论文披露销售流水共 **878,504 条**，先把交易级数据汇总为日级单品时序，再汇总成日级品类时序。

这是正确的粒度转换，因为问题2最终做的是“每天”的补货/定价，而不是日内小时级优化。

---

## 3.1 销量加权价格指数：值得保留

论文没有直接对品类内所有 SKU 的价格做算术平均，而是用销量作为权重。

这解决了一个重要问题：

> 低销量高价 SKU 不应该和主力低价 SKU 对品类价格产生同等权重。

在问题2中，这种价格指数比“平均售价”明显更合理。

### 但要再严谨一步

销量权重也是内生的：价格变化会影响销量，销量又成为价格指数的权重。

所以它适合做**经营描述指标**，但不能把它直接理解为一个外生价格变量的因果效应。

---

## 3.2 品类损耗率直接取单品均值：略粗

论文给出的平均损耗率为：

| 品类 | 平均损耗率 |
|---|---:|
| 花叶类 | 11.16% |
| 花菜类 | 9.17% |
| 辣椒类 | 8.00% |
| 食用菌类 | 8.30% |
| 水生根茎类 | 9.44% |
| 茄类 | 6.75% |

论文表述是把单品损耗率按品类分组后计算均值。

问题在于：

- 一天只卖 1 kg 的 SKU；
- 一天卖 100 kg 的 SKU；

对品类平均损耗率贡献相同。

如果用于利润决策，更好的方案是：

```math
l_c=\frac{\sum_{i\in c}w_i l_i}{\sum_{i\in c}w_i}
```

其中 `w_i` 取近期销量或预计补货量。

或者干脆保留 SKU 损耗率，在利润计算时再聚合。

---

## 3.3 “3天以内缺失前向填充”是一个很强的业务假设

论文将无销售记录分成：

- 短缺口：可能只是偶发未批发；
- 长缺口：可能季节性退出市场。

并采用：

- 3 天以内：前向填充；
- 超过 3 天：销量记 0。

优点是它没有把所有缺失机械填 0。

但问题也明显：

> **前向填充销量，相当于假设缺失日的需求接近前一天。**

如果真实原因是缺货、未上架或数据缺失，这样会人为制造销量。

更稳的做法是额外构造 `available` 状态；没有库存/上架数据时，至少做不同缺失规则的敏感性分析。

---

## 3.4 IQR 后用均值替换极端值：可能把“真实爆发需求”也洗掉

论文使用 IQR：

```math
[Q_1-1.5IQR,\;Q_3+1.5IQR]
```

识别异常，再用非异常日销量均值替换。

这对录入错误确实有效。

但蔬菜销量中的极端值未必是“错误”，它可能来自：

- 节假日；
- 大促；
- 季节集中上市；
- 特殊单品（粽叶等）的节令爆发。

尤其论文后面又显式建节假日效应，如果前面已经把节假日峰值替换成均值，会削弱真实信号。

更好的策略：

```text
明显数据错误 → 修复
可解释的业务峰值 → 保留
无法解释的极端值 → robust loss / winsorize / 标记异常变量
```

# 4. Prophet 模型：结构上合适，但验证表述偏乐观

论文的品类需求结构为：

```math
D_i(t)=g_i(t)+s_i(t)+h_i(t)+f(P_i(t))+\varepsilon
```

其中：

- `g`：趋势；
- `s`：周/年周期；
- `h`：节假日；
- `f(P)`：价格外生项。

这是本题非常自然的分解。

---

## 4.1 为什么 Prophet 在这里好解释

不是因为 Prophet 一定比 ARIMA 准，而是它能把需求拆成可解释组件：

```text
趋势
星期效应
年度季节性
节假日
价格
```

论文对花叶类的解释也很贴近业务：

- 周末销量高；
- 7–8 月较高；
- 国庆、清明、端午有变化；
- 春节消费结构可能变化。

数模论文中，这种“统计分解 ↔ 现实解释”很加分。

---

## 4.2 但表2的拟合水平并不能支持“非常良好”这种强表述

论文给出的 R²：

| 品类 | R² |
|---|---:|
| 水生根茎类 | 0.51 |
| 花叶类 | 0.55 |
| 花菜类 | 0.45 |
| 茄类 | 0.49 |
| 辣椒类 | 0.47 |
| 食用菌类 | 0.50 |

也就是大约只有 45%–55% 的波动被解释。

这对高噪声零售数据并不一定差，但也不能只看拟合曲线就说“非常良好”。

更关键的是，当前期刊版没有清楚说明：

- 指标是训练样本内还是留出集；
- 有没有 rolling-origin 验证；
- 7 日 ahead 的真实误差怎样。

因此：

> **它证明了模型能够解释一部分历史结构，但没有充分证明未来一周预测性能。**

---

# 5. 价格—销量关系：这是亮点，也是最大识别风险之一

论文先从 Prophet 中剥离趋势、季节、节假日，再研究剩余部分与价格的关系。

这个思路比直接：

```text
销量 ~ 售价
```

要好很多。

六类价格偏效应均为负：

| 品类 | 价格对销量偏效应 | 相关系数 |
|---|---:|---:|
| 花叶类 | -21.910 | -0.965 |
| 花菜类 | -3.327 | -0.966 |
| 辣椒类 | -3.694 | -0.881 |
| 食用菌类 | -3.215 | -0.914 |
| 水生根茎类 | -0.815 | -0.565 |
| 茄类 | -0.459 | -0.687 |

方向符合正常需求规律。

---

## 5.1 取 0.1 元邻域中值再拟合：是“降噪平滑”，不是新的因果识别

论文发现同一价格附近对应销量区间很宽，于是：

- 找价格差 0.1 元以内的点；
- 取中值；
- 再拟合线性关系。

这能明显让图更干净，对抗异常值也有效。

但它解决的是**噪声展示**，没有解决最根本的内生性：

> 商超并不是随机给价格。

价格可能因为：

- 批发成本变了；
- 需求预计变旺；
- 商品品质不同；
- 临期促销；
- 竞争环境变化；

才被调整。

所以负相关可以被解释为“价格敏感关系的证据”，但不能直接当严格因果弹性。

比赛里可以接受，真实经营上线时则要用更强识别：

- 控制更多混杂因素；
- 面板固定效应；
- 工具变量；
- A/B 价格实验。

# 6. 品类级利润模型：把预测器放进优化器，这是核心亮点

论文利润式大意为：

```math
\max_{P,Q}\sum_i
\left[
(P_i-C_i)Q_i(1-l_i)
+(d_iP_i-C_i)Q_il_i
\right]
```

并使用不含价格外生项的 Prophet 预测批发成本。

优化中：

```text
给一个候选价格
→ Prophet 预测该价格下需求
→ 计算利润
→ 模拟退火调整价格
```

这是完整的预测—决策耦合闭环。

---

# 7. 但变量语义出现了“销量 / 补货量”漂移

论文先把 `Q_i(t)` 定义为“销售总量”，随后又根据：

> 蔬菜必须当天售卖、不存在存货

令：

```math
Q_i(t)=D_i(t)
```

最后表5却把对应结果称作“日补货总量”。

这三者其实是不同变量：

```text
采购量 q
可销售库存
真实需求 D
成交销量 min(D,q)
```

如果损耗在销售前发生，采购量还应该高于最终成交量。

所以更严谨的变量系统应写成：

```math
q_i \rightarrow (1-l_i)q_i \rightarrow \min[D_i(p), (1-l_i)q_i]
```

再根据剩余品相、折价或报废处理残值。

当前论文把这些量近似合并，计算简洁，但真实含义被压缩了。

---

# 8. “损耗率”与“打折比例”也有语义混用

论文把 `Q_i l_i` 一部分解释为运损/品相变化后进行折扣销售，并乘折扣率 `d_i`。

但官方附件4只说：

> 损耗率反映近期商品的损耗情况，通过近期盘点周期的数据计算得到。

“损耗”不天然等于：

> “这一比例的货还能以折扣价卖掉”。

真实可能包含：

- 报废；
- 腐损；
- 蒸发失重；
- 挑拣损耗；
- 品相变差可折价；
- 运输损坏。

论文问题4后面自己也承认已有数据没有明确区分存货损耗和运输损耗。

所以比赛方案可以把它作为近似，但最严谨的表述应该是：

> **损耗率需要拆成“不可售损失”和“可降价销售的品质下降”两个过程。**

# 9. 模拟退火的选择：真正合理之处是“局部信任域”

论文以 2023-06-30 价格为初始点，模拟退火寻找附近局部最优。

它给了两个理由：

1. Prophet 被反复调用，目标函数不适合普通解析优化；
2. 价格—需求线性关系只在历史价格附近可信，因此不追求很远的全局最优。

第二个理由尤其好。

### 更规范的写法

与其靠“低温、小随机扰动”隐式限制，不如直接定义：

```math
|P_{i,t}-P_{i,t-1}|\le\Delta_i
```

或者：

```math
P_{i,t}\in[P_i^{10\%},P_i^{90\%}]
```

也就是显式 **trust region（信任域）**。

这样“模型在什么范围有效”变成约束，而不是算法参数的副作用。

# 10. 未来 7 天的递推方式存在“自生成数据反馈”风险

论文写到：

> 每一天预测结束后，将该日最优价格与成交量作为预测下一日可使用的历史数据，再用 Prophet 回归。

这在真实运营中，如果一天已经结束、真实数据已经观测到，是合理的滚动更新。

但比赛要求在 6 月 30 日时一次给出 7 月 1–7 日策略。

此时 7 月 1 日还没发生，所谓“成交量”实际上是模型预测出来的。

把它当成真实历史重新训练，会导致：

```text
模型预测
→ 写回训练集
→ 模型把自己的预测当事实
→ 再预测
```

误差可能逐日累积。

更稳的方式：

- 直接做 7 日多步预测；
- 或者明确做 Monte Carlo 场景滚动；
- 真实上线后才在每日结束时用真实观测更新。

# 12. 一个必须补上的随机性：为什么“预测多少就补多少”不够

论文认为蔬菜当天售卖，因此最优销量与预测需求持平。

但“当天售卖”并没有消除需求预测误差。

如果点预测 100 kg：

```text
真实需求可能 80
也可能 120
```

补 100 kg：

- 前者损耗；
- 后者缺货。

所以补货决策应该依赖**需求分布**而不是点预测。

这正好与同一期赛题解析文章形成有价值的对照：

- 吴萌、张驰、王志勇《“蔬菜类商品的自动定价与补货决策”问题解析》
- DOI：`10.19943/j.2095-3070.jmmia.2024.02.04`

其公开摘要明确提出：

- 剥离销量时间效应；
- 研究价格与销量耦合；
- 使用随机优化；
- 关键词包含 **报童模型（newsvendor）**。

这不是说复旦方案“错”，而是说明：

> **从竞赛优秀方案继续升级，最自然的一步就是把需求不确定性显式放进利润优化。**

# 13. 问题3：从 61 个候选 SKU 下钻到商品组合

论文先筛选：

> 2023-06-24 至 06-30 有批发价格数据的单品，共 61 种。

值得学。

更好的层级方案是：

> 品类层用强时间模型，单品层只预测“品类总需求如何分配到 SKU”，而不是 61 个 SKU 各自孤立预测。

# 14. 单品需求函数与利润模型

论文单品层利润：

```math
\max w=\sum_i(1-l_i)(z_i-c_i)y_i
```

并把线性需求反写成价格：

```math
z_i=\frac{y_i-\beta_{i0}}{\beta_{i1}}
```

若：

```math
y_i=\beta_{i0}+\beta_{i1}z_i,\quad \beta_{i1}<0
```

那么这个逆需求形式本身是数学一致的。

它使得：

> 补货/销量 `y` 决定对应能卖完的价格 `z`。

这样可以减少一个自由变量。

# 15. 约束设计是问题3最值得学习的地方

论文加入：

```math
27\le\sum_i x_i\le33
```

以及：

```math
2.5x_i\le y_i
```

还通过需求函数给每个单品销量上界，避免价格低于成本后无限扩大销量。

对每个品类 `G_j`，总进货量控制在预测品类需求的 0.9–1.1 倍附近。

这一层逻辑是完整的：

```text
选哪些
+
每个补多少
+
卖多少钱
+
总品类需求不能严重偏离
```

比单品独立贪心高级很多。

# 16. 一个文本一致性问题：61 个候选，模型却写 i=1,…,58

论文 3.1 明确写：

# 18. 为什么最优方案里会出现负利润 SKU

表8可见：

- 高瓜(1)：利润约 `-4.79` 元；
- 野生粉藕：利润约 `-16.54` 元。

乍看会觉得：

> 利润最大化怎么会主动选亏钱商品？

但有约束优化时，负局部利润不必然意味着全局错误。

可能原因：

- 为满足水生根茎类总需求覆盖；
- 为满足 27–33 个商品组合规模；
- 其他 SKU 的需求上界不足。

这恰好是一个很好的运筹学直觉：

> **最优组合里的每一个局部决策，不要求单独最优；它只需要帮助整体目标在约束下最优。**

不过论文没有给出影子价格/去掉该 SKU 后的对照，所以无法进一步判断这些负利润 SKU 是否“必要”。

# 19. 遗传算法：能跑，但“最优”证据不足

论文参数：

- 种群规模 40；
- 最大进化 500 次；
- 最终利润约 1408 元。

遗传算法适合黑箱和混合变量，但期刊版没有报告：

- 随机种子；
- 多次运行分布；
- 可行率；
- 与 MILP/MIQP 或简单贪心基线比较；
- 最优性 gap。

因此更严谨的说法应是：

> “遗传算法搜索到一个高质量可行解。”

而不是无条件把它称作数学意义上的全局最优。

如果重新做，我会至少：

```text
跑 20 个随机种子
报告 best / median / worst
检查每个解所有约束
与简单基线比较
```

## 21.1 但动态规划状态用“总库存量”可能不够

论文示意：

```math
f(s_k)=f(s_{k-1})+\sum_i z_{i,k}m_{i,k}
```

若 `s_k` 只是总库存量，就无法区分：

```text
100 kg 白菜
```

和：

```text
50 kg 白菜 + 50 kg 菌菇
```

它们的：

- 单价；
- 损耗；
- 保存时间；
- 明日需求；

都不同。

真正满足 Markov 性的状态更接近：

```math
S_k=(s_{1,k}^{age},s_{2,k}^{age},...,s_{n,k}^{age})
```

也就是按 SKU，甚至按库存年龄记录。

因此论文这里是**问题4的模型方向示意**，还不是可以直接运行的完整动态规划。

---

## 21.2 符号也有复用风险

问题3里 `z_i` 表示定价；问题4动态规划文字中又把 `z_{i,k}` 描述为利润。

比赛写作最好避免同一篇论文里改变符号含义。

比如统一用：

```text
p = price
c = cost
q = order
s = stock
π = profit
```

可读性会高很多。

# 25. 从最高奖论文中真正应该学到什么

不是：

> “2023 C题用 Prophet、模拟退火、遗传算法。”

而是：

### 第一层

**数据粒度要服务于决策粒度。**

交易流水先变成日级 SKU / 品类数据。

### 第二层

**把可解释的时间结构与价格效应拆开。**

否则成本季节性、需求季节性和价格会缠在一起。

### 第三层

**价格进入需求预测器以后，预测器必须嵌进优化器。**

这就是 predictive → prescriptive 的转变。

### 第四层

**模型可信范围决定优化范围。**

历史只支持局部价格弹性，就别优化到奇怪的极端价格。

### 第五层

**品类层解决总量，单品层加入组合约束。**

层级结构比把所有 SKU 一开始扔进一个大模型更稳。

### 第六层

**获奖方案仍然可以继续升级。**

本题最明显的升级方向是：

> 从“点预测 + 确定性补货”升级为“价格敏感随机需求 + 报童/场景优化 + 决策回测”。

这也是本仓库学习国一/最高奖论文的意义：

> **理解它为什么赢，同时知道下一步怎样比它更严谨。**
