# 03｜迁移手册：从“预测题”升级成“预测—决策一体化”

> 2023 C题表面是蔬菜零售，真正可迁移的对象是：**一个需求会被价格影响、需求又有随机性，同时还要决定订货与商品组合的经营系统。**
>
> 以后遇到机票、酒店、电商、餐饮、生鲜、库存、动态定价、供应链、收益管理题，都可以从这里迁移。

---

# 1. 第一条件反射：先问“观测到的销量等于需求吗？”

很多数据题默认：

```math
Y_t=D_t
```

但库存型业务里更常见：

```math
Y_t=\min(D_t,Q_t)
```

其中：

- `D_t`：潜在需求；
- `Q_t`：可供库存；
- `Y_t`：实际成交。

只要存在缺货，就有：

```math
Y_t<D_t
```

因此以后看到以下题型：

- 商店销量；
- 医疗床位使用；
- 酒店入住；
- 航班售票；
- 餐厅订单；

第一问都应该是：

> **数据记录的是需求，还是被容量截断后的成交？**

这一步决定后面的预测上限。

---

# 2. 第二条件反射：如果价格是决策变量，就不能只做普通预测

普通预测题：

```math
\hat D_{t+1}=f(X_t)
```

动态定价题：

```math
\hat D_{t+1}(p)=f(X_t,p)
```

这里 `p` 不是普通已知特征，而是我们自己要决定的。

因此优化结构必须是：

```math
p
↓
需求预测 D(p)
↓
利润/成本
↓
评价当前 p
```

而不是：

```text
先预测一个固定销量
→ 再随便改价格
```

这是 **predictive analytics → prescriptive analytics** 的核心转变。

---

# 3. 把时间效应与决策效应分开

销量通常可以写成：

```math
D_t=\text{time effect}+\text{decision effect}+\varepsilon_t
```

例如：

```math
D_t
=g(t)+s(t)+h(t)+f(p_t)+\varepsilon_t
```

其中：

- `g`：长期趋势；
- `s`：季节/星期；
- `h`：节假日；
- `f(p)`：价格影响。

为什么一定要分？

因为价格本身往往也有季节性。

如果直接做：

```math
D_t=a+bp_t
```

可能把：

> 夏季需求高、夏季成本低

误判成：

> 价格下降导致全部销量上升。

所以相关性/弹性分析前，优先剥离共同时间结构。

---

# 4. “先去季节，再算相关”是一个非常通用的套路

假设两个商品销量：

```math
Y_A(t),Y_B(t)
```

原始相关：

```math
Corr(Y_A,Y_B)
```

可能主要来自：

- 都在周末上涨；
- 都在夏天旺销。

更有意义的是：

```math
r_A=Y_A-\hat Y_A^{time}
```

```math
r_B=Y_B-\hat Y_B^{time}
```

然后计算：

```math
Corr(r_A,r_B)
```

适用题型：

- 多商品销量关系；
- 多地区旅游流量；
- 多站点客流；
- 能源负荷联动；
- 多资产共同趋势。

口诀：

> **先去公共时间因子，再看剩余联动。**

---

# 5. “相关”与“替代/互补”必须分层表述

## 销量相关

```math
Corr(Y_i,Y_j)
```

只能说明共同变化。

## 替代/互补

更关心：

```math
\frac{\partial D_i}{\partial p_j}
```

- `>0`：j 变贵，i 需求增加，可能替代；
- `<0`：j 变贵，i 也下降，可能互补。

所以以后遇到“商品关联”题，建议用三层证据：

```text
层1：共同时间趋势
层2：去时间效应后的残差相关
层3：交叉价格效应 / 因果证据
```

不要第一层就写“互补”。

---

# 6. 价格弹性最好写成经济含义清楚的形式

推荐 log-log：

```math
\ln D=\alpha-\epsilon\ln P+\cdots
```

其中 `ε` 直接是价格弹性：

```math
\epsilon=-\frac{\partial \ln D}{\partial \ln P}
```

例如 `ε=1.2`：

> 价格上涨 1%，需求约下降 1.2%。

相比：

```math
D=a+bP
```

它更便于跨品类比较。

不过如果历史价格区间很窄，局部线性完全可以接受。

原则是：

> **选择与你的数据范围匹配、可解释的最简单函数。**

---

# 7. 价格数据的最大陷阱：内生性

历史价格不是随机实验。

商家可能在：

- 需求旺时涨价；
- 成本高时涨价；
- 品质高时涨价；
- 临期时降价。

于是：

```math
p_t\leftrightarrow D_t
```

双方互相影响。

所以从历史观察数据估计价格弹性时，比赛层可做：

- 控制时间、成本、促销；
- 固定效应；
- 使用历史正常价格区间；
- 明确“关联而非严格因果”。

真实业务则进一步考虑：

- A/B 价格试验；
- 工具变量；
- 自然实验。

这条对电商/酒店/广告题尤其重要。

---

# 8. 点预测不等于订货量

预测：

```math
\hat D=100
```

不代表最优订货：

```math
q^*=100
```

订货要看预测误差和成本结构。

如果需求分布：

```math
D\sim F
```

固定价格时，经典报童模型：

```math
F(q^*)=\frac{C_u}{C_u+C_o}
```

- `C_u`：少订的损失；
- `C_o`：多订的损失。

因此：

```text
需求预测告诉你“可能卖多少”
补货优化决定“风险下应该订多少”
```

两者不是同一个问题。

---

# 9. 易腐商品为什么天然适合报童模型

报童模型的三大特征：

1. 一次性或短周期订货；
2. 需求不确定；
3. 剩余货价值显著下降。

蔬菜、面包、鲜花、机票、酒店房晚、时尚品首销，都符合类似结构。

通用利润：

```math
\Pi(q,D)=p\min(q,D)+v(q-D)^+-cq
```

如果有缺货罚：

```math
-b(D-q)^+
```

也可以加入。

当价格也可决策：

```math
\max_{p,q}\ E[\Pi(p,q,D(p))]
```

就变成 **price-dependent newsvendor**。

---

# 10. 联合定价—订货的稳健求解套路

如果只有少量品类，强烈推荐：

```text
外层价格网格
↓
每个价格下得到需求分布
↓
内层报童分位数求最优订货
↓
比较期望利润
```

优点：

- 容易解释；
- 容易检查；
- 不容易被黑箱优化骗。

只有当维度明显上升时，再上：

- 模拟退火；
- GA；
- PSO；
- Bayesian optimization。

竞赛原则：

> **先把评价器做对，再决定优化器多复杂。**

---

# 11. 信任域：不要让优化器跑到数据没见过的地方

历史价格只在：

```text
5–8 元/kg
```

有数据。

即使拟合函数在数学上允许：

```text
价格 20 元/kg
```

模型在那里的预测也不可信。

所以定义：

```math
p\in[p_{low},p_{high}]
```

或：

```math
|p_t-p_{t-1}|\le\Delta
```

这叫 **trust region** 思想。

适用于任何“模型后接优化”的数模题：

- 工艺参数优化；
- 能耗优化；
- 药物剂量；
- 定价；
- 配方优化。

模型的训练域就是优化器的安全边界。

---

# 12. 多步未来决策：区分 open-loop 与 rolling horizon

## Open-loop

今天一次决定未来 7 天：

```text
7/1–7/7 全部提前算出
```

只能使用今天已知的信息。

## Rolling horizon

每天结束后：

```text
观察真实销量、成本、库存
→ 更新预测
→ 重新优化后续天
```

真实运营几乎总应采用 rolling horizon。

比赛如果要求一次性提交未来一周结果，可以输出 open-loop 方案，并在论文中说明：

> 实际上线后建议每日滚动更新。

不要把模型自己预测的未来值假装成真实新数据。

---

# 13. 品类层与 SKU 层：优先使用层级建模

大规模商品系统不要 200 个 SKU 各做一套完全独立模型。

更稳的结构：

```text
总市场需求
↓
品类需求
↓
SKU份额
```

即：

```math
D_{i,t}=D_{c,t}\cdot s_{i|c,t}
```

其中：

- 品类总量更稳定，适合时间序列预测；
- SKU 份额负责细分。

SKU 样本少时，还可以做 partial pooling：

```math
\beta_i\sim N(\beta_c,\tau_c^2)
```

这类层级思想对：

- 店铺—商品；
- 城市—站点；
- 病种—医院；
- 设备—传感器；

都很好用。

---

# 14. 商品组合问题的标准数学骨架

对商品 `i`：

```math
x_i\in\{0,1\}
```

是否选。

```math
q_i\ge0
```

数量。

典型约束：

## 总品种数

```math
L\le\sum_i x_i\le U
```

## 最小陈列

```math
q_i\ge q_i^{min}x_i
```

## 未选择则数量为0

```math
q_i\le M_ix_i
```

## 货架容量

```math
\sum_i v_iq_i\le A
```

## 品类服务水平

```math
\sum_{i\in c}q_i\ge\rho_cD_c
```

这套骨架几乎可以直接迁移到：

- 菜单设计；
- 商品选品；
- 仓库 SKU 配置；
- 广告组合；
- 投资组合带 cardinality constraint。

---

# 15. “尽量满足”通常更适合软约束

如果题面说：

> 尽量满足需求。

不一定要写成硬约束：

```math
q\ge0.9D
```

也可以引入缺口：

```math
u_c=(D_c-\sum_{i\in c}q_i)^+
```

目标：

```math
\max Profit-\lambda\sum_cu_c
```

这有两个好处：

- 不会因为某个品类预测异常而整个模型不可行；
- `λ` 直接表示服务水平的重要程度。

以后看到“兼顾、尽量、优先保证”这类自然语言，都可以想到：

> **罚函数 / 多目标 / 软约束。**

---

# 16. 启发式算法不是免检通行证

如果用 GA / SA / PSO，至少做四件事。

## 16.1 可行性修复

每个候选解先修到：

```text
品种数合法
最小量合法
容量合法
服务水平合法
```

再评价。

## 16.2 多随机种子

例如 20 次：

```text
best
median
worst
std
```

## 16.3 与简单基线比较

例如：

```text
按利润率排序选前30个
```

如果 GA 连简单贪心都赢不了，就没必要写复杂算法。

## 16.4 报告收敛而不是只放一张漂亮曲线

应该回答：

- 多少代稳定；
- 多次运行是否接近；
- 最优值差异多少。

---

# 17. 黑箱优化的核心不是算法，而是评价函数

任何复杂优化题都可以问：

> 给我一个候选方案，我能不能可靠地算出它有多好？

本题评价器是：

```text
价格
补货
商品组合
↓
需求预测
↓
实际销售/损耗
↓
利润
↓
约束处罚
```

如果这个评价器错了，再高级的遗传算法只会更快地找到错误模型的最优解。

和 2023 A题、2024 A题一样，真正的核心都是：

> **先造可靠 evaluator，再谈 optimizer。**

---

# 18. 预测模型要怎样验证

## 时间序列不能随机切分

应该：

```text
训练 2020–2022
→ 验证 2023早期
```

或 rolling-origin。

## 需要多个 horizon

至少：

```text
1-day
3-day
7-day
```

因为任务最终是 7 日策略。

## 误差最好按经营量级归一化

除了 MAE / RMSE，还可以：

```math
WAPE=\frac{\sum|y-\hat y|}{\sum y}
```

否则 30 kg 的 MAE 对大品类和小品类含义完全不同。

---

# 19. 最终模型应该做“决策回测”

假装站在历史某一天：

```text
只给模型当时以前的数据
↓
预测明天
↓
生成价格和订货
↓
用明天真实数据结算
```

然后与真实/简单策略比较。

指标：

```text
利润
缺货率
报损率
服务水平
库存周转
```

这比：

> “R²=0.6，所以模型有效”

强得多。

---

# 20. 决策模型还要做敏感性分析

本题最值得测试的参数：

## 价格弹性

```math
\epsilon\times(0.8,1.0,1.2)
```

看最优价格是否剧烈跳变。

## 损耗率

```math
l\pm20\%
```

看补货是否过于敏感。

## 需求波动

扩大预测残差：

```math
\sigma\times(0.5,1,1.5)
```

看订货安全量变化。

## 商品数量限制

```text
27 / 30 / 33
```

看增加 SKU 是否真的增加利润。

这些图通常比“算法参数敏感性”更有经营含义。

# 21. 数据缺口应该直接映射到模型结构

一个很实用的模板：

```text
我们现在不知道什么？
↓
它导致哪个变量不可识别？
↓
新增什么数据？
↓
模型会怎样改变？
```

例如：

### 不知道是否缺货

→ 销量不能等同需求

→ 采集库存和 OOS 时点

→ 可以做 censored demand estimation

### 不知道库存年龄

→ 无法估计腐损/折价

→ 记录批次与入库时间

→ 做 age-dependent inventory model

### 不知道真实货架容量

→ 只能用“27–33种”做代理

→ 采集体积和货架空间

→ 替换为真实容量约束

这就是高质量问题4的写法。

# 22. 什么时候该用 Prophet，什么时候不该执着于 Prophet

适合：

- 日级数据；
- 明显周/年季节性；
- 节假日重要；
- 需要解释分量。

不一定适合：

- SKU 极稀疏；
- 大量间歇需求；
- 价格响应高度非线性；
- 需要严格概率预测。

替代：

- SARIMA / ETS；
- GAM；
- XGBoost/LightGBM + lag features；
- Croston/TSB（间歇需求）；
- hierarchical forecasting；
- probabilistic forecasting。

比赛最正确的问题不是：

> “Prophet 高级吗？”

而是：

> “它是不是匹配这个数据结构？”

---

# 23. 什么时候该用报童模型

看到以下词：

```text
需求随机
一次订货
剩余损失
缺货损失
保鲜期短
过期
座位/房间不能跨期
```

立刻想到：

> Newsvendor / stochastic inventory

如果需求还被价格控制：

> price-dependent newsvendor

如果跨多天、有库存滚存：

> multi-period inventory / dynamic programming / MDP

这是一个很值得形成的模型树。

---

# 24. 什么时候该上动态规划

必须存在真正跨期状态：

```text
今天的决定
→ 改变明天的库存/年龄/资源
→ 影响明天决策
```

状态不能只取一个总量，如果组合不同会改变未来。

例如蔬菜：

```math
S_t=(库存SKU, 每个SKU数量, 库存年龄)
```

如果今天货必须全部清零，反而不一定需要 DP；每天独立的报童模型可能更自然。

所以：

> **不是题目有“多天”就必须动态规划。**

要看是否存在跨期状态。

# 25. 一张通用决策树

以后拿到零售/供应链题，可以这样判断：

```text
是否要预测需求？
│
├─ 否 → 直接优化
│
└─ 是
   │
   ├─ 需求会被我的决策影响吗？
   │   ├─ 否 → forecast → optimize
   │   └─ 是 → decision-dependent forecast
   │
   ├─ 需求有不确定性吗？
   │   ├─ 可忽略 → 确定性优化
   │   └─ 重要 → stochastic / robust optimization
   │
   ├─ 剩余库存跨期吗？
   │   ├─ 否 → newsvendor / 单期
   │   └─ 是 → multi-period / DP / MDP
   │
   └─ 有选品/开关变量吗？
       ├─ 否 → 连续优化
       └─ 是 → mixed-integer optimization
```

# 26. 竞赛写作里最值得画的 6 张图

1. **品类日销量时序图**：展示周/年结构。
2. **去时间效应后的价格—需求图**：支持价格弹性。
3. **残差相关热力图**：回答问题1而不被共同季节性骗。
4. **预测区间图**：不是只画一条未来曲线。
5. **价格—期望利润曲线**：解释为什么选择该价格。
6. **商品组合约束验收图/表**：品种数、品类服务水平、利润。

这些图都直接回答“为什么”，比堆算法流程图更有价值。

# 27. 一篇成熟论文的自检清单

提交前逐项问：

- [ ] 销量和需求是否混用了？
- [ ] 缺失记录为何是0/为何插值，解释了吗？
- [ ] 价格是外生变量还是决策变量，结构写清楚了吗？
- [ ] 时间效应与价格效应是否分离？
- [ ] 预测是否使用时间顺序验证？
- [ ] 补货是否考虑需求误差？
- [ ] 优化器是否被限制在模型可信域？
- [ ] SKU 选择变量与补货量是否通过 Big-M/上下界联动？
- [ ] “尽量满足”是否被数学化？
- [ ] 启发式算法是否多次运行？
- [ ] 结果是否逐条验收约束？
- [ ] 最后有没有回到利润/缺货/损耗评价？

# 28. 最终模型记忆卡

遇到：

> “历史销量 + 未来定价 + 补货 + 选品 + 最大利润”

脑中先出现：

```text
Observed sales
≠
latent demand

Demand
=
Time effect
+
Price effect
+
Noise

Price
→ Demand distribution
→ Order quantity
→ Expected profit

SKU selection
→ Binary variables
→ Capacity / assortment constraints
```

然后才决定用：

```text
Prophet / GAM / SARIMA
Newsvendor
MILP / MIQP
SA / GA
```

模型名永远排在问题结构之后。
