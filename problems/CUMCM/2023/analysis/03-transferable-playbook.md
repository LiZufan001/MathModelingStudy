# 03｜2023 A题迁移手册：以后遇到什么题，应该想到这些方法

> 这一篇不再讲“定日镜”。目标是把2023 A题压缩成一套以后可以复用的思考框架。

---

# 1. 先给这道题贴正确的标签

不要把它记成：

> 太阳能题 / 蒙特卡洛题 / 双层规划题。

更有用的标签是：

> **昂贵黑箱评价 + 高维空间设计 + 几何约束 + 多阶段降维优化。**

因为以后题目可能换成：

- 无人机基站布局；
- 雷达/传感器布置；
- 仓储货架设计；
- 光伏阵列排布；
- 风机布局；
- 路灯/摄像头覆盖；
- 卫星星座；
- 物流网点；
- 避障路径规划；

但真正的数学结构可能和2023 A题很像。

---

# 2. 看到“先评价、再优化”，先造 evaluator

常见题面：

> 给定一种方案，计算若干性能指标；随后设计方案使某指标最优。

这时第一反应应该是：

```text
方案 x
 ↓
evaluate(x)
 ↓
目标值 f(x) + 约束 g(x)
```

第一问实际上是在定义后续优化器需要调用的函数。

### 现场自问

- 如果所有设计变量都已经给定，我能不能算出最终目标？
- 每次评价需要哪些中间步骤？
- 哪些步骤解析可算？
- 哪些步骤只能仿真？
- 哪些步骤最耗时？

如果这几问还没回答，不要急着讨论遗传算法、粒子群。

---

# 3. 复杂总体性能：先分解损失机制

2023 A题有：

`总效率 = 遮挡 × 余弦 × 大气 × 截断 × 反射率`

这背后是一个通用套路：

> **把一个复杂总指标，拆成多个有物理/业务意义的环节。**

例如通信系统：

`有效吞吐 = 原始速率 × 覆盖率 × 可用率 × 成功传输率`

生产系统：

`有效产量 = 理论产能 × 开机率 × 良率 × 利用率`

物流：

`服务效果 = 覆盖 × 时效 × 成功率 × 成本效率`

好处：

1. 每一项更容易建模；
2. 每一项都可以单独验证；
3. 最终能解释瓶颈；
4. 后续优化有方向。

---

# 4. 什么时候应该想到 Monte Carlo

## 4.1 典型信号

如果你发现目标其实是：

> “大量随机/连续情况中，有多大比例满足一个复杂条件？”

例如：

- 光线是否成功命中；
- 随机误差下是否碰撞；
- 不确定需求下是否缺货；
- 随机风速下是否超限；
- 随机用户位置下是否覆盖；

Monte Carlo 就值得考虑。

## 4.2 尤其适合的情况

数学上类似：

`E[g(X)]`

或者：

`P(condition(X)=true)`。

而 `condition` 里面可能包含复杂仿真、几何相交、逻辑判断，没有漂亮的解析积分边界。

## 4.3 不要为了“高级”使用 Monte Carlo

如果一个积分可以直接精确算，或者低维数值积分很容易，就没必要随机抽样。

Monte Carlo 的核心优势是：

> 对维数和边界复杂度相对不敏感，但收敛慢。

# 5. Monte Carlo一旦进入优化，必须考虑“噪声”

这点比会写随机数更重要。

假设方案A和B真实目标差：

`0.0003`

但你的Monte Carlo标准误差：

`0.001`

那么优化器根本分不清A和B。

### 至少做三件事

#### 1. 样本数收敛

`N=100,200,500,1000,...`

观察结果是否稳定。

#### 2. 多次重复

同一设计用不同随机种子跑若干次，估计均值和标准差。

#### 3. Common Random Numbers

比较不同方案时，尽量使用同一批随机样本。

这样随机波动会部分抵消，方案差异更清晰。

### 比赛论文中可以怎么写

> 当样本数由1000增至2000时，目标值变化小于0.X%，故后续优化采用1000条样本；最终候选方案再使用10000条样本复核。

这比只写“采用蒙特卡洛法”专业很多。

---

# 6. 看到“每个个体都有变量”，先警惕维数灾难

2023 A题如果逐镜优化：

`x_i,y_i,w_i,h_i,z_i`

几千面镜子就是上万个变量。

类似情况非常常见：

- 每个城市一个调度量；
- 每台设备一个参数；
- 每个时间点一个控制量；
- 每个像素一个决策；
- 每个节点一个资源分配；
- 每个区域一个政策强度。

第一反应不是“换更强优化器”。

第一反应应该是：

# **这些变量真的需要彼此独立吗？**

---

# 7. 高维变量的六种常见降维法

## 方法1：统一参数

所有个体先共用一个值。

例如问题2：所有镜子同尺寸、同高度。

最简单，适合基线。

## 方法2：分组

把个体按位置、类别、时间段分成K组，每组一个参数。

`N个变量 → K个变量`

## 方法3：函数参数化

`u_i = f(feature_i; θ)`

问题3就是：

`w_i=f(r_i)`、`z_i=g(r_i)`。

## 方法4：结构化生成器

不优化每个坐标，而优化生成规则。

如：

- 同心圆；
- 网格；
- 蜂窝；
- 螺旋；
- 分区密度。

## 方法5：基展开

时间控制量：

`u(t)=Σ a_k φ_k(t)`

只优化少数系数。

## 方法6：先聚类再优化

数据本身没有明显物理分组时，先聚类成若干类，再给每类一个策略。

# 8. 降维不是“偷懒”，而是建模假设

降维意味着：

> 你主动限制了可行方案空间。

因此应说明：

1. 为什么这个结构合理？
2. 它牺牲了什么？
3. 是否可以逐渐放宽？

最漂亮的写法不是直接说：

> 为简化计算，我们假设……

而是：

> 基于工程布置规律，我们首先限制在某结构族中求解；再逐步增加自由度，并比较性能增益，从而判断复杂度是否值得。

这就是2023 A题问题2→问题3非常值得借鉴的结构。

---

# 9. 一个通用的“逐级放宽”模型设计

以后遇到超高维设计，可以主动设计模型层级：

```text
Level 0：最简单统一参数
Level 1：少量分组
Level 2：线性/低阶函数
Level 3：分段函数
Level 4：更自由的个体优化
```

每升一级，记录：

- 目标提升多少；
- 计算量增加多少；
- 稳定性是否下降；
- 可解释性是否下降。

如果：

`Level 2 比 Level 1 只提升0.1%`

就没有必要为了“模型复杂”继续往上堆。

这叫**复杂度-收益权衡**。

---

# 10. 什么时候应该分层/交替优化

如果变量可以明显分成两类：

- A类变化会影响整个系统；
- B类只在A给定后局部调整；

就可以考虑：

```text
固定B → 优化A
固定A → 优化B
反复迭代
```

2023 A题：

- 塔位置：全局几何变量；
- 镜面尺寸、高度、密度：结构变量。

类似例子：

- 仓库位置 ↔ 配送路线；
- 基站位置 ↔ 用户资源分配；
- 生产线配置 ↔ 排产；
- 网络拓扑 ↔ 流量分配；
- 站点选址 ↔ 车辆调度。

### 注意

交替优化通常只保证局部改善，不自动保证全局最优。

所以最好：

- 多初值；
- 随机重启；
- 粗全局搜索；
- 最终方案交叉验证。

---

# 11. 昂贵评价器下，优化算法怎么选

不要按“算法知名度”选。

先看四个问题：

1. 变量维数多少？
2. 连续还是离散？
3. 评价是否有噪声？
4. 单次评价有多贵？

---

## 情况A：低维、平滑、便宜

可以：

- 网格；
- 梯度法；
- Nelder-Mead；
- pattern search。

## 情况B：低维、黑箱、可能多峰

可以：

- Differential Evolution；
- CMA-ES；
- PSO；
- 多起点局部优化。

但如果每次评价很贵，种群算法要谨慎。

## 情况C：低维但评价极贵

考虑：

- Latin Hypercube先采样；
- Gaussian Process / surrogate；
- Bayesian Optimization；
- 粗精度筛选 + 高精度复核。

## 情况D：高维

先别选算法。

**先降维。**

这是2023 A最重要的答案。

# 12. “粗到细”是比赛里最稳的优化节奏

推荐通用流程：

```text
粗模型/少样本
↓
大范围扫一遍
↓
找到若干好区域
↓
缩小范围
↓
更精细搜索
↓
最终候选用高精度模型复核
```

2023国一代码里其实已经有这个影子：

- 先粗网格找塔位置；
- 再在邻域内移动；
- 逐个参数用较小步长遍历。

更现代的实现可以更系统，但思路一样。

---

# 13. 几何仿真题如何降低计算量

2023 A的评价非常贵。

以后遇到类似题，可以从以下角度加速。

## 13.1 空间剪枝

只检查可能相交的邻居。

## 13.2 空间索引

KD-tree、R-tree、网格哈希。

## 13.3 向量化

一次计算很多光线，而不是Python/MATLAB深层循环。

## 13.4 并行化

不同镜子、不同时间点、不同随机样本天然可并行。

## 13.5 缓存

某些只依赖时间的太阳位置和DNI不要重复算。

## 13.6 多保真度

优化早期：少光线、少时间点。

最后：全60时点、大样本。

## 13.7 代理模型

用已经计算过的 `(参数 → 性能)` 数据训练一个近似函数，辅助筛候选。

# 14. 论文结果图应该服务于“下一步决策”

不要为了图多而画图。

2023 A里最有意义的是效率热力图，因为它回答：

> 镜场哪些区域效率高？损失为什么发生？塔往哪里移动可能更有利？

好的图通常属于三类：

### 诊断图

告诉你模型哪里有问题。

### 解释图

说明为什么结果会这样。

### 决策图

帮助选参数或方案。

如果一张图只是把表格又画了一遍，而且没有带来新的判断，它的价值就有限。

# 15. 做优化前的自检清单

在把 evaluator 交给优化器之前，至少问：

- [ ] 所有物理量单位统一了吗？
- [ ] 所有效率都在[0,1]吗？
- [ ] 几何方向的正负号通过简单场景测试了吗？
- [ ] 极端场景符合直觉吗？
- [ ] 随机模拟收敛了吗？
- [ ] 约束检查单独写成函数了吗？
- [ ] 目标函数重复运行是否稳定？
- [ ] 一次评价需要多久？
- [ ] 优化总预算大约允许多少次评价？
- [ ] 有没有不改变答案太多的降维/剪枝办法？

如果这些问题没有答案，直接跑PSO通常只是在烧时间。

---

# 16. 最终方案的自检清单

得到“最优解”以后，不要马上写结论。

至少检查：

- [ ] 60MW约束真的满足？
- [ ] 所有镜子都在350m圆区内？
- [ ] 塔周100m内无镜子？
- [ ] 相邻间距全部合法？
- [ ] 镜宽≥镜高？
- [ ] 边长2~8m？
- [ ] 安装高度2~6m？
- [ ] 镜子旋转时不会触地？
- [ ] 没有重复坐标？
- [ ] 高精度重新评价后仍然满足约束？
- [ ] 换随机种子后性能没有崩？

很多优化程序找到的是“数值上看起来最好、实际上不可行”的点。

**可行性检查和优化本身同等重要。**

---

# 17. 如何判断一个“优化模型”写得好不好

读论文时不要被算法名迷惑，问以下五件事。

## 1. 决策变量从哪里来的？

它们真的能被工程上控制吗？

## 2. 目标函数有实际意义吗？

还是为了方便计算随便构造？

## 3. 约束有没有漏？

有没有只在文字里说，代码却没检查？

## 4. 变量维数合理吗？

有没有本来可以参数化却直接暴力高维搜索？

## 5. 算法和目标函数性质匹配吗？

是连续、离散、有噪、不可微、多峰还是昂贵黑箱？

这五问比“用了什么模型”更重要。

---

# 18. 如何判断一篇国一论文值不值得学

不是看它有没有：

- 神经网络；
- 遗传算法；
- 粒子群；
- 模拟退火；
- 十几个公式。

而要看：

1. 题目结构有没有看对；
2. 假设有没有帮助把问题变得可解；
3. 模型与现实机制有没有对应；
4. 复杂度是否控制住；
5. 问题之间有没有复用；
6. 结果有没有验证；
7. 模型局限有没有承认；
8. 方案是否真正可输出。

2023这篇最值得学的是第2、4、5条。

# 19. 2022和2023放在一起，你应该形成两个不同套路

## 2022 A

题型信号：

- 动力学；
- 周期外力；
- 微分方程；
- 稳态功率；
- 参数优化。

思路：

```text
受力
→ ODE
→ 求解
→ 功率
→ 优化
```

## 2023 A

题型信号：

- 三维几何；
- 大量个体；
- 遮挡/命中；
- 评价函数昂贵；
- 布局优化。

思路：

```text
几何评价器
→ Monte Carlo
→ 降维参数化
→ 仿真优化
```

真正的数模能力就是：

> 先识别题目的数学骨架，再调出不同工具箱，而不是所有题都用同一套模型。

# 20. 比赛现场的通用决策树

```text
拿到题目
│
├─ 先问：题目要“预测 / 评价 / 优化 / 机理 / 分类”中的什么？
│
├─ 是否给出明确物理/业务机制？
│   ├─ 是 → 优先机制建模
│   └─ 否 → 再考虑数据驱动
│
├─ 目标函数能直接算吗？
│   ├─ 能 → 进入优化/分析
│   └─ 不能 → 先建立 evaluator / simulation
│
├─ evaluator 是否包含复杂概率/几何积分？
│   ├─ 是 → Monte Carlo / 数值积分 / 仿真
│   └─ 否 → 解析或确定性数值法
│
├─ 决策变量很多吗？
│   ├─ 是 → 分组 / 结构化 / 函数参数化
│   └─ 否 → 直接优化
│
├─ 一次评价贵吗？
│   ├─ 是 → 粗到细 / 代理 / 缓存 / 并行
│   └─ 否 → 可用更充分的全局搜索
│
└─ 最终：可行性 + 稳健性 + 误差 + 解释
```

把这棵树练熟，比背50种算法更有用。

# 21. 如果现在让你独立重做2023 A，建议的升级版流程

## Step 1：实现确定性几何模块

先不用Monte Carlo，主光线完成：

- 太阳方向；
- 镜面法向；
- 余弦效率；
- 大气透射；
- 射线矩形相交；
- 射线圆柱相交。

逐个单元测试。

## Step 2：加入光锥随机性

固定随机种子，生成统一随机方向池。

## Step 3：验证问题1

做：

- 样本数收敛；
- 全量/邻域遮挡对照；
- 典型镜面手工检查；
- 效率热力图。

## Step 4：建立问题2参数化布局

不必只限定同心圆，可比较2~3种候选布局族：

- 同心圆交错；
- 径向扇区；
- 简单Campo式。

先选有希望的布局族。

## Step 5：低精度全局搜索

用较少随机光线找到好区域。

## Step 6：高精度精修

候选点用完整60时点和大样本复核。

## Step 7：问题3逐级放宽

```text
统一参数
→ 线性径向参数
→ 分段径向参数
```

比较性能提升和复杂度。

## Step 8：论文最后一定给“为什么”

不要只写：

> 最优塔坐标为……

要写：

> 为什么塔偏向这个方向；哪些效率提高；代价是什么；约束为什么恰好活跃。

# 22. 给自己做的训练题

在不看国一论文的情况下，尝试完成以下任务。

## 训练1

用一张纸画出问题1的计算流程图，不写任何具体算法名。

要求最终能从：

`时间 + 镜子坐标`

走到：

`E_field`。

## 训练2

解释为什么：

- `η_cos` 适合解析计算；
- `η_sb` 更适合光线追迹。

## 训练3

假设有5000面镜子，每面 `(x,y,w,h,z)` 都可调。

至少提出三种不同的降维参数化方案，并比较优缺点。

## 训练4

设计一个实验，证明Monte Carlo使用500条光线已经足够，或者证明不够。

## 训练5

设计一个比论文“线性随半径变化”更自由、但变量仍不超过20个的问题3模型。

例如：5个径向分区，每区一组宽/高/安装高度。

## 训练6

如果优化器返回：

`59.99 MW，单位面积功率0.600`

和：

`60.02 MW，单位面积功率0.594`

哪一个是可行解？为什么不能因为前者目标更好就选它？

# 23. 本题的最终知识卡

以后看到下面这些关键词，可以联想到相应方法：

| 题目信号 | 优先想到 |
|---|---|
| 遮挡、碰撞、命中、可见性 | 几何相交 / ray tracing |
| 连续随机方向、复杂区域积分 | Monte Carlo |
| 数千个位置变量 | 结构化布局 / 参数化 |
| 每个个体参数可不同 | 分组 / 函数参数化 |
| 全局变量+局部变量 | 分块 / 交替 / 层次优化 |
| 一次仿真很慢 | 粗到细 / 剪枝 / 并行 / surrogate |
| 随机仿真嵌套优化 | 固定随机样本 / 收敛与方差分析 |
| 输出设计方案 | 约束检查 + 可复现文件 |

# 24. 学完2023 A真正应该留下的一句话

> **高维复杂设计问题，往往不是靠更强的优化器解决，而是靠更好的问题表示解决。**

2023这篇国一真正聪明的地方，就是不断改变“问题表示”：

```text
复杂光学损失
→ 用随机光线表示

几千个镜子坐标
→ 用同心圆规则表示

几千个尺寸和高度
→ 用半径函数表示
```

每改一次表示，原来不可算的问题就变得更可算。

这就是比“记住蒙特卡洛和双层规划”更深一层的数模能力。
