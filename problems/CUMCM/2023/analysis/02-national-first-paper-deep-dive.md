# 02｜中山大学国一论文深度拆解：他们为什么这样做，以及哪些地方不要照抄

> 分析对象：《定日镜场优化设计模型》
>
> 核心目标：不是给论文“打分”，而是区分三件事：
>
> 1. **真正值得迁移的建模思想**；
> 2. **只适用于本题的实现选择**；
> 3. **论文或公开支撑代码里需要警惕的近似、启发式和不一致。**

---

# 1. 先看整篇论文的骨架

这篇论文的摘要已经把完整路线说得很清楚：

```text
问题1
蒙特卡洛光线追迹
→ 建阴影遮挡 / 截断效率模型
→ 算给定镜场年均性能

问题2
同心圆密排布局
→ 把上千面镜子的坐标压缩为结构参数
→ 吸收塔规划 + 定日镜规划交替
→ 控制变量遍历

问题3
允许尺寸、高度不同
→ 不直接给每面镜子独立变量
→ 令尺寸、高度随同心圆半径变化
→ 继续低维优化
```

这篇能拿国一，最应该学的不是“模型名称多”，而是它每一问都在解决上一问暴露出的新困难：

```text
评价难
→ 光线追迹

优化维数太高
→ 结构化布局

问题3自由度再次爆炸
→ 函数参数化
```

这是一条非常完整的**问题驱动式建模链**。

---

# 2. 问题1：论文首先建立了一个“物理评价器”

论文没有把光学效率直接拟合成一个经验函数，而是把它拆成：

`η = η_sb η_cos η_at η_trunc η_ref`。

这个拆分很强，因为每个因子对应一个清楚的物理损失机制：

- `η_cos`：镜面投影损失；
- `η_at`：传播距离带来的大气损失；
- `η_sb`：入射/反射路径被镜子或塔挡住；
- `η_trunc`：反射光没有落在有限尺寸集热器上；
- `η_ref`：镜面材料反射率。

### 这一步为什么值得学

复杂系统经常没有一个直接可建的“总效率”。

好的做法是：

> 把总体性能分解成多个有物理意义、可单独建模、可单独验证的损失环节。

这样后面不仅能算总值，还能回答：

> 到底是哪种损失最严重？

他们的问题1结果显示余弦效率是明显短板，于是后面优化吸收塔位置就有了物理解释，而不是盲目调参数。

# 3. 光锥模型：他们为什么不是只追一根主光线

题目特别强调太阳光并非完全平行，而有一定锥形角。

论文的处理是：

1. 先建立太阳主光线；
2. 在与主光线垂直的截面中建立二维正态分布；
3. 把随机点转成一个小偏移向量；
4. 叠加到主方向上得到非平行入射光线；
5. 对大量随机光线进行追迹。

这是一个典型的：

**连续能量分布 → 概率分布 → 随机抽样。**

从数模角度看，这比“硬积分”更自然，因为后面还有复杂的遮挡布尔条件。

### 可迁移思想

如果你以后看到一个积分形式类似：

`∫ f(x) 1{复杂条件成立} dx`

而“复杂条件”是几何碰撞、可见性、命中区域等难以写成简单边界的东西，Monte Carlo 通常值得考虑。

---

# 4. 他们如何处理阴影遮挡：几何 + 局部剪枝

公开代码中的 `eta_caculate.m` 做了一个很实际的加速：

- 对目标镜先算与其他镜子的距离；
- 只取大约20m以内的邻近定日镜参与遮挡检查；
- 在目标镜上抽取点；
- 对每条光线做射线与矩形 / 圆柱相交判断。

这个20m邻域不是一个数学定理，而是**计算加速启发式**。

为什么他们需要这么做？

如果每面镜子都和全场3000面镜子逐一检查：

`3000 × 3000 × 光线数 × 60时点`

计算量会非常大。

利用“遮挡通常由空间邻居产生”的局部性，可以把每面镜子需要检查的对象大幅减少。

### 这条思想非常可迁移

以后遇到：

- 粒子碰撞；
- 车辆避障；
- 无线干扰；
- 空间邻接；
- 点云匹配；
- 路径冲突；

都应该问：

> 我真的需要全对全比较吗？能不能只检查局部邻域？

常见工具包括：

- 网格分桶；
- KD-tree；
- ball tree；
- 邻接表；
- 空间哈希。

国一代码用的是最简单的距离阈值筛选。

# 5. 问题1结果为什么不仅是“交表”

论文问题1得到：

| 指标 | 年平均结果 |
|---|---:|
| 光学效率 | 61.58% |
| 余弦效率 | 75.56% |
| 阴影遮挡效率 | 92.72% |
| 截断效率 | 99.80% |
| 输出热功率 | 37.629 MW |
| 单位面积输出热功率 | 0.599 kW/m² |

然后他们画效率热力图，观察镜场不同区域效率差异，并指出余弦效率和总体效率空间分布相近。

这是一个很好的论文习惯：

> **数值结果 → 空间可视化 → 找主导因素 → 为下一问优化提供方向。**

如果问题1只交六个数字，问题2就像从天上掉下来的。

而现在逻辑变成：

```text
发现余弦损失明显
↓
余弦效率强烈依赖塔与镜子的相对几何关系
↓
塔位置值得作为重要设计变量
```

这就是“问题之间有因果衔接”。

# 6. 问题2真正的核心：不是双层规划，而是“先把变量数砍掉”

题目本来允许你设计每面镜子的位置。

如果有 N≈3000 面镜子，仅位置就是约6000个连续变量。

国一论文没有直接优化这些坐标，而是参考工程布局，规定：

- 镜子围绕吸收塔形成同心圆；
- 同一圆上均匀排列；
- 圈间交错；
- 间距取接近最小安全距离。

于是每面镜子的坐标由生成规则决定。

这一步叫**结构化参数化**。

### 为什么这是整篇最值得学的地方之一

优化算法最怕的不是“算法不高级”，而是：

- 变量太多；
- 每次函数评价太贵；
- 约束太复杂。

如果你能利用场景知识把6000维压到5维，普通遍历都可能比6000维遗传算法靠谱。

所以以后遇到高维设计题，顺序应是：

```text
先问能不能降维
↓
再问用什么优化算法
```

而不是反过来。

---

# 7. 同心圆布局具体帮他们消掉了哪些变量

所有镜子同尺寸同安装高度时，原始变量可以写成：

`X_t,Y_t,w,h,z,{x_i,y_i}_{i=1}^N`。

同心圆密排以后：

- `x_i,y_i` 不再独立；
- 镜子总数 N 也由场地、半径、间距和排布规则间接产生；
- 镜间安全距离与宽度联系起来。

剩下真正需要搜索的主要只是：

- 塔位置；
- 镜面宽度；
- 镜面高度；
- 安装高度。

即使考虑排布细节，维数也低了几个数量级。

这才是“建模”而不是“套算法”。

# 8. 论文所谓“双层规划”到底是什么

论文把优化拆成两层：

## 上层：吸收塔规划

主要决策变量：

`(X_t,Y_t)`。

论文把年平均光学效率作为上层重点目标，搜索更有利的塔位置。

## 下层：定日镜参数规划

固定塔位置以后，再调：

- 安装高度；
- 镜面高度；
- 镜面宽度；
- 由布局规则产生的位置、数量。

目标是满足：

`E_field ≥ 60 MW`

并让：

`E_unit`

尽量大。

随后把下层结果反馈给上层，交替迭代。

### 更准确地理解

严格优化理论里的 bilevel programming 往往是：

`min_x F(x,y*(x))`

其中 `y*(x)` 本身是另一个完整优化问题的最优解。

这篇公开代码更接近：

**分块坐标搜索 / alternating optimization（交替优化） + 层次化启发式。**

论文叫“双层规划”可以理解，但学习时不要把名称神化。

真正值得迁移的是：

> 全局变量和局部结构变量影响层级不同，所以分块优化。

# 9. 他们实际上怎样搜问题2

公开代码非常有教学价值，因为能看到论文里“遍历、双层规划”背后的真实实现。

## 9.1 先粗搜塔位置

`a_q2.m` 先在 `[-350,350] × [-350,350]` 上取大约10×10网格，再删掉圆形场地以外的点。

对每个候选塔位置：

- 生成同心圆镜场；
- 计算年平均性能；
- 找一个较好的初始塔位置。

这就是典型的：

**coarse search（粗搜索）先找盆地。**

## 9.2 再做局部塔位置更新

`a_q2_2.m` 每轮在当前塔位置附近生成3×3邻域点，步长带一定随机性，然后选择光学效率最高的邻居。

这本质上像一个简单的 pattern search / hill climbing。

## 9.3 下层逐个变量扫描

固定塔以后，对：

- 安装高度；
- 镜面高度；
- 镜面宽度；

按0.25m步长做一维遍历。

每次只改变一个变量，其余保持不变。

这就是**控制变量法 / coordinate search（坐标搜索）**。

他们还重复调整高度，因为高度和宽度、安装高度存在耦合。

### 为什么这样做在比赛里很实用

评价函数很贵，又没有导数。

此时：

- 梯度法不好用；
- 高维全局搜索很慢；
- 变量已经被压到很少；

简单坐标搜索就很有吸引力。

比赛里不要小看“笨方法”。

如果模型结构合理、维数很低、每一步可解释，一个可靠的遍历经常比复杂黑箱优化更稳。

# 10. 问题2最终结果如何解释

论文给出的设计约为：

- 吸收塔：`(48.2,-126)`；
- 镜面尺寸：`5.75m × 5.75m`；
- 安装高度：`2.875m`；
- 定日镜数：3070；
- 总镜面面积：约101501.8m²；
- 年平均热功率：约60.023MW；
- 单位面积年平均热功率：约0.591kW/m²。

这里有两个值得理解的现象。

## 10.1 为什么总功率几乎刚好60MW

目标不是最大总功率，而是：

`单位面积功率最大，且总功率≥60MW`。

多放低效率镜子虽然会提高总功率，却可能降低单位面积产出。

因此最优方案贴着60MW约束很合理。

## 10.2 为什么单位面积功率反而低于问题1的0.599

问题1给定镜场只有约37.6MW。

问题2必须在同样有限场地内做到60MW，需要更多镜子、更大覆盖范围或更密排布，因而会引入：

- 更多遮挡；
- 更多远距离镜子；
- 较差位置的镜子。

所以“优化后单位面积指标一定超过问题1”并不是必然的。

约束变强以后，可行域不同了。

# 11. 问题3真正厉害的一步：再次降维

问题3允许：

- 不同镜子尺寸不同；
- 安装高度不同。

如果直接解锁3000面镜子的 `w_i,h_i,z_i`，变量又会爆炸。

作者没有这么做。

他们观察实际镜场规律并假定同一同心圆上的镜子参数相同，再进一步设：

`w(r)=A(r-100)+5.75`

`h(r)=B(r-100)+5.75`

`z(r)=C(r-100)+2.875`

其中只优化三个斜率 `A,B,C`。

于是：

```text
原来：几千个 w_i,h_i,z_i
↓
现在：3个函数斜率
```

这就是典型的：

**functional parameterization（函数参数化）。**

我认为这是这篇论文最值得你长期记住的两个招数之一，另一个是问题2的结构化布局。

---

# 12. 为什么“半径 r”是一个好解释变量

作者不是随便找一个变量做线性关系。

离塔距离会系统性影响：

- 传播距离；
- 大气透射；
- 反射角；
- 镜场密度；
- 遮挡；
- 光斑传播；
- 可利用空间。

因此镜子尺寸和高度随半径变化有一定工程依据。

这体现了一个很通用的建模习惯：

> 高维个体参数不要直接独立优化，先找一个能解释差异的低维特征。

例如：

- 配送点参数随距离仓库距离变化；
- 设备控制量随负荷变化；
- 价格随时间段变化；
- 农业施肥量随土壤指标变化；
- 网络资源随节点度数变化。

然后令：

`decision = f(feature; θ)`

真正优化的是少数 `θ`。

# 13. 问题3为什么只用线性函数

因为比赛时间有限。

最简单的函数族就是：

`a + br`。

优点：

- 参数少；
- 容易满足边界约束；
- 容易解释；
- 搜索快；
- 输出方案平滑。

缺点：

- 真实最优关系未必线性；
- 可能错过局部结构；
- 只能找到该函数族中的最优，而不是原问题全局最优。

论文自己也承认问题3只是局部最优，并把“线性关系过于简单”列为缺点。

这种诚实是好的。

### 如果比赛时间更充足，可以升级为

1. 分段常数：把半径分5~10个区间，每区一组参数；
2. 分段线性；
3. 二次函数；
4. spline；
5. 少量径向基函数。

自由度逐步增加，而不是一步解锁3000面镜子。

这叫：

**progressive relaxation（逐级放宽模型自由度）。**

# 14. 问题3结果为什么只提升一点点也有意义

问题3结果约为：

- 吸收塔：`(66.25,-113.23)`；
- 定日镜数：3075；
- 总镜面面积：约101016.98m²；
- 年平均功率：约60.01MW；
- 单位面积功率：约0.594kW/m²。

相比问题2：

`0.591 → 0.594 kW/m²`

提升不大。

但这并不说明问题3“没用”。

它说明在他们限定的结构空间中：

> 允许镜面参数随半径变化能继续获得一定收益，但问题2的统一尺寸方案已经相当接近这个结构族里的好解。

好的论文应该解释这种“小提升”而不是强行吹成巨大突破。

# 15. 为什么这篇论文能拿国一：真正强的地方

## 15.1 建模路线完整

问题1不是孤立计算，而是后面全部优化的评价器。

问题2、3一直复用同一物理评价逻辑。

## 15.2 复杂几何选择了合适的数值方法

阴影和截断边界复杂，使用光线追迹 + Monte Carlo 很自然。

## 15.3 面对维数灾难，没有硬上优化器

问题2用同心圆布局压坐标维数。

问题3再用半径函数压尺寸、高度维数。

这是非常成熟的竞赛建模判断。

## 15.4 能把结果解释回物理

例如根据热力图和效率分量解释塔位置、余弦效率、镜场区域差异。

## 15.5 最终方案可落地

不仅报目标值，还给：

- 塔坐标；
- 镜子尺寸；
- 高度；
- 数量；
- 每面镜子位置文件。

对于设计题，“可生成方案”比只得到一个最优值更重要。

# 16. 但是：国一论文也不是标准答案

这一节非常重要。

学习优秀论文时，要同时训练**审计能力**。

以下内容是根据作者公开在 GitHub 的支撑代码核对得到的。它们有可能是赛后整理/上传版本中的问题，不一定等同于比赛现场最终运行版本，所以应表述为“公开代码存在不一致”，而不是直接断言论文结果一定错误。

# 17. 公开代码不一致1：问题1安装高度写成了5m

官方题目问题1明确要求：

> 定日镜安装高度均为4m。

但作者公开的 `问题一源代码/a_q1.m` 中：

```matlab
positions(:, 3) = 5 .* ones(data_len, 1);
```

也就是中心高度设成5m。

同时镜面尺寸仍是6×6。

### 这给我们的教训

比赛提交前必须做一张：

**题目参数 → 代码变量 → 论文参数表**

逐项核对。

不要相信“代码跑了很多遍所以一定没写错”。

尤其是：

- 单位；
- 初值；
- 高度；
- 边界；
- 参数范围；
- 时间点；

最容易出现这种静默错误。

如果复现这篇论文，应先把这里改成4m，再重新验证结果。

# 18. 公开代码不一致2：光锥扰动没有完整传递到反射方向

论文描述是：

> 对非平行太阳光进行抽样，并对其反射光继续追迹，从而计算截断效率。

但公开的 `eta_caculate.m` 中：

```matlab
new_direction = offset_direction(sun_direction, 4.65e-3);
reflection_direction = reflect(-sun_direction, normal_direction);
```

可以看到：

- `new_direction` 是带随机偏移的入射光；
- 反射方向却使用了 `sun_direction` 主光线，而不是 `new_direction`。

这意味着公开代码中，太阳光锥的随机角度没有完整传播到反射光线。

而截断效率本来恰恰依赖反射光斑的扩散。

### 更一致的实现应该类似

`reflection_direction = reflect(-new_direction, normal_direction)`

当然还应注意镜面法向是根据主光线控制的，不应随着每根随机光重新调整。

### 这条教训非常重要

论文里的每个随机变量、误差、扰动，都要检查它有没有一路传播到最终输出。

很多代码表面上“加入了随机误差”，实际上中途又用了未扰动变量，导致误差模型没有真正生效。

# 19. Monte Carlo精度论证不够充分

公开代码里单面镜：

```matlab
num_points = 200;
epoch = 1;
```

即大约200个镜面采样点，并且一次随机实验。

但论文没有给出：

- 200为什么足够；
- 随机种子；
- 多次重复方差；
- 置信区间；
- N从100增到1000时结果变化多少。

这对问题1也许还能接受，但到了优化阶段风险更大。

因为优化器可能在比较：

`方案A = 0.5912`

和

`方案B = 0.5915`

如果Monte Carlo随机误差本身就是0.001，那么这种比较没有意义。

### 更好的比赛方案

至少做一次：

| 光线数 | 目标值均值 | 标准差 | 时间 |
|---:|---:|---:|---:|
| 100 | ... | ... | ... |
| 200 | ... | ... | ... |
| 500 | ... | ... | ... |
| 1000 | ... | ... | ... |

选一个误差和计算量折中的数量。

优化阶段还可以使用**固定随机数 / common random numbers**：

不同设计方案使用同一批随机光线样本，这样方案间的差值噪声会小很多。

# 20. 20m邻域剪枝需要验证

公开代码只检查距离目标镜约20m以内的镜子作为潜在遮挡物。

这是聪明的加速，但论文中没有充分证明20m一定不会漏掉重要遮挡。

更严谨的做法：

```text
cutoff = 15,20,30,40,全量
```

随机抽若干镜子和时点比较遮挡效率。

如果20m与40m、全量差异极小，就有证据支持这个剪枝。

这叫：

**验证加速近似没有改变问题本身。**

以后做任何近似剪枝都应该有类似检查。

# 21. 问题2的“上层目标”是一个代理目标

最终真正目标是：

`max E_unit`

且：

`E_field ≥ 60MW`。

但论文上层主要最大化的是年平均光学效率 `η`，再把结果传给下层。

光学效率高通常有利于单位面积输出，但两者不是严格等价：

- 塔位置还会改变可布置区域；
- 镜子数量和总面积变化；
- 遮挡随密度变化；
- 达到60MW所需的镜子规模变化。

所以这是一个合理的**proxy objective（代理目标）**，不是严格等价变换。

### 教训

如果为了降复杂度把总目标拆成代理目标，要明确写：

> 为什么这个代理量与最终目标正相关？在哪些情况下可能不等价？

并最好最终再用真正目标复核候选方案。

# 22. 问题2算法是局部启发式，不等于全局最优

公开代码采用：

- 粗网格初始化；
- 邻域塔位置搜索；
- 参数逐个扫描；
- 重复直到参数不再变化。

这很实用，但容易停在局部解。

论文自己也没有声称严格全局最优。

### 更好的论证方式

- 多个不同塔位置初值；
- 多个尺寸初值；
- 不同遍历顺序；
- 不同步长；
- 低精度全局算法粗筛 + 高精度局部精修。

如果最终都收敛到相近区域，可信度会明显提高。

论文提到不同初始点最后尺寸、高度收敛到5.75和2.875附近，这个方向是对的，但可以做得更系统。

# 23. 公开问题3代码存在明显变量更新疑点

在作者公开的 `问题三源代码/a_q3.m` 中，优化宽度斜率的循环里可以看到类似：

```matlab
best_k_w = k_w;
...
for new_k_w = ...
    ...
    if ...
        best_unit_energy = res_unit_energy;
        best_k_h = new_k_h;
        ...
    end
end
k_w = best_k_w;
```

这里按语义应当更新 `best_k_w = new_k_w`，但公开代码却写到了 `best_k_h`。

后面的打印变量也混用了 `new_k_h`。

另外循环结束处还有使用最后一次 `new_k_w` 而非确认后的 `k_w` 的情况。

这很像支撑代码整理时留下的变量名错误。

### 非常重要的学习点

“国一代码”也必须 code review。

尤其优化程序最危险的 bug 是：

> **程序一直在输出结果，但某个决策变量实际上根本没有更新。**

所以要给每轮优化记录：

- 旧参数；
- 候选参数；
- 最优参数；
- 目标值；
- 是否变化。

最后检查每一个声称“被优化”的参数确实变化过。

# 25. 如果我们重新参加2023 A题，会怎样改

我会保留这篇论文的**总体架构**，但升级实现。

## 问题1

仍然采用：

`太阳几何 + 光线追迹 + Monte Carlo`。

改进：

1. 严格按4m高度复现；
2. 随机光锥正确传到反射方向；
3. 固定随机种子；
4. 做样本数收敛；
5. 空间索引代替硬编码20m；
6. 对少量场景使用全量遮挡计算校验剪枝；
7. 向量化/并行化。

## 问题2

仍然先结构化降维。

但把变量设为：

`θ=(X_t,Y_t,w,h,z,s_r,s_θ)`

其中还可给圈间距、错位角留少量自由度。

优化策略：

```text
低精度评价器
+ 全局粗搜索（Differential Evolution / CMA-ES / LHS筛选）
↓
挑前若干方案
↓
高精度Monte Carlo重新评价
↓
局部搜索精修
```

比单一路径坐标搜索更容易逃离局部最优。

## 问题3

不用直接逐镜优化。

尝试三级模型：

```text
M0：全场统一尺寸/高度
M1：线性随半径变化
M2：4~8个径向分区的分段常数/分段线性
```

如果M2相对M1只提升很小，就保留M1，因为它更简单、更稳、更易实施。

这会形成非常漂亮的模型复杂度论证。

# 26. 这篇论文最值得你抄走的，不是公式，而是四个习惯

## 习惯一：先做评价，再做优化

所有后续设计都围绕同一个物理评价器。

## 习惯二：变量太多，先参数化

3000个坐标 → 同心圆生成规则。

几千个尺寸高度 → 半径函数的几个参数。

## 习惯三：先看结果结构，再决定下一步

效率热力图告诉他们什么损失重要、塔往哪里移可能更好。

## 习惯四：承认自己求的是一个结构族中的局部优解

比赛论文不需要假装证明了全局最优。

只要：

- 建模合理；
- 算法可复现；
- 方案优于基线；
- 结果有验证；

就已经是一篇很强的竞赛论文。

# 27. 最后给这篇论文做一句“学习标签”

2022 A题最值得学的是：

> **物理动力学 → 微分方程 → 功率 → 优化。**

2023 A题最值得学的是：

> **复杂几何评价 → Monte Carlo仿真 → 结构化降维 → 仿真驱动优化。**

不要记成：

> “2023 A用蒙特卡洛和双层规划。”

应该记成：

> **当目标函数本身需要昂贵仿真才能得到，而设计变量又成千上万时，先建立可信评价器，再利用物理/空间规律把高维设计压成低维参数化问题。**

这才是以后真正能迁移到新题目的东西。
