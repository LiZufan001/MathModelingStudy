>
> 本页只影响论文写作结构，不改变任何正式算法结果。

## 2. 主样本的结构特征

主样本共约 75 个 PDF 页面（含封面和附录），正文大致采用：

1. 问题综述；
2. 问题分析；
3. 模型假设与符号说明；
4. 问题一建模与求解；
5. 问题二建模与求解；
6. 问题三建模与求解；
7. 模型评价；
8. 参考文献；
9. 附录（补充结果 / 源程序等）。

最值得学习的不是页数，而是**三问的递进叙事**：Q2 明确写成 Q1 的物理约束扩展，Q3 明确写成 Q1+Q2 之上的时间流水扩展。评委不需要重新建立三套上下文。

## 3. 摘要的可取与不可取

### 可取

- 按问题一 / 二 / 三组织，而不是按“背景—方法—结果”泛泛写；
- 在摘要里给出代表性定量结果，让评委第一屏就看到算法有效性；
- 方法名称、目标函数和结果数字一一对应。

### 不照搬

主样本摘要数字非常密集。我们的结果证据更复杂（Q1 promoted、Q2 traffic、Q3 fixed-traffic 与 FA1 trade-off 两条口径），若把六组数字全部塞进摘要，反而会降低可读性。

因此本队摘要坚持：

- Q1 只给 Conv1 的严格小幅改善或直接略写；
- Q2 给一个总量/代表改善；
- Q3 给 Conv0/Conv1 代表数字；
- FA1 trade-off 若篇幅紧张不进摘要。

## 4. 每一问的结果呈现范式

主样本有一个非常稳定的模式：

> 方法与公式 → 核心算法/流程图 → **六组 case 的单一总表** → 1~3 张解释机制的图 → 本问小结。

它没有把 Matmul / FA / Conv 六个 case 各写成一小节。这一点非常值得保留。

### 对我们的直接约束

正文中：

- 六组正式数字尽量集中在 `key_results.tex` 或单问总表；
- case-specific 讨论只挑真正有机制差异的对象（例如 Q3 Conv0/Conv1、FA1 trade-off）；
- `q1_summary / q2_summary / q3_summary` 等完整细表优先放附录；
- 不逐 case 重复“算法有效”。

## 5. 图表密度学习

主样本正文大约使用十余张图和若干总表，图并非装饰，而承担三类任务：

1. **算法流程**：让复杂多层策略可视化；
2. **总体对比**：六组 case 的统一对比；
3. **贡献解释**：把多阶段优化拆开，说明最终提升来自哪一层。

我们现有资产已经覆盖前两类：

- D1：三问统一 pipeline；
- D2：Q2 buffer / SPILL 机制；
- F1：Q3 六组固定 traffic 改善；
- F3：FA1 Traffic–Cycles 权衡；
- T1：跨 Q1/Q2/Q3 总结果表。

结构学习后新增第三类：

- **F4：Q3 `promoted Q2 raw → formal core → post-pass final` 阶段贡献分解。**

这样 Q3 不再像“黑箱直接降到最终值”，而能解释通用 core 与 critical-SPILL post-pass 各自贡献。

## 6. 伪代码与公式的使用

主样本用正式伪代码块说明核心调度算法，但没有把所有工程细节都展开成伪代码。

我们应采用同样的“只展示核心决策逻辑”原则：

- Q1：portfolio + bounded lookahead 的触发与选择；
- Q2：连续区间分配 + SPILL victim / candidate selection；
- Q3：fixed-traffic candidate → strict replay → official/safe gate → accept/reject。

不要在正文复制 Python；源码存在 public repo，附录只给关键伪代码和复现入口。

## 7. 验证章节：我们应比主样本更强

主样本有独立的“模型评价”收尾，但我们已经拥有更强的工程验证证据：

- 独立 validator/evaluator；
- small exact oracle；
- 六组 fresh replay；
- external competition output replay；
- Q3 dual evaluator；
- formal acceptance；
- published-result verifier；
- paper-assets CI。

因此不应为了模仿获奖论文而削弱这部分。`OUTLINE.md` 的“模型验证、稳健性与可复现性”继续单独成节，是本队论文的重要差异化优势。

## 8. 优缺点与改进方向

主样本采用“优点 / 缺点 / 改进方向”的平行结构，每一点短标题 + 一小段解释，阅读效率高。

我们沿用这种结构，但内容必须和 `CLAIM_LEDGER.md` 一致：

- 不把局部饱和写成全局最优；
- 不把 Q1 的 0.020618% 写成“显著改善”；
- 不把 FA1 少量 refined 点写成完整连续 Pareto 前沿。

## 9. 附录策略

主样本附录包含结果和大量源程序。我们不照搬“大段源码附录”。

更适合本队的是：

- 附录 A：六组详细结果表；
- 附录 B：诊断图与补充 Pareto；
- 附录 C：核心伪代码；
- 附录 D：复现/验收信息；
- public GitHub 仓库承担完整源码和自动化复现。

这样正文更紧凑，也避免论文成为代码打印件。

## 10. 页数与篇幅结论

2025 A 题现有全文候选从约 59 页到 120 页不等，已核验国一主样本约 75 页。因此：

> **页数不是应模仿的目标，信息层级才是。**

在 2026 官方格式/页数要求发布前，不冻结绝对页数。建议只冻结相对篇幅：

- 问题重述 + 假设符号 + 总体框架：约正文 15%；
- Q1：约 18%~20%；
- Q2：约 22%~25%；
- Q3 + trade-off：约 28%~30%；
- 验证 + 优缺点 + 结论：约 15%。

若后续需压页，优先把诊断图、参数细节、完整六组细表移入附录，而不是删掉模型定义或验证证据。

## 11. 与当前 OUTLINE 的结构级 diff

### 已经做对，保持

- 三问统一为“逻辑顺序 → 物理内存 → 时间流水”；
- 候选生成与独立评价分离；
- 主表与附录细表分层；
- Q3 fixed-traffic 主线与 FA1 trade-off 分离；
- 单独的验证/可复现章节；
- Claim Ledger 约束措辞边界。

### 需要吸收

1. 每一问末尾显式设置“本问结果与小结”，用一段话收束方法—结果—边界；
2. Q3 增加阶段贡献分解图 F4；
3. 正文六组 case 始终优先合表，不按 case 拆六段；
4. “模型优点 / 局限 / 改进方向”用平行短条目，避免长篇自评；
5. 参考文献状态同步为已经建立 `references.bib + REFERENCE_MAP + CI gate`。

## 12. 不模仿清单

- 不复制获奖论文的算法名和措辞；
- 不为了看起来“像国一”而堆页数；
- 不为了图多而画重复图；
- 不把完整源码粘进正文或大篇幅附录；
- 不把相对改善百分比作为唯一指标，绝对值与题面指标必须同时保留；
- 不因为获奖论文使用某类算法就改变已经通过 formal acceptance 的本队路线。
