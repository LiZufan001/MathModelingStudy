> 两边引用的是**完全相同的二进制 PDF 文件**，至少可以由完整 SHA256、字节数、页数和原始相对路径共同确认。

- 它并未公开 PDF 本体；

- 因而不能仅凭该仓升级 A1/A2 身份状态。

## 3. 为什么暂时无法从这个仓库恢复封面

### 3.1 PDF 从首个公开版本起就未进入 Git

仓库 `.gitignore` 明确写有：

```text
# 蒸馏后 PDF 已删, 防误提交大文件
references/papers/*.pdf
```

公开 Git 历史中：

- `v2.0.0` 首个公开版本已经采用这一策略；
- `v2.2.0` 是把 2025 年 21 篇论文的“深读结果”入库；
- 当前没有证据表明 A1/A2 PDF 曾经作为 Git blob 提交后再删除。

因此，不能指望从普通 Git 历史中恢复 PDF 二进制。

### 3.2 `extracted_text` 缓存路径存在，但缓存文件未提交

manifest 保存了：

```text
cache_path = extracted_text/...pdf.txt
```

但对 `v2.2.0` commit 整棵 Git tree 的枚举没有出现 `extracted_text/` 路径；直接访问对应缓存文件也不存在。

所以当前也不能借“已提取全文缓存”直接读取第一页参赛队号。

### 3.3 上游语料根被有意做了开源卫生隔离

`distill_huaweibei_cases.py` 明确写：

```python
# 语料根不在源码中硬编码（开源卫生）：用环境变量 MATHMODEL_HUAWEIBEI_CORPUS 或 --corpus-root 指定。
```

脚本的职责是：

- 扫描本地语料；
- 对 manifest 重算 SHA256；
- 从已有 PDF 重算页数/摘要统计；
- 校验人工标注。

它**不负责下载语料**。

当前仓库全文搜索也没有发现：

- 百度网盘来源；
- 夸克来源；
- 原始下载 URL；
- 本地绝对路径；
- A1/A2 作者/学校/参赛队号。

因此该作者很可能有意把本地语料与开源代码分离。

## 5. 新反例：Q1 的“拓扑/邻域 + SA”不能用于 A1 身份绑定

公开赛期仓：

- <https://github.com/nsyw705/2025-MM>

本仓既有 `A_PUBLIC_CODE_IDENTITY_TRACE.md` 已经形成高优先级身份假设：

> `nsyw705/2025-MM` 很可能对应北京邮电大学 `A25100130018`（余嘉宁 / 李俊豪 / 张铮宇），其中 commit 作者 `LJH` 很可能为李俊豪；但尚无队号或直接实名闭环。

官方奖项：**成功参与奖**，并非全国一等奖。

### 5.1 本轮补出的代码事实

`ProcessorScheduling.cpp` 中实际上存在明确的模拟退火实现：

```text
T = 10000
T_min = 0.1
alpha = 0.97
```

并存在：

- 邻域 1：交换；
- 随机交换节点；
- 可行性尝试计数；
- 无改进次数停止；
- NPU 多级缓存；
- `Spill_Out / Spill_In` 节点；
- DAG / 拓扑相关调度结构。

因此它与 A1 Q1 的“拓扑合法邻域模拟退火”在**算法类型层面**确实存在接近之处。

### 5.2 但它仍然不是 A1 强身份候选

当前仓内仍未检出 A1 的更强组合：

- `Chaitin` 图着色；
- `CG / CF / victim` 链；
- 分层 ILP / rounding；
- 与 A1 Q2 相同的 SPILL 分层求解结构。

也没有 A2 的：

- `ABQPSO`；
- `[seq|alloc|spill|offset]`；
- Repair `R1–R5`；
- `DPEA`；
- `domain_greedy_results.txt`。

所以这条真实赛期仓反而提供了一个非常有价值的**负面对照**：

> **“NPU + DAG + cache/SPILL + SA + swap 邻域”并不足以把某支队伍绑定到 A1。**

后续搜索 A1 时必须提高到 Q2/Q3 的联合罕见指纹，尤其是：

> `Chaitin + CG/CF/victim + 分层 ILP/Rounding + SPILL`

而不是继续单搜“模拟退火 / 拓扑邻域”。
