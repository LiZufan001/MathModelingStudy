# 二、指导老师最值得表扬的 8 点

## 1. 先理解协议，再做特征工程

论文不是：

```text
CSV → CNN
```

而是先讨论：

```text
PD / ED / NAV
carrier sensing
sync / async
AMC
MCS / NSS
RTS/CTS
```

再决定哪些数据值得进入模型。

这是数据型赛题最重要的基本功。

## 2. Q1 的 threshold exceedance 思维很好

把：

```text
RSSI
NAV threshold
```

合成：

```text
fraction above NAV
```

比单独喂两列更有物理意义。

## 3. 能把 AP↔AP RSSI 和发送机会联系起来

CSMA/CA 的核心就是“能否听到别的发送者”。

因此 AP↔AP RSSI 成为 Q1 最重要特征，在物理方向上合理。

## 4. 能面对失败模型

直接 25 分类坍缩后，没有藏掉失败结果，反而展示图 4-5，并重新观察 PHY Rate。

这属于很好的科研/竞赛习惯：

> **失败不是删掉，而是解释为什么失败，再改变问题表示。**

## 5. Q3 尊重了题面接口

题目明确允许真实 `(MCS,NSS)`，作者没有为了“全链条都是自己预测”而强行传递 Q2 的误差。

## 6. 图、表、代码交付充分

有：

- feature importance；
- loss curves；
- CDF；
- 部分预测表；
- 大量代码附录。

评委容易检查完整性。

## 7. 2AP / 3AP 分开建模是合理工程选择

两类数据特征维数、节点结构都不同。在比赛时间有限时，分开建模比强行统一更稳。

## 8. 论文叙事很容易让评委读懂

```text
谁能发？
→ 发多快？
→ 最终吞吐多少？
```

故事线清楚，是这篇能进入顶级评选的重要非算法因素。

# 三、A级问题：如果我是严格评委，会重点追问

## A1. Q3 官方指标 90% 分位点为什么代码取 10%？

题面要求：

\[
P(error\le ERROR)=90\%.
\]

公开附录：

```python
threshold_index = int(len(sorted_errors)*0.1)
```

升序数据的 10% 位置就是 q10。

**风险：极高。**

因为正文“>95%”的核心证据直接依赖这个指标。

### 我会问

> 你们正式提交结果的 evaluator 与附录是否一致？如果不一致，请展示最终 evaluator；如果一致，请重新计算 q90 后报告结果。

---

## A2. 为什么用训练 batch 的误差计算所谓 accuracy？

代码先：

```python
for X_batch,y_batch in train_loader:
```

收集误差，再计算 accuracy。

这不是 validation accuracy。

### 我会问

> 图 5-1/5-2 的 accuracy 到底来自 train、validation 还是 official test？请给数据流图。

---

## A3. 验证集为什么与训练集共享同一 experiment？

我们复核：

- 2AP Q1：验证行约 82.3% 同组泄漏；
- 3AP Q1：100%；
- 2AP Q3：验证约 4 行，100% 同组泄漏。

### 我会问

> 如果把同一 test_id 的所有 AP 放在同一 fold，性能下降多少？

这会直接决定“泛化良好”是否成立。

---

## A4. 2AP Q3 只有约 4 行验证，为什么能谈泛化？

```python
test_size=0.01
```

对 392 行约 4 行。

任何 q90/CDF 在 4 行上都没有稳定统计意义。

### 我会要求

至少 GroupKFold 5 folds。

---

## A5. 3AP Q3 的 `y_test` 是官方空 throughput，test loss 怎么算？

公开代码：

```python
test_data = official_test
y_test = test_data['throughput']
```

但官方 test 的 throughput 为空。

因此该 test loss 无法成为真正验证证据。

---

## A6. Q2 86.73% 是 pair accuracy 还是坐标 accuracy？

3AP 代码：

```python
(predicted == targets).sum()
total += targets.numel()
```

一个样本有 NSS、MCS 两个坐标。

一个对一个错也算 50%。

### 我会要求

重新报告：

```text
exact pair accuracy
NSS accuracy
MCS accuracy
macro-F1
```

---

## A7. Q3 为什么使用真实 PER？题目只明确放行真实 MCS/NSS

原题把 PER 列在“统计信息/模型输出”中，Q3 只特别说明允许真实 `(MCS,NSS)`。

论文代码保留真实 `per`。

### 这是题意高风险点

不能简单因为 test CSV 中有 PER 就自动认定可用。

### 我会问

> 你们依据题面哪一句认为 PER 可以作为 Q3 输入？如果去掉 PER，结果是多少？

最安全答法应有：

- 主结果：不使用 PER；
- 补充结果：若官方确认允许，再使用 PER。

---

## A8. 正文的“改进加权随机森林”为什么附录没有？

正文给出权重 `ω_i`，附录只有标准 `RandomForestRegressor.predict()`。

### 我会问

> 加权 RF 的实现在哪里？最终 87.96% 特征结果来自标准 RF 还是加权 RF？

如果没有完整证据，应把正文改成“尝试/提出”而不是“最终采用”。

# 四、B级问题：方法可以成立，但论证需要补

## B1. AP↔AP RSSI 的 87.96% 是否被当成因果贡献？

RF impurity importance 不是 causal effect。

需要 permutation / SHAP / ablation。

---

## B2. 3AP 多干扰源为什么不做功率和？

多个 dBm 不能直接相加。

正确需要：

\[
10\log_{10}\sum_j10^{P_j/10}.
\]

公开代码只是保存多个 pairwise RSSI difference。

---

## B3. Q1 的发送机会信息到底怎样进入 Q2？

正文多次写“结合问题一发送机会分析”。

但 Q2 附录主特征构造更明显的是 RSSI/SIR 矩阵，没有清晰看到 `predicted seq_time` 或 `P(sync)` 直接进入。

### 我会问

> Q1→Q2 的变量接口到底是什么？

这是多问串联题很重要的论文完整性问题。

---

## B4. 为什么 Akima 固定到 540？

论文理由：最长序列约 521，取整到 540。

但模型需要证明：

```text
256 / 384 / 512 / 540 / 640
```

中 540 不是随意选择。

---

## B5. 插值轴是不是物理时间？

如果只是序列 index，CNN 学到的“局部模式”未必是真实时序模式。

应确认时间戳或做 mask/variable-length 对比。

---

## B6. 为什么一定是 CNN？

如果输入是手工排列的矩阵或 tabular feature vector：

- 矩阵相邻位置是否有稳定空间含义？
- 改变 AP 编号会不会改变卷积结果？
- 改变 DataFrame 列顺序会不会改变 Q3 结果？

如果答案是“会”，说明 CNN 的 translation locality 假设并不自然。

---

## B7. PHY Rate 到 (MCS,NSS) 为什么当成一一映射？

速率表有重复值。

训练集中也实际出现：

- 2AP 68.8 Mbps 对应多个 pair；
- 3AP 51.6、68.8 Mbps 对应多个 pair。

需要 conditional mapping。

---

## B8. `NSS=2` 约占 97%–98%，为什么只报 accuracy？

不平衡任务至少要给：

- majority baseline；
- macro-F1；
- balanced accuracy。

# 七、模拟答辩：12 个最可能的追问

## Q1

**为什么 AP↔AP RSSI 重要度高达 87.96%，这个数字是因果比例吗？**

理想回答：不是因果比例，是当前 RF 的特征重要度；补 permutation + ablation 证明结论稳定。

## Q2

**你们正文的 weighted RF 在代码哪里？**

理想回答：展示自定义 ensemble；若没有，应承认最终结果使用标准 RF 并修正文稿。

## Q3

**为什么按 AP 行随机切分，而不是按一次实验切？**

理想回答：改成 GroupKFold，展示新结果。

## Q4

**直接 25 分类为什么全部变成 `(2,11)`？**

理想回答：展示类别分布，说明主类占比高，再解释 target reformulation。

## Q5

**86.73% 是不是完整 pair accuracy？**

理想回答：必须给 exact-pair evaluator；不能用 coordinate average 代替。

## Q6

**PHY Rate 一样时怎么判断 NSS/MCS？**

理想回答：不是一一映射，使用条件概率 / hierarchical model 消歧。

## Q7

**3AP 中两个邻 AP 同时干扰时 SINR 怎么算？**

理想回答：在线性功率域聚合，并用同步概率决定干扰是否激活。

## Q8

**Q1 的发送机会结果实际怎样进入 Q2？**

理想回答：明确 `P(sync)` / `pred_seq_time` 等变量接口，并做是否使用 Q1 信息的消融。

## Q9

**为什么插值成 540？**

理想回答：给长度敏感性实验；若没有，只能称工程超参数。

## Q10

**Q3 95% accuracy 的 90% CDF 分位在哪里算？**

理想回答：展示独立官方 evaluator，确认是 q90 而不是 q10。

## Q11

**为什么用真实 PER？题目只放行真实 MCS/NSS。**

理想回答：主模型不依赖 PER；或提供官方规则依据，并给无 PER 消融。

## Q12

**为什么 tabular features 用 Conv1d？换列顺序性能会怎样？**

理想回答：如果没有稳定邻域语义，改用树模型/MLP；如果保留 CNN，要证明 feature ordering 有物理意义。

# 八、如果比赛中我是你们指导老师，我会卡的 6 个门

## Gate 1：数据定义

必须写清：

```text
一行是什么？
一次实验是什么？
哪些行相关？
```

## Gate 2：输入许可

每个字段标：

```text
official input / allowed special input / target / unavailable at inference
```

## Gate 3：官方 evaluator

先于模型完成并通过手工测试。

## Gate 4：baseline

深度学习前必须跑：

```text
mean/majority
linear/logistic
RF/CatBoost
```

## Gate 5：grouped validation

出现同一实验多行数据，不允许 row random split。

## Gate 6：论文—代码一致

提交前逐项问：

```text
正文说用了什么？
代码真的用了什么？
图表是哪个脚本生成的？
```
