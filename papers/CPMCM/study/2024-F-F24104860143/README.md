这是全文最值得学习的地方：**前一问的状态量成为后一问的输入，四问不是四套互不相关的模型。**

但把 79 页论文、原题、官方附件和公开 Python 附录交叉核对后，也必须把若干问题分开评价：

1. Q1 的开普勒二体正算公式与数值结果基本自洽，位置/速度结果可复算；但“正算后再反算回原参数”主要是 round-trip self-consistency，不等价于独立验证；
2. 正文式 (3.45) 把轨道坐标旋转写成 `R3(-Ω)R3(-i)R3(-ω)`，其中倾角应为 `R1(-i)`；后续 P/Q 公式和代码使用的是正确的 `R1`，因此更像正文笔误；
3. Q2/Q3 的 `TT→TDB` 近似式存在明确单位错误：`0.001657 sin(g)` 是秒，但代码直接加到以“天”为单位的 JD 上；
4. 该错误在 Q2 将约 `0.964 ms` 的 TT–TDB 修正误当成 `83.308 s` 的历表时刻偏移，使 DE200 取到的位置偏约 `2513.5 km`，最终几何时延偏约 `6.867 ms`；

6. Q3 的“引力红移时延” `-GM/(rc^2)` 量纲是无量纲，不是秒；代码却直接标成秒；
7. Q3 的“动钟变慢”正文写 `-2(r_SSB·v_SSB)/c²`，代码函数却是 `+2(...)`，而且最终传入的是 GCRS 的卫星位置/速度，不是正文所写 BCRS/SSB 量；
8. Q3 正文式 (5.9) 的地球 BCRS z 坐标误用了加入卫星 z 后的数值，式 (5.10) 的卫星 BCRS z 反而与代码一致；
9. Q4 把 NHPP 写成 `λ(t)=λb+λs h(φ(t))` 是正确主线，初始递推法是局部常强度近似，低流量/快速变率时确有误差；
10. Q4 改进的“Poisson 总数 + Uniform order statistics + Λ^{-1}”实现思想是标准正确方法，但正文却错误地说齐次 Poisson 的到达间隔服从 `R(0,1)`；
11. Q4 的线性插值代码分母写成 `φ1-φ2` 而不是 `φ2-φ1`，会把斜率符号反转，甚至产生负的总光子强度；论文据此得出“线性插值不如三次样条”的比较并不公平；
12. Q4 χ² 代码把 `(n_i-np_i)^2/(np_i)` 写成了 `((n_i-np_i)^2/n)*p_i`，统计量公式执行错误，论文的 χ²=24.98915 因而不能作为有效的 Poisson 拟合优度证据；
13. Pearson=0.99351 主要是“用标准轮廓生成强度，再和同一个标准轮廓比较”的 self-consistency；理论期望轮廓本来就是 `a+b h(φ)`，Pearson 在无噪声极限趋近 1，因此它不能独立证明物理模型正确；
14. 改进法正文报告 Pearson=0.99351，并称“优于表 6.1”，但表 6.1 的三次样条也是 0.99351，公开数字本身不能支持“优于”。

> **学它“轨道状态 → 时延 → 相位 → 随机点过程 → 折叠验证”的系统链；同时把时间尺度、单位、参考系、随机过程验证做得比原论文更严。**

# 1. Q1：从开普勒根数到卫星位置与速度

## 1.1 作者的核心模型

设地球标准引力参数为 `μ=398600.4418 km^3/s^2`，已知：

- 偏心率 `e`；
- 比角动量 `h`；
- 倾角 `i`；
- 真近点角 `θ`；
- 升交点赤经 `Ω`；
- 近地点幅角 `ω`。

先由

\[
a=\frac{h^2}{\mu(1-e^2)},\qquad
p=a(1-e^2),\qquad
r=\frac{p}{1+e\cos\theta}
\]

得到轨道尺度。

然后构造轨道平面基向量 `P,Q`：

\[
\mathbf r=r\cos\theta\,\mathbf P+r\sin\theta\,\mathbf Q,
\]

\[
\mathbf v=-\frac hp\sin\theta\,\mathbf P
+\frac hp(e+\cos\theta)\mathbf Q.
\]

这是标准、清晰、可计算的二体轨道正算。

## 1.2 论文结果可复算

按公开附录输入：

\[
e=2.06136076\times10^{-3},\quad
h=5.23308462\times10^4\ \mathrm{km^2/s}
\]

等参数，得到：

\[
a=6870.3614282\ \mathrm{km},
\]

\[
\mathbf r=(1274.9134151,-1848.8519650,6507.2626553)\ \mathrm{km},
\]

\[
\mathbf v=(-6.2107952,3.7461273,2.2763309)\ \mathrm{km/s}.
\]

与论文表 3.1 一致。

## 1.3 Q1 最值得学的地方

作者不是直接引用一个黑箱 `coe2rv()`，而是把：

```text
二体方程
→ 角动量守恒
→ 轨道积分
→ 轨道坐标系
→ 惯性系旋转
→ r/v 公式
```

完整推了一遍。

对于物理机理题，这种推导很容易给评委留下“作者知道公式从哪里来”的印象。

## 1.4 但验证并不独立

作者把正算得到的 `(r,v)` 再反算六根数，并得到和输入相同的参数，称其“有力验证准确性”。

问题是：

> **forward 和 inverse 共用同一套二体假设与大量相同公式。**

如果两端存在同源符号错误，round-trip 完全可能仍然回到原值。

更好的验证应至少加：

- `||r×v||=h`；
- 比机械能与 `a` 的一致性；
- 轨道方程残差；
- 与独立 orbital mechanics 库交叉验证；
- 短时间数值积分与解析轨道对比。

## 1.5 一个正文笔误

式 (3.45) 写成：

\[
R_3(-\Omega)R_3(-i)R_3(-\omega),
\]

而倾角是绕 x 轴旋转，应为：

\[
R_3(-\Omega)R_1(-i)R_3(-\omega).
\]

后面的 P/Q 展开和 Python 代码实际用的是正确结果，因此应归类为：

> **正文公式笔误，而不是最终数值算法错误。**

# 2. Q2：几何时延——思路正确，但时间单位错误会放大到毫秒级

## 2.1 正确的问题结构

作者做了四件事：

1. MJD → JD；
2. TT → TDB；
3. GCRS → BCRS；
4. 用 Crab 的 RA/Dec + proper motion 得到方向单位向量。

最后：

\[
\Delta t_{R}= -\frac{\mathbf r_{SC,SSB}\cdot\hat{\mathbf n}}{c}.
\]

这个思路与标准 pulsar barycentric correction 中 Roemer delay 的几何本质是一致的。

## 2.2 TT→TDB 的单位错误

论文与代码都写：

```python
g = 6.24 + 0.017202*(jd_TT-2451545)
jd_TDB = jd_TT + 0.001657*sin(g)
```

问题在于：

\[
TDB-TT\approx0.001657\sin g
\]

这里的 `0.001657` 单位是 **秒**。

而 `jd_TT` 的单位是 **天**。

所以正确近似应是：

\[
JD_{TDB}=JD_{TT}+\frac{0.001657\sin g}{86400}.
\]

### 用原 DE200 实测错误影响

MJD 57062.0 时：

\[
TDB-TT\approx0.000964218\ \mathrm{s}.
\]

论文代码却把这个数当“天”加入 JD，相当于历表查询提前/推后：

\[
0.000964218\times86400
\approx83.3084\ \mathrm{s}.
\]

用同一份 DE200 复算：

- 论文代码位置与单位修正后位置相差约 `2513.52 km`；
- 论文几何时延：`-277.9236602398 s`；
- 单位修正后：`-277.9305272693 s`；
- 差约 `6.867 ms`。

这已经远大于脉冲星高精度计时里很多相对论小项。

### 比赛教训

> **时间是最危险的“带单位自变量”：秒、天、MJD、JD、TT、TDB 一旦混用，错误会通过历表位置放大，而不是只差一个小常数。**

## 2.3 路径差正文单位标错

论文式 (4.24) 写：

\[
\Delta d=-83319417239.6452\ \mathrm{km}.
\]

但从最终：

\[
\Delta t=-277.92366\ \mathrm{s}
\]

反算，路径差应约为：

\[
-8.33194\times10^{10}\ \mathrm{m}
=-8.33194\times10^7\ \mathrm{km}.
\]

所以该数值其实是 **m**，不是 km。

公开代码也正是：

```python
ds = -dot(r_km,n)*1e3   # m
dt = ds/c
```

即：

> **代码量纲是对的，正文数值单位标签错了。**

不能反过来把最终 `-277.92366 s` 判成多了 1000 倍。

# 3. Q3：相对论小项——这是本篇最需要批判性阅读的部分

## 3.1 Shapiro 项

论文只保留太阳：

\[
\Delta t_S
=-\frac{2GM_\odot}{c^3}
\ln\left(1+\frac{d_{proj}}{d_{sun}}\right).
\]

报告：

\[
-6.6254740\ \mu s.
\]

量级上并非异常，太阳 Shapiro delay 本来就可能处于微秒至百微秒量级。

作为竞赛简化，只考虑太阳可以接受，但必须明确：

> 这是“题目允许忽略较小项”下的近似，不是完整 TEMPO2 级模型。

## 3.2 “引力红移时延”存在量纲硬伤

论文式 (5.4)：

\[
\Delta t_{redshift}
=-\frac{GM_\odot}{r c^2}.
\]

量纲：

\[
\frac{m^3/s^2}{m\cdot m^2/s^2}=1.
\]

这是**无量纲的势能/c²比例**，不能直接叫“秒”。

而公开代码：

```python
dt_redshift = (-GM_sun/d_sate)/c**2  # unit : s
```

直接把这个无量纲数标为秒，并得到约：

\[
-9.9793\times10^{-9}\ \mathrm{s}.
\]

所以该项不能作为严格成立的时间延迟公式。

正确的钟差/Einstein 类修正需要从**钟速率差**积分到时间差，或者直接采用一致的 TT/TCG/TCB/TDB 转换模型，而不是把瞬时势 `U/c²` 直接当时延。

## 3.3 动钟项：正文、函数、实际调用三者不一致

正文：

\[
\Delta t_{rel}=
-\frac{2\mathbf r_{SSB}\cdot\mathbf v_{SSB}}{c^2}.
\]

公开函数却是：

```python
dt = +2*dot(p,v)/c**2
```

符号已经不同。

更关键的是主程序：

```python
# dt = calculate_specialrelativity_delay(p_sate_SSB, v_sate_SSB)
dt = calculate_specialrelativity_delay(p_sate_GCRS, v_sate_GCRS)
```

即正文说的是 SSB/BCRS 状态，最终却传了**地心 GCRS 状态**。

复算：

- 用最终 GCRS 调用：`-7.02705e-10 s`，正好对应论文报告；
- 若把函数按注释传入 BCRS 状态，代码的 `+2r·v/c²` 会得到约 `+0.01738 s`。

这两者相差约 **7 个数量级**。

这里不能简单说“0.01738 s 就是正确答案”，因为正文公式本身是否是题目所需的完整 SR 时间转换仍需物理推导；但可以确定：

> **公开论文的符号、参考系和实际代码调用没有统一。**

## 3.4 Q3 的地球 z 坐标正文抄错

由 DE200：

\[
z_{EMB}=57,890,210.3794789\ \mathrm{km},
\]

\[
z_{Earth/EMB}=-1,451.1329569\ \mathrm{km}.
\]

因此地球 BCRS 应为：

\[
z_{Earth}=57,888,759.2465220\ \mathrm{km}.
\]

再加卫星：

\[
6507.2626553\ \mathrm{km}
\]

才得到：

\[
z_{SC}=57,895,266.5091774\ \mathrm{km}.
\]

论文式 (5.9) 却把 `57,895,266.5091774` 提前写成地球 z，式 (5.10) 又原样写为卫星 z。

代码实际向量相加是正确的，因此也是：

> **正文中间量版本/抄录错误。**

# 4. Q4：NHPP 建模——本篇最有迁移价值的一问

## 4.1 正确的统计结构

题目明确说光子到达时间服从非齐次 Poisson 过程。

作者定义：

\[
\lambda(t)=\lambda_b+\lambda_s h(\phi(t)),
\]

其中：

- 背景流量密度 `1.54 ph/(s·cm²)`；
- 探测面积 `250 cm²`；
- 因此背景事件率 `385 ph/s`；
- Crab 信号强度取背景 10 倍，即 scale `3850 ph/s`；
- `h(φ)` 为标准轮廓。

累计强度：

\[
\Lambda(t)=\int_0^t\lambda(s)ds.
\]

对于任一区间：

\[
N(a,b)\sim Poisson(\Lambda(b)-\Lambda(a)).
\]

这是标准 NHPP 框架。

## 4.2 相位模型

作者使用：

\[
\phi(t)=\phi_0+
u(t-t_0)
+\frac12\dot\nu(t-t_0)^2
+\frac16\ddot\nu(t-t_0)^3,
\]

并根据附件参数使用 Crab 的自转频率和一阶导数。

这点很重要：

> **随机过程的非齐次性不是任意画出来的，而是由“脉冲星相位 → 标准轮廓 → 光子强度”这个机理链生成。**

## 4.3 初始递推法只是局部近似

由 NHPP 等待时间：

\[
\Lambda(t+Z)-\Lambda(t)=-\ln U.
\]

作者因为 `Λ^{-1}` 难解析，近似成：

\[
t_{k+1}\approx t_k-rac{\ln U}{\lambda(t_k)}.
\]

这相当于在一个等待间隔里把强度冻结为当前 `λ(t_k)`。

当：

- 光子流量很高；
- 相邻事件间隔很短；
- λ(t) 在该间隔变化不大；

这个近似合理。

作者后来指出低流量时 `δt→0` 不再好用，因此提出改进，方向是正确的。

# 5. Q4 改进算法：实现思想正确，理论叙述混淆

## 5.1 公开代码实际做了什么

A.6：

1. 离散积分得到 `Λ(t_k)`；
2. 采样：

\[
I\sim Poisson(\Lambda(T));
\]

3. 采样 `I` 个：

\[
U_i\sim Uniform(0,1);
\]

4. 令：

\[
\tau_i=\Lambda(T)U_i;
\]

5. 数值计算：

\[
t_i=\Lambda^{-1}(\tau_i);
\]

6. 排序。

这就是 NHPP 的 **order-statistics / cumulative-intensity inverse transform** 方法。

### 这个实现思想是对的

条件于：

\[
N(T)=I,
\]

变换后的累计强度坐标中的 `I` 个事件位置确实对应均匀次序统计量。

因此这部分不应该因为正文证明写乱了就全盘否定。

## 5.2 正文证明哪里错了

正文一边令 `R` 是 `[0,1]` Uniform，随后又写：

\[
\tau_{i+1}-\tau_i=R
\]

并据此说它“服从参数为 1 的指数分布”；后面又称 Poisson 到达间隔服从 `R(0,1)`。

这是两个不同构造被混在了一起：

### 构造 A：time-rescaling

齐次 Poisson(1) 的**相邻等待时间**是：

\[
E_i\sim Exp(1),
\]

累加后再用 `Λ^{-1}`。

### 构造 B：conditional order statistics

先：

\[
N\sim Poisson(\Lambda(T)),
\]

再条件于 N，在累计强度区间内采样 N 个 Uniform 点并排序。

公开 A.6 实现的是 **B**，这是正确的；但正文却用 **A 的“指数等待时间”**去解释 **B 的 Uniform 样本**，于是推导文字不成立。

### 比赛教训

> **算法能跑对，不代表论文证明就写对；尤其随机过程要把“无条件过程”和“条件于事件总数后的分布”分清。**

# 6. Q4 三种轮廓插值比较存在代码级不公平

## 6.1 线性插值斜率符号写反

公开函数：

```python
h_phi = (h2-h1)/(phi1-phi2)*(phi-phi1)+h1
```

正确应该是：

```python
h_phi = (h2-h1)/(phi2-phi1)*(phi-phi1)+h1
```

分母符号相反。

复现该公开代码后：

- 论文错误版线性插值 Pearson：`0.99042015`，与表 6.1 的 `0.99042` 精确对应；
- 修正线性插值后，同一随机种子 Pearson 约 `0.99375`；
- 错误版甚至会在某些相位给出**负的总光子强度**。

因此：

> **“三次样条优于线性插值”这一结论不能由表 6.1 公平支持，因为 linear baseline 本身实现错了。**

这是非常典型的 baseline audit。

## 6.2 周期边界也没有明确处理

标准 profile 的相位点是 bin center，范围约：

\[
0.001953125\sim0.998046875.
\]

但相位模型输出 `[0,1)`。

`CubicSpline(phi_x,h_y)` 默认不是周期样条，在 0 和 1 附近使用外推。

标准轮廓本来是周期函数，所以更严格应：

- 显式做 circular extension；或
- 构造周期一致的插值；
- 再归一化 `∫_0^1 h(φ)dφ=1`。

用公开默认 spline 外推，完整 `[0,1]` 的轮廓面积比原数据的归一化目标产生约几个百分点偏差，会直接改变期望事件总数。

# 7. Pearson=0.99351 应怎样正确解释

作者用标准模板 `h(φ)` 构造：

\[
\lambda(t)=\lambda_b+\lambda_s h(\phi(t)).
\]

然后模拟很多光子，再折叠并与**同一个 h(φ)** 做 Pearson。

在无限样本极限，折叠期望值就是：

\[
a+b h(\phi).
\]

而 Pearson 对正的 affine transform 满足：

\[
Corr(h,a+bh)=1.
\]

所以：

> **高 Pearson 主要验证“采样器 + 折叠器能否恢复作为输入的模板”，不是独立验证真实 Crab 辐射过程。**

它仍然有价值，但应叫：

- numerical self-consistency；
- simulator fidelity to prescribed template。

不要写成“证明物理模型高度准确”。

## 7.1 对改进方法的复算

按 A.6 公开算法、同一附件轮廓、seed=42 复现，我们得到的 profile Pearson 约 `0.99596`（具体值可能随 SciPy 插值/实现版本略有变化），而不是正文写的 `0.99351`。

更重要的是正文说：

> 逆变换法 Pearson = 0.99351，优于表 6.1。

但表 6.1 的三次样条本身就是：

\[
0.99351.
\]

所以公开论文数字至少存在**“相等却写成优于”**的一致性问题。

# 8. χ² Poisson 检验：公开代码公式执行错误

论文公式是标准 Pearson：

\[
\chi^2=\sum_i\frac{(n_i-np_i)^2}{np_i}.
\]

但公开代码写：

```python
chi2_stat += (sample_counts[i]-n*p[i])**2/n*p[i]
```

Python 运算顺序使其成为：

\[
\frac{(n_i-np_i)^2}{n}\,p_i,
\]

而不是：

\[
\frac{(n_i-np_i)^2}{n p_i}.
\]

差了一个 `p_i^2` 量级关系。

因此论文报告：

\[
\chi^2=24.98915
\]

以及由此得出的“通过 Poisson 检验”，不能由公开程序有效支持。

此外它还存在：

- 大量理论类别期望频数远小于 5；
- 自由度按实际出现的 distinct count 数构造；
- 没有合理合并尾部类别；

这些都会破坏经典 χ² 近似前提。

## 8.1 更适合 NHPP 的验证

最推荐的是 **time-rescaling theorem**：

若模拟事件为：

\[
t_1<t_2<\cdots,
\]

计算：

\[
z_i=\Lambda(t_i)-\Lambda(t_{i-1}).
\]

正确 NHPP 应满足：

\[
z_i\overset{iid}{\sim}Exp(1).
\]

然后做：

- KS test；
- exponential QQ plot；
- lag autocorrelation；
- 多窗口 count calibration。

这比只检验“一秒内总事件数大概像 Poisson”更能检验**整个到达时间过程**。

不能只拿 generator 输入的模板再验证 generator。

### 经验 4：高级模型比较前先验证 baseline 没写错

修正一个线性插值符号，可能比换 cubic spline 更重要。

### 经验 5：随机过程验证要验证“过程”，不是只验证一个总数

NHPP 最自然的是 compensator/time-rescaling，而不只是 total-count χ²。
