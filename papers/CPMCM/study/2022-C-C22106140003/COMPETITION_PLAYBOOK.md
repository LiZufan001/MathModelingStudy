# 比赛速查：从 C22106140003 提炼的复杂调度题打法

> 用途：正式比赛遇到“多资源 + 缓存 + 排序 + 时间 + 优先规则 + 多目标评分”的题，先翻这份文件。它不是 2022 C 的复述，而是从该论文抽出的可迁移工作流。

---

## 0. 看到什么题型时立刻联想到这篇

若题目出现以下 4 项以上，可优先考虑本套路：

- 多车道 / 多机器 / 多队列；
- 中间缓存、返回、返工、备用通道；
- 工件顺序会影响后续评分；
- 每一步动作需要真实运输/处理时间；
- 有“先到先服务”“某类任务必须优先”等业务规则；
- 目标同时包含序列质量、资源使用次数、总耗时；
- 工件数达到几十到几百，完整排列搜索太大；
- 第二问会取消/修改某条优先约束。

核心关键词：

> **simulation first, optimization second**

---

# 一、开题后 2~4 小时：先别急着上算法

## Step 1：画“资源—位置—移动”图

至少明确：

```text
源序列
 ↓
设备 A
 ↓
缓存/车道 1 ─┐
缓存/车道 2 ─┼→ 设备 B → 输出序列
缓存/车道 k ─┘
 ↑
返回/返工通道
```

在图上标出：

- 每个资源容量；
- 允许移动方向；
- 每段移动/加工时间；
- 哪些资源不能并行；
- 哪些位置会阻塞。

**验收：**队里任何一个人只看这张图，都能解释“一件工件从输入到输出怎么走”。

---

## Step 2：把条件分成硬约束和软目标

### 硬约束

违反一次就不是合法解：

- 容量；
- 唯一占位；
- 不能穿越；
- 先后关系；
- 设备互斥；
- 强制优先级；
- 时间可达性。

### 软目标

合法解之间比较好坏：

- 排序违例；
- 等待时间；
- 完工时间；
- 换线次数；
- 返工次数；
- 能耗；
- 风险。

> **不要通过“罚一个很大的数”来代替所有硬约束。** 最稳妥的做法是让状态转移层根本不生成非法动作。

---

## Step 3：先写官方评分器

推荐结构：

```python
def evaluate(solution):
    hard_ok = check_constraints(solution)
    if not hard_ok:
        return INVALID

    p1 = penalty_sequence(solution)
    p2 = penalty_ratio(solution)
    p3 = expensive_action_count(solution)
    p4 = time_penalty(solution)
    total = combine(p1, p2, p3, p4)
    return total, (p1, p2, p3, p4)
```

必须做 3 类测试：

1. 手工构造的完美小样例；
2. 恰好违反一处规则的样例；
3. 官方示例/已知结果。

**评分器一旦通过验证，后续所有算法只调用它，不再自己重写评分公式。**

---

# 二、第一版可行解：状态仿真器

## Step 4：定义状态

模板：

```python
State = {
    time,
    waiting_jobs,
    queues_or_lanes,
    return_buffer,
    machines,
    finished_jobs,
    expensive_action_count,
}
```

## Step 5：定义事件/动作

例如：

```text
job enters lane j
job moves one stage
machine becomes free
job reaches queue head
job goes directly to output
job enters return/rework buffer
```

## Step 6：定义状态转移

```python
next_state = transition(state, action)
```

任何一次 transition 后立即检查不变量：

```text
总工件数守恒
无重复
无容量超限
无设备冲突
无非法跨越
时间单调增加
```

### 第一阶段验收

此时不要求高分，只要求：

- 能从头跑到尾；
- 不死锁；
- 输出格式正确；
- 每条硬约束都通过断言。

这是整个调度题最关键的安全底座。

---

# 三、从规则构造 baseline

## Step 7：先把题目规则变成 dispatch rule

常见映射：

| 题目文字 | 可尝试的规则 |
|---|---|
| 按输入顺序 | FIFO |
| 特殊缓冲必须优先 | priority / RRF |
| 等待最久者先服务 | earliest arrival / longest waiting |
| 最快完成者优先 | MTT / earliest completion |
| 最短加工时间 | SPT |
| 最早交期 | EDD |
| 最小松弛时间 | minimum slack |

不要小看简单规则。复杂约束下，一条好的 dispatch rule 往往比“编码不好的 GA”更稳。

---

# 四、不要只看队列长度：用 ETA/完成时间选资源

若任务可选多个机器/车道，不要默认：

```text
选当前最空的
```

优先估计：

\[
ETA_j = \text{到达资源 j 的时间}
       + \text{等待时间}
       + \text{预计处理/释放时间}.
\]

再选：

\[
j^*=\arg\min ETA_j.
\]

### ETA 中可以逐步加入

- 当前队列长度；
- 每个任务平均处理时间；
- 设备当前位置；
- 切换时间；
- 下游拥塞；
- 未来已预约任务。

**先用简单 ETA 跑通，再逐步加项。**

---

# 五、有“返回/返工/备用资源”时：把它定价

2022 C 最值得迁移的招数之一：返回道不是免费优化器，而是一项有代价的操作。

通用形式：

```text
不采取补救动作的损失 = L_direct
采取补救动作的成本   = C_repair

if L_direct - L_current > C_repair:
    使用补救动作
else:
    正常执行
```

若还要考虑未来时间，可扩展：

\[
\Delta C
=\Delta C_{quality}
+\lambda_1\Delta C_{time}
+\lambda_2\Delta C_{resource}.
\]

适用场景：

- 返回道；
- 返工；
- 临时仓储；
- 备用机器；
- 插队；
- 换线；
- 绕行；
- 人工干预。

# 六、第二问“取消约束”时的标准思考方式

看到：

> “若不再要求 A 必须优先于 B……”

不要只做：

```python
# 删除 if A: choose A
```

应该做：

```text
1. 原约束删掉后，多出了哪些合法动作？
2. 新增自由度由什么指标来选择？
3. 时间、成本、风险、未来评分哪个最适合做比较？
4. 能否把强制优先级改成 argmin / argmax 决策？
```

2022 C 的典型升级：

```text
RRF / LWT（强规则）
       ↓ 约束解除
MTT（比较预计运输完成时间）
```

通用模板：

\[
a^*=\arg\min_{a\in\mathcal A(S)}\widehat{Cost}(S,a).
\]

# 七、什么时候不要直接上 GA/PSO

出现以下情况时，高度警惕“完整排列编码”：

- N > 100；
- 一个解需要满足复杂设备状态约束；
- 随机交换两个任务很容易产生非法解；
- repair 比 objective 还难写；
- 决策变量规模是 \(O(N^2)\)；
- 单次适应度评估还要跑完整仿真。

这时优先考虑：

### 方案 A：优化策略参数，而不是完整排列

例如 GA 只搜索：

```text
返回阈值
ETA 权重
拥塞系数
look-ahead 深度
局部评分权重
```

### 方案 B：仿真 decoder

染色体只表达偏好，最终动作由 simulator 解码成合法方案。

### 方案 C：rolling horizon

每次只优化未来 W 个任务。

### 方案 D：beam search / look-ahead

保留有限个合法未来状态，而不是在整个排列空间搜索。

---

# 八、从一步贪心升级的优先顺序

如果 baseline 已合法但分数不够，建议按以下顺序升级，避免一开始架构爆炸：

1. **改 tie-breaker**：平分时怎么选；
2. **改 ETA**：加入下游拥塞；
3. **调局部阈值/权重**；
4. **2~5 步 look-ahead**；
5. **beam search**；
6. **rolling-horizon MILP**；
7. **策略参数的 GA/PSO/贝叶斯优化**；
8. 只有规模足够小时再考虑完整全局模型。

每升级一步都保存 baseline 结果，做 A/B 对比。

# 十、写作时怎么讲这个故事

推荐结构：

## 10.1 问题分析

先解释为什么“最终排序”不等于真实可执行调度：存在设备、缓存和移动约束。

## 10.2 基础仿真模型

说明状态、资源和状态转移，证明任何输出都可执行。

## 10.3 baseline 规则

从题目强制规则自然得到 FIFO/RRF/LWT 等策略，不要凭空“发明算法”。

## 10.4 优化策略

把剩余自由度转化为 ETA、局部评分差、MTT 等可计算量。

## 10.5 多问升级

明确说：

```text
约束变化
→ 合法动作集合变化
→ 决策自由度变化
→ 策略需要重设计
```

## 10.6 验证

可行性 + 分项得分 + 运行时间 + 消融 + 敏感性。

这样论文故事线会比“模型一、模型二、模型三堆算法”清晰得多。

# 十二、可直接记住的调度题口诀

> **先状态，后策略；先合法，后高分。**  
> **硬约束生成动作，软目标选择动作。**  
> **规则受限时按优先级，规则放宽时按代价比较。**  
> **昂贵补救动作要定价，大规模排列不要盲目全局搜。**

这四句就是本篇精读最值得在正式比赛时随手调用的东西。
