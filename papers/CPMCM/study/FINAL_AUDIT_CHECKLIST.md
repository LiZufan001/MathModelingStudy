# 华为杯赛末总审计清单｜提交前逐项打勾

> 目的：防止“模型其实不错，但 evaluator / 单位 / 可行性 / 数字版本 / 验证协议”把整篇论文拖垮。  
> 用法：冻结模型以后，由**非原作者本人**交叉检查。关键项建议两人签字确认。

---

# A. 题意与官方口径

- [ ] 每一问都能用一句话写出“官方要求输出什么”。
- [ ] 每一问的官方目标函数/评价指标已经抄成代码，并和题面逐字符核对。
- [ ] 所有赛中更正/补充说明都已检查。
- [ ] hard constraints 与 soft objectives 已区分。
- [ ] 没有把“建议/可参考”误写成“必须”。
- [ ] 没有擅自缩小题目允许的可行域而不解释 optimality gap。
- [ ] 题目要求的阈值、分位点、误差方向全部核对。

# B. 数据与单位

- [ ] 所有附件都建立了文件清单、字段说明、单位说明。
- [ ] 缺失值、异常值、重复样本处理有记录。
- [ ] 关键变量的 m/km、s/day、dB/linear、概率/% 已统一。
- [ ] 时间尺度/时区/参考系写清楚。
- [ ] 空间坐标系/投影/像素到现实尺度写清楚。
- [ ] 插值网格大小没有被误写成真实观测分辨率。
- [ ] 数量级 sanity check 通过。

# C. 独立样本与验证切分

- [ ] 已明确“一个独立样本”到底是人、实验、订单、设备、日期、路段还是别的。
- [ ] 同组兄弟样本没有同时出现在 train 和 validation。
- [ ] 时间序列只用过去预测未来。
- [ ] scaler / PCA / feature selection / resampling 只在 train fold fit。
- [ ] 超参数没有在最终 test 上调。
- [ ] 最终 test/外部验证在模型选择结束前保持隔离。

# D. Baseline 与模型必要性

- [ ] 每问至少有一个简单可信 baseline。
- [ ] 高级模型相比 baseline 的提升已量化。
- [ ] 能明确说出高级模型解决 baseline 的哪个失败模式。
- [ ] 若高级模型提升很小，论文没有夸大其必要性。
- [ ] 失败实验若改变了路线，已如实保留关键证据。

# E. 优化/调度/路径可行性

- [ ] `check_feasibility()` 已独立运行。
- [ ] 所有容量、冲突、时序、边界、覆盖、连通约束通过。
- [ ] 有 lower bound / relaxation / obvious bound。
- [ ] 近似解与下界 gap 已报告或讨论。
- [ ] 随机优化跑了多个 seed。
- [ ] GA/SA/ACO/PSO 的最终解不是唯一一次幸运运行。
- [ ] A*/Dijkstra 的 heuristic/edge cost 条件满足所声称的最优性。
- [ ] 多目标问题没有被随意拍权重后假装唯一最优。

# F. 物理/机理模型

- [ ] 关键公式逐项做量纲分析。
- [ ] 关键状态量有合法范围/invariant 检查。
- [ ] 参考系、时间尺度、坐标方向一致。
- [ ] 高阶小修正没有掩盖更大的基础误差。
- [ ] 有独立公式/库/下界交叉验证，不只做正反自洽。
- [ ] “proxy” 没有被写成“真实物理量”而不说明校准。

# G. 图像/信号/传感器链

- [ ] 检测/分割精度与下游物理量精度区分开。
- [ ] pixel → physical quantity 有标定过程。
- [ ] 上游特征/通道选择最终用下游任务复验。
- [ ] 时序切片的独立性已检查。
- [ ] 2D → 几何 → 3D 的不确定性没有被丢掉。
- [ ] 关键概率有明确随机事件定义。

# H. 多源融合与预报

- [ ] 每个数据源的观测含义和误差模型清楚。
- [ ] 观测、状态估计、预报三层没有混叫“真值”。
- [ ] 融合结果带 uncertainty / confidence 或至少误差诊断。
- [ ] NWP/外部模型先做偏差校正或至少误差评估。
- [ ] 极端危险事件有单独 recall / tail metric。
- [ ] 风险路径与普通最短路/A*在同一 evaluator 下比较。

# I. 主观评价与综合评分

- [ ] 每个指标都能回答“对应哪个可观察机制”。
- [ ] 做过“如何刷这个指标”的反作弊检查。
- [ ] 权重来源有依据。
- [ ] AHP 一致性检验通过（若使用）。
- [ ] 权重敏感性做过。
- [ ] 高度相关指标没有重复投票。
- [ ] 排名稳定性/置信区间至少有一种。
- [ ] 若无真值，已做理论关系 + baseline + sensitivity + 外部对象中的至少三层验证。

# J. 指标/evaluator 数学审计

- [ ] 分位点方向没写反（q90 ≠ q10）。
- [ ] norm 与 norm² 没混。
- [ ] dB/线性域计算正确。
- [ ] 概率、相关系数范围合法。
- [ ] denominator 与官方公式一致。
- [ ] 多输出分类的 accuracy 定义清楚。
- [ ] RMSE/MAE/R² 的目标变量缩放口径一致。
- [ ] 代码中的 metric 名称与真正算的公式一致。

# K. 实验与代码复现

- [ ] 关键实验记录 code commit / data version / seed / config。
- [ ] 没有“数据加载失败就自动生成 synthetic data”进入正式脚本。
- [ ] 所有随机种子可复现。
- [ ] 结果目录无旧版本混入。
- [ ] 图表可由代码重新生成。
- [ ] 表格可由 `metrics.json/csv` 自动生成。
- [ ] 附录代码至少能按当前数据路径运行核心流程。
- [ ] 没有正文写了算法 A、代码实际跑算法 B 的情况。

# L. 图表审计

- [ ] 每张图都有明确回答的问题。
- [ ] 坐标轴、单位、图例完整。
- [ ] 没有把插值平滑误解释成信息增多。
- [ ] 对比图使用相同数据、相同 evaluator、相同条件。
- [ ] 敏感性图标出了稳定区，不只标最佳点。
- [ ] 残差/失败案例有展示。
- [ ] 最终答案有一张一眼可读的主结果图。

# M. 正文—表格—摘要一致性

- [ ] 摘要数字与正文表格逐项核对。
- [ ] 正文分析引用的表格数字真实存在。
- [ ] 图题、表题、编号没有版本错位。
- [ ] 不同章节对同一阈值/参数口径一致。
- [ ] 算法名、理论复杂度、代码实现一致。
- [ ] 没有旧版本结果遗留在结论。
- [ ] 所有百分比都注明比较基线。

# N. 写作边界

- [ ] 没有把内部自洽写成外部验证。
- [ ] 没有把相关性写成因果。
- [ ] 没有把模型假设下的反事实写成真实实证效果。
- [ ] 没有把 proxy 写成 ground truth。
- [ ] 没有把局部两组实验结论外推到全部数据而不说明。
- [ ] 优缺点与正文证据对应。
- [ ] “推广”单独写适用条件。

# O. 最终结果与回答题目

- [ ] 每问结尾直接回答题目，不只讨论模型。
- [ ] 最终数值/路线/方案/排名明确。
- [ ] infeasible 结果不会被当成候选最优解。
- [ ] 主要结论有 baseline 或边界支撑。
- [ ] 不确定性/敏感性影响最终决策时已说明。

# P. 提交前文件审计

- [ ] 论文最终 PDF 能打开，页数正确。
- [ ] 公式无乱码、缺字、截断。
- [ ] 图清晰，中文字体正常。
- [ ] 文件名符合赛事要求。
- [ ] 匿名/队伍信息符合规则。
- [ ] 附件/代码/结果文件齐全。
- [ ] 最终提交包在另一台电脑/目录解压检查过。
- [ ] 上传前保留本地最终版本哈希/备份。

---

# 一票否决级红旗

以下任何一项发现后，优先级高于继续调模型：

- [ ] official evaluator 算错；
- [ ] hard constraints 违反；
- [ ] train/test 泄漏；
- [ ] 单位/参考系错；
- [ ] 正文和代码核心模型不一致；
- [ ] 摘要/表格关键结论不是同一结果版本；
- [ ] 目标队/数据/来源身份写错；
- [ ] 最终附件无法运行/无法打开。
