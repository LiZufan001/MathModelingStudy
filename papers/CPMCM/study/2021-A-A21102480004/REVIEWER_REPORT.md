# 一、如果我是评审老师：第一页后的 60 秒判断

我的判断会是：

> **这不是一篇“调包式算法论文”，作者确实在拆解矩阵计算链条，而且方法层次丰富，值得继续读。**

第一页能吸引评委继续看的原因：

1. 抓住“相关矩阵组”这一题眼，不是对 1536 个矩阵完全独立计算；
2. 不是只优化 SVD，而是同时优化重复计算、近似分解、乘法/求逆和存储；
3. Q1→Q2→Q3 有明显复用关系；
4. 有理论、程序和数值实验三层内容；
5. 对算法 runtime 和内存也有工程意识。

这类论文在算法题里很容易显得“有原创工作量”。

# 二、指导老师最值得表扬的 7 点

## 1. 从“重复计算”而不是“单核算法”切入

先问哪些 H 可以共享 V，再问 SVD 本身怎么加速。

这比直接说“我们采用 randomized SVD”更成熟。

## 2. 能把矩阵结构当成资源

使用了：

- 相关性；
- 低秩；
- Hermitian；
- 分块；
- 子空间近似。

结构不是背景知识，而是求解入口。

## 3. 知道 Big-O 和实际速度有差异

纯 Strassen 在小矩阵上反而慢，于是引入 cutoff。

这是很好的算法工程意识。

## 4. 会考虑临时内存生命周期

通过改变 Strassen 中间矩阵生成顺序降低峰值内存，说明作者不是只盯 FLOPs。

## 5. 压缩方法做了 block-size 对比

whole matrix、256 大块、4×4 小块都试过，最后由数据告诉你中等块更合适。

## 6. Q3 能复用前两问形成完整故事

至少从论文叙事上：

```text
Q1 计算
Q2 存储
Q3 端到端
```

非常完整。

## 7. 第 6 节敢于写缺点

作者自己承认：

- 阈值需人工调；
- randomized SVD 对 4×64 小矩阵未必明显受益；
- cutoff T 应自适应；
- 分块方式可继续优化；
- 代码对固定维度依赖较强。

这比“模型具有很强推广性”式空话好很多。

# 三、评审老师最可能扣分的 6 个核心问题

## A 级风险 1：rho evaluator 公开代码写错

附录：

```matlab
P(l,i,j)=norm(a'*b)/norm(a)*norm(b);
```

应为：

```matlab
P(l,i,j)=norm(a'*b)/(norm(a)*norm(b));
```

由于 MATLAB 同级乘除左结合，原式会导致 `rho` 可明显大于 1。

论文结果图确实出现 `rho > 1`，说明问题不是纯理论推测。

### 评审追问

> 你们的精度约束 rho_min≥0.99，到底是用哪段代码验证的？为什么归一化相关系数会超过 1？

### 如果是我们队

必须有：

```matlab
assert(rho >= -tol && rho <= 1+tol)
```

并重跑全部六组数据。

---

## A 级风险 2：Q2 error evaluator 分母与题面不一致

附录用：

```matlab
sum2 += norm(reconstructed,'fro')^2
```

官方要求：

```matlab
sum2 += norm(original,'fro')^2
```

### 评审追问

> -30 dB 是按哪一个定义验的？请给我直接对应题面的代码。

### 如果是我们队

正式论文中把 evaluator 公式和 10 行实现同时放出来，作为“验收函数”。

---

## A/B 级风险 3：Coppersmith–Winograd 理论归属不准确

公开附录所谓 `coppersmith_winograd` 的 2×2 block 公式使用 7 个子乘法和 15 个加减。

这在常见矩阵算法文献里对应 Winograd's variant / Strassen–Winograd，递推指数仍为：

\[
\log_2 7\approx2.807.
\]

论文把它与 Coppersmith–Winograd 的约 2.376 指数直接关联，不够准确。

### 评审追问

> 你实现的递归式是什么？如果每层仍然是 7T(n/2)，为什么指数会变成 2.376？

这一个问题答不上来，会明显伤害理论可信度。

---

## B 级风险 4：官方 complexity 没有完整结账

题目给了精确运算权重。

论文却大量报告：

- Big-O；
- SVD 数减少比例；
- synthetic 512/1024 runtime；

但缺一张全六数据集、全流程的官方 complexity 表。

### 评审追问

> 你算相似度和聚类本身也要花计算。把这些全部加回去以后，总复杂度是多少？

> Q2 题目说压缩/解压计算和存储同等重要，你的三种压缩方案各自编解码复杂度是多少？

如果没有表，这一问只能说“方法看起来省”，很难说“严格对齐题目目标”。

---

## B 级风险 5：阈值口径多套并存

正文相似阈值写 0.95，附录出现 0.9985 / 0.998。

正文压缩贡献率出现 0.947、0.966、0.749，附录 `accumCon` 又固定 0.99。

### 评审追问

> 最终提交使用的参数到底是什么？这些阈值是训练数据上调的，还是六个数据集分别调的？会不会过拟合？

### 应补

- 参数总表；
- 阈值扫描曲线；
- 自动选择规则。

---

## B/C 级风险 6：H 存储公式算错

H reshape 后是 `256×1536`。

rank-m 存储应为：

\[
256m+1536m+m=1793m.
\]

论文写成 `1739m`。

这个单独不致命，但它会让评委产生：

> “其他 storage 数字有没有自动校验？”

所以所有维度型公式应由程序生成。

# 四、12 个模拟答辩追问

## Q1

**问：** 为什么列范数 Pearson 相关能代表两个矩阵的 V 相似？

**合格回答需要：**

- 它只是廉价 proxy，不是充分条件；
- 展示 `R(H1,H2)` 与真实 `rho(V1,V2)` 的散点图；
- 给 false positive / false negative；
- 最终由 rho evaluator 兜底。

## Q2

**问：** 相似关系不传递，你的父子结点贪心为什么合理？

**应补：**

- 明确它是启发式代表元选择；
- 与 set cover / k-medoids / greedy dominating set 对比；
- 报代表元数量和总 complexity。

## Q3

**问：** 全两两相似度比较要 294144 对/数据集，这个预处理成本算了吗？

**应补：** complexity ledger。

## Q4

**问：** H 是 4×64，randomized SVD 真的比标准 SVD 快吗？

**应补：** 原始尺寸上的 crossover；不能只拿“大矩阵理论”回答。

## Q5

**问：** randomized SVD 有随机性，你们最差一次 rho 是多少？

**应补：** 多 seed、均值/最差、失败概率。

## Q6

**问：** 为什么要显式求逆？

**优秀回答：**

\[
V^HV+\sigma^2I
\]

是 HPD，可转为 Cholesky solve；如仍用逆，需要证明在本题官方 complexity 下更优。

## Q7

**问：** 你说 Coppersmith–Winograd 是 O(n^2.376)，请写出你代码的递推式。

公开附录版本很难支撑该指数，这是高风险问法。

## Q8

**问：** Strassen 在 1024 维能快，但本题求解中的关键矩阵维数是多少？

必须把“通用算法实验”和“本题实际收益”分开。

## Q9

**问：** 为什么压缩 rank 用奇异值线性累计贡献率，而不是平方能量？

更严格做法：直接用 Frobenius 尾能量保证 -30 dB。

## Q10

**问：** Q2 存储和编解码计算同等重要，你最终怎么做双目标决策？

应给 Pareto 或归一化等权评分。

## Q11

**问：** Q3 为什么先解压 H 再计算？能不能直接在压缩因子上求 W？

这是开放题最值得深入的方向。

## Q12

**问：** 结果中 rho 为什么大于 1？

若只回答“浮点误差”，很容易被进一步追问公式和代码。

# 八、指导老师最终要求

如果我们借鉴这篇，我会给出五条硬要求：

1. **先写 official evaluator，再写模型。**
2. 所有复杂度都进入一张 ledger，不准只报 Big-O。
3. 所有阈值必须自动选择或有扫描依据。
4. 随机算法必须固定 seed + 多次试验。
5. 理论算法名称、递推式和实际代码必须逐项对应。

> 一等奖论文可以告诉我们“什么整体路线有竞争力”；评审训练要继续问“其中哪一环经不起复算”。两种视角缺一不可。
