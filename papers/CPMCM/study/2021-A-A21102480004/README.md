# 0. 指导老师先给结论

这篇论文最值得学的不是 Strassen、随机 SVD、Huffman 这些算法名，而是它在做一件很典型的“算法型数学建模”工作：

> **先寻找数据矩阵之间可复用的结构，再用近似低秩分解减少重复计算；随后继续优化最重的矩阵运算内核；最后把低秩结构用于存储压缩，并把前两问串成端到端流程。**

它的主线可以压缩成：

```text
矩阵 H 的相关性
    ↓
代表元 / 父子结点复用
    ↓
减少需要做 SVD 的矩阵数
    ↓
随机 SVD 进一步降低单次分解成本
    ↓
优化 V^H V + σ²I 的计算 / 求解内核
    ↓
低秩分块压缩 H、W
    ↓
Q3 串成 H → W_hat 的端到端流程
```

这条链条很强，因为作者不是简单换一个黑箱算法，而是在不断问：

1. **有没有重复算的东西？**
2. **单次计算还能不能更便宜？**
3. **数据本身能不能少存？**
4. **计算和存储能不能一起设计？**

这正是算法工程型赛题的核心思维。

但这篇也存在几处必须批判性阅读的技术问题，其中有些会直接影响官方指标验证：

- 正文“相关阈值大于 0.95”，附录实际代码出现 `0.9985` / `0.998`，口径不一致；
- 附录用于验证 `rho` 的 MATLAB 表达式少了括号，会把本应不超过 1 的归一化相关指标算成可能大于 1；论文图中确实出现了 `rho > 1`，作者却把它解释为数值截断误差；
- Q2 附录误差代码把重构矩阵范数放在分母，而官方定义要求原矩阵范数；
- 论文把一个“7 次块乘法 + 15 次块加法”的实现称作 Coppersmith–Winograd，并赋予约 `O(n^2.376)` 的理论复杂度；按公开附录公式看，它更符合通常所称的 **Winograd variant / Strassen–Winograd**，理论指数仍是 `log2 7 ≈ 2.807`，只是减少了加法常数；
- H 的整体降维 SVD 存储公式写成 `393216 - 1739m`，按维数重新计算应为 `393216 - 1793m`；
- 官方要求以给定基本运算权重统计“总计算复杂度”，Q2 还要求存储与压缩/解压计算复杂度同等重要；论文大量使用渐近复杂度和墙钟时间，但没有把全流程统一折算成官方口径的完整复杂度账本。

因此这篇最正确的学习姿势是：

> **学习它的结构发现、复用、低秩近似和端到端算法设计；不要直接照抄它的指标验证代码，也不要把渐近复杂度、程序运行时间和题目规定的计算复杂度混为一谈。**

# 1. 原题真正考什么

六组数据的固定规模为：

- `M = 4`
- `N = 64`
- `L = 2`
- `J = 4`
- `K = 384`
- `σ² = 0.01`

数据核心关系可理解为：

- `H_{j,k}`：`4 × 64` 复矩阵；
- 对 `H_{j,k}` 做 SVD，取前 `L=2` 个右奇异向量形成 `V_{j,k}`；
- 再由

\[
W_{j,k}=V_{j,k}\left(V_{j,k}^{H}V_{j,k}+\sigma^2 I\right)^{-1}
\]

得到 `W`。

题目有三问。

## Q1：计算复杂度最小

分别设计：

\[
\widehat V=f_1(H),\qquad \widehat W=f(H)
\]

要求：

\[
\rho_{\min}(V)\ge 0.99,
\qquad
\rho_{\min}(W)\ge 0.99,
\]

在此前提下，使**按官方基本运算权重计算的总复杂度最低**。

官方给出了统一基本操作成本，例如：

| 基本操作 | 权重 |
|---|---:|
| 加/减 | 1 |
| 乘 | 3 |
| 倒数 | 25 |
| 开方 | 25 |
| exp/log/sin/cos | 25 |
| 其他 | 100 |

因此这一问的“低复杂度”并不等于：

```text
程序在我的电脑上跑得快
```

而是首先要回答：

```text
按照题目给定的操作计价规则，一共花了多少计算成本？
```

墙钟时间只能作为补充验证。

## Q2：存储 + 编解码计算双目标

要求：

\[
err_H\le -30\ \mathrm{dB},\qquad
err_W\le -30\ \mathrm{dB},
\]

并同时降低：

1. 存储复杂度；
2. 压缩与解压缩的计算复杂度。

题面明确说两者**同等重要**，并要求统计压缩/解压的所有运算。

同时，每个复元素仍按 64 bit 存储（实部、虚部各 32 bit），因此不能通过“把浮点数改成 8 bit”来偷走存储量。

## Q3：开放式端到端设计

输入 `H`，直接输出 `W_hat`：

\[
H\longrightarrow \widehat W
\]

要求：

- `rho_min(W) >= 0.99`；
- 同时尽量降低计算与存储复杂度；
- 可以重构整个流程，而不是必须沿用标准 SVD → inverse 的流水线。

这是整题真正允许“算法共设计”的地方。

# 2. Q1 第一层：先减少“需要算多少次”——模方法 + 父子结点

作者没有首先优化 SVD 本身，而是先观察：

> 同一行的 384 个 `H_{j,k}` 中，是否存在高度相似的矩阵？如果高度相似，能否只对一个代表矩阵做 SVD，再复用其 `V`？

这是非常值得学习的顺序。

## 2.1 “模方法”在做什么

对两个 `m × n` 矩阵：

\[
B=(b_1,\ldots,b_n),\qquad C=(c_1,\ldots,c_n),
\]

作者把每一列压成其二范数：

\[
B_1=(\|b_1\|_2,\ldots,\|b_n\|_2),
\]

\[
C_1=(\|c_1\|_2,\ldots,\|c_n\|_2),
\]

再计算这两个一维向量的 Pearson 相关系数，作为矩阵相似度 `R(B,C)`。

### 指导老师评价

优点：

- 原矩阵比较被压成长度 64 的向量比较；
- 简单、解释性强；
- 对“列能量分布相似”的信道矩阵比较敏感；
- 很适合做预筛选。

但它不是严格的矩阵距离。

因为只保留每列的二范数，它会丢掉：

- 相位；
- 列方向；
- 列间相关结构；
- 奇异子空间的详细信息。

所以它更准确的角色是：

> **cheap proxy / 廉价代理指标**。

真正能不能复用 `V`，最终还必须由官方 `rho` 验证。

## 2.2 父子结点算法

作者注意到“相似”不满足传递性：

```text
H1 与 H2 相似
H2 与 H3 相似
≠ H1 与 H3 一定相似
```

于是没有简单做连通分量，而是设计“父结点—子结点”容器：

- 每组选择一个父结点；
- 父结点做一次 SVD；
- 子结点共享父结点得到的 `V`；
- 从而减少 SVD 次数。

论文在 Data4 的一行数据上报告：

- 384 个矩阵被分成 193 类；
- 实际需要计算的 `V` 数量降到原来的 **50.260%**。

### 我们应如何重新理解它

这其实可以抽象成一张图：

- 每个 `H_k` 是一个节点；
- 两矩阵相似度足够高就在节点间连边；
- 选择尽量少的“代表节点”，让其余节点都被某个代表覆盖；
- 同时用真正的 `rho` 保证复用后精度达标。

这已经非常接近：

- dominating set；
- set cover；
- facility location；
- representative clustering。

所以如果今天重新做，我会把作者的顺序依赖贪心“父子结点”升级成：

> **相似图 + 最少代表元覆盖 + 精度约束**。

这会让模型更数学化，也更容易解释“为什么代表元数接近最少”。

# 3. Q1 第二层：减少“单次 SVD 花多少”——随机 SVD

作者采用近似矩阵分解的随机化思想。

目标是找到低维正交基 `Q`，使：

\[
\|A-QQ^*A\|\le \varepsilon.
\]

然后把大矩阵投影到低维子空间：

\[
B=Q^*A,
\]

只对小矩阵 `B` 做 SVD：

\[
B=\widetilde U\Sigma V^*,
\]

最后恢复：

\[
U=Q\widetilde U.
\]

论文采用增量随机构造 `Q` 的方式：不断抽 Gaussian 随机向量并扩充正交基，直到残差足够小。

### 这一层最值得学的思路

作者不是只做：

```text
384 次完整 SVD → 384 次 randomized SVD
```

而是两层降复杂度：

```text
先通过代表元复用：减少需要做 SVD 的次数
        ↓
再用 randomized SVD：降低剩下每次 SVD 的成本
```

即：

\[
\text{总复杂度}
=\text{调用次数}\times\text{单次成本}.
\]

优化总成本时，这两个方向应该同时看。

### 评审老师会追问

随机算法必须补：

- 随机种子；
- 多次运行分布；
- 失败概率；
- `epsilon` / rank 怎么选；
- 精度和复杂度曲线。

论文对这些的量化还不够完整。

# 4. Q1 第三层：优化 `W` 的矩阵运算内核

标准流程中：

\[
A=V^HV+\sigma^2I,
\qquad
W=VA^{-1}.
\]

作者重点优化矩阵乘法与求逆。

## 4.1 Strassen：理论快不等于实际快

普通矩阵乘法约为：

\[
O(n^3),
\]

Strassen 递归为：

\[
O(n^{\log_2 7})\approx O(n^{2.807}).
\]

但论文实验发现：直接递归 Strassen 因为大量临时矩阵和函数递归，小规模时反而更慢。

于是作者引入 cutoff `T`：

```text
n < T  → 普通矩阵乘法
n ≥ T  → Strassen 递归
```

论文报告：在 1024 维矩阵求逆测试中，混合 Strassen 求逆相对传统求逆运行时间降低约 **41.5%**。

这是这篇非常值得迁移的一课：

> **渐近复杂度只告诉你 n→∞ 的增长率；比赛里的实际 n 有 crossover point。**

任何递归快算法都应该做阈值实验，而不是看到 `O(n^2.81)` 就默认比 BLAS 快。

## 4.2 利用 Hermitian 结构继续省

`V^H V + σ²I` 是 Hermitian 矩阵，而且 `σ²>0` 后还是正定的。

作者在分块求逆时利用：

\[
A_{21}=A_{12}^H,
\]

减少一部分重复乘法，报告 1024 维时在前述基础上再降低约 **3.2%** 时间。

这个方向是对的：

> **矩阵的 Hermitian / 对称 / 稀疏 / Toeplitz / 低秩结构，本身就是算法资源。**

## 4.3 一个需要纠正的算法归属：所谓 “Coppersmith–Winograd”

论文接下来把一种 2×2 分块的 7 次乘法、15 次加减公式称为 Coppersmith–Winograd，并据此写出接近 `O(n^2.376)` 的理论描述。

但公开附录的函数 `coppersmith_winograd` 使用的正是这类 7 乘、15 加的块公式。

在矩阵乘法文献中，这通常称为 **Winograd's variant / Strassen–Winograd**：

- 仍然使用 7 个半尺寸子乘法；
- 比 Strassen 原始形式减少加法数；
- 递归指数仍为 `log2(7) ≈ 2.807`。

真正的 Coppersmith–Winograd 是另一类基于张量/三线性形式的渐近矩阵乘法构造，不是把 2×2 Strassen 公式简单改成 15 次加法。

因此从公开附录代码看：

> 论文这里更合理的表述应是“在 Strassen–Winograd 变体上进一步优化常数”，而不能把该实现直接赋予 `O(n^2.376)` 的指数。

论文实测“再降低约 2.2% 时间”仍可作为**实现层常数优化**来看，但理论归属和复杂度指数需要重新解释。

## 4.4 存储意识：这是一个很好的亮点

Strassen 的一个工程问题是临时矩阵很多。

作者进一步调整 `M_i` 和 `C_ij` 的生成/释放顺序，让不再需要的临时变量尽快释放，试图把峰值中间存储从约：

\[
7\times64N^2\ \text{bit}
\]

降到约：

\[
64N^2\ \text{bit}.
\]

不论其实现是否达到现代高性能库水准，这个思维非常值得学：

> **算法复杂度不仅有 FLOPs，还有 peak memory、memory traffic 和临时对象生命周期。**

# 6. Q2：压缩——论文真正有效的是低秩分块，而不是 Huffman

作者先讨论了 Huffman 编码。

但原题明确规定压缩结果仍以 32-bit 单精度实数/虚数为存储单元，不能靠改变底层比特长度来减少题目统计的“元素存储量”。

作者最后没有把 Huffman 当主方案，这是正确的。

### 写作上的提醒

Huffman 在正文占用了相当篇幅，但最终不参与主要优化。

如果比赛篇幅紧，我会建议：

> 一段说明“为什么不采用 Huffman”即可，不要让一条被淘汰的路线抢占主模型篇幅。

## 6.1 方法 1：把整个 4 维数据降成一个大二维矩阵再低秩 SVD

W：

\[
64\times2\times4\times384
\longrightarrow
256\times768.
\]

取 rank `m` 后保存：

- `U(:,1:m)`：`256m`
- `S`：`m`
- `V(:,1:m)`：`768m`

共：

\[
1025m
\]

个复数存储单元。

原始 W 一共：

\[
196608
\]

个复数，因此节省：

\[
196608-1025m.
\]

H：

\[
4\times64\times4\times384
\longrightarrow
256\times1536.
\]

按相同逻辑 rank `m` 应存：

\[
256m+1536m+m=1793m.
\]

所以正确节省量应是：

\[
393216-1793m.
\]

但论文公式 (14) 写成了：

\[
393216-1739m,
\]

这是明显的数字顺序笔误/计算错误。

## 6.2 方法 2：256×256 大块分块 SVD——论文最终最好的方案

作者没有对整个矩阵只用一个 rank，而是：

- W 的 `256×768` 分成 3 个 `256×256` 大块；
- H 的 `256×1536` 分成 6 个 `256×256` 大块；
- 每块独立选 rank。

每个 `256×256` rank-`m_i` 块需要：

\[
256m_i+256m_i+m_i=513m_i
\]

个复存储单元。

于是：

\[
S_W=196608-513\sum_{i=1}^{3}m_i,
\]

\[
S_H=393216-513\sum_{i=1}^{6}m_i.
\]

论文报告方法 2 的最高节省：

- H：**19,551,552 bit**；
- W：**8,150,592 bit**。

按原始数据量重新换算：

- H 原始存储：`25,165,824 bit`，最高约节省 **77.69%**；
- W 原始存储：`12,582,912 bit`，最高约节省 **64.78%**。

这是很有价值的结果。

### 为什么分块有效

一个全局 rank 必须照顾最难压缩的方向；分块以后：

```text
容易压缩的块 → 小 rank
难压缩的块   → 大 rank
```

这相当于局部自适应码率。

## 6.3 方法 3：4×4 小块 rank-1——过细了

作者对 H 再尝试 4×4 小块，仅在块高度低秩时做 rank-1 SVD。

理论上更局部，但很多块并不满足条件，能压的块太少，最终效果不如 256×256 大块。

这说明：

> **block size 本身就是超参数。过大不能适应局部秩，过小又失去跨块低秩结构。**

# 7. Q2 的两个关键技术问题

## 7.1 rank 选择没有直接对准 Frobenius dB 误差

正文使用“累计奇异值贡献率”阈值，例如：

- W 方法 1：0.974；
- H 方法 1：0.947；
- W 方法 2：0.966；
- H 小块方法：0.749。

附录 `accumCon` 中甚至又出现固定阈值 `0.99`。

而 `accumCon` 计算的是：

\[
\frac{\sum_{i=1}^{r}\sigma_i}{\sum_i\sigma_i},
\]

即**奇异值线性和**。

但题目的 Frobenius 重构误差天然对应：

\[
\|A-A_r\|_F^2=\sum_{i>r}\sigma_i^2.
\]

所以更严格、直接的方法应该按**平方奇异值尾能量**选 rank：

\[
10\log_{10}
\frac{\sum_{i>r}\sigma_i^2}
     {\sum_i\sigma_i^2}
\le -30\ \mathrm{dB}.
\]

这样不需要先手工试 `0.947/0.966` 再验证，而是直接从官方误差约束解出最小 rank。

## 7.2 附录误差分母口径错了

官方定义：

\[
err_H=10\log_{10}\frac{E\|\widehat H-H\|_F^2}{E\|H\|_F^2}.
\]

但公开附录代码中：

```matlab
sum1 = sum1 + norm(a-b,'fro')^2;
sum2 = sum2 + norm(b,'fro')^2;
error = 10*log10(sum1/sum2);
```

其中 `a` 是原矩阵、`b` 是重构矩阵。

这使分母变成：

\[
\|\widehat H\|_F^2
\]

而不是官方要求的：

\[
\|H\|_F^2.
\]

因此按公开附录代码，`-30 dB` 的验收口径并未严格对齐题面。

# 8. 一个更严重的附录验证问题：rho 公式的 MATLAB 运算优先级

官方 `rho` 本质上是归一化相关量，形式类似：

\[
\rho(a,b)=\frac{|a^Hb|}{\|a\|\,\|b\|}.
\]

按 Cauchy–Schwarz：

\[
0\le\rho\le1.
\]

但是附录多处写成：

```matlab
P(l,i,j)=norm(a'*b)/norm(a)*norm(b);
```

MATLAB 的 `*` 和 `/` 同级、从左到右，因此实际计算的是：

```matlab
(norm(a'*b)/norm(a))*norm(b)
```

而不是：

```matlab
norm(a'*b)/(norm(a)*norm(b))
```

这正好可以解释为什么论文结果图里出现多个 `rho > 1` 的值。

论文把大于 1 解释为 MATLAB 截断/双精度误差，但正常浮点误差只可能造成极微小越界，不会合理解释明显的大于 1。

### 评审结论

这是一个**指标验证层面的重大风险**：

> 按公开附录程序，论文没有用正确公式验证 `rho_min >= 0.99`。

但应保持边界：

- 我们能确认的是**公开论文附录代码存在问题**；
- 不能据此断言作者比赛实际提交和内部最终程序一定完全相同；
- 因此不能直接反推“整个获奖结果无效”。

对我们自己的比赛，教训非常明确：

> **官方 evaluator 必须独立实现，并用手算小样例和数学上下界测试。**

`rho` 这种理论上必在 `[0,1]` 的量，一旦跑出 1.018，就应该立即触发断言，而不是解释成数值误差。

# 9. Q3：作者做了一个可工作的串联系统，但还不是最充分的“端到端共设计”

论文 Q3 基本流程是：

```text
H
↓ 方法2压缩
H_compressed
↓ 解压
H_r
↓ 模方法 + 父子结点 + randomized SVD
V_r
↓ 改进矩阵乘法/求逆
W_r
↓ 再压缩
W_compressed
↓ 解压
W_hat
```

Data4 第一行在这一流程下：

- 384 个 H 分成 180 类；
- 需要计算的 V 数量为原来的 **46.875%**。

这套流程的优点是：

- 前两问方法可以复用；
- 工程上容易实现；
- 论文叙事非常统一。

但 Q3 允许重新设计 `H → W_hat`，所以更激进的做法应该问：

> 为什么要“压缩 H → 解压 H → 再做 SVD → 算 W → 再压缩 W → 再解压”？

如果已经有 H 的低秩因子，是否能直接在低秩空间里计算近似 `V/W`？

也就是说，真正的端到端共设计可以尝试：

```text
H 的低秩表示
    ↓ 不恢复完整 H
直接估计所需子空间
    ↓
在低维因子上求解
    ↓
直接输出 W 的低秩/压缩表示
```

这样可以把**重构本身的计算和内存流量都省掉**。

# 10. 如果今天重新做 Q1：我会优先用 Cholesky / 线性方程，而不是显式求逆

注意：

\[
A=V^HV+\sigma^2I.
\]

由于 `σ²>0`，A 为 Hermitian positive definite。

因此没有必要真的形成：

\[
A^{-1}.
\]

可以把：

\[
W=VA^{-1}
\]

改写为解线性方程。

例如求：

\[
A W^H = V^H.
\]

然后对 A 做 Cholesky：

\[
A=LL^H,
\]

通过两次三角方程求解得到 W。

优点：

- 通常比显式 inverse 更稳定；
- 能直接利用 Hermitian positive definite；
- 计算量更容易精确统计；
- 实际 MATLAB 中可用 `chol` / `\`；
- 也更符合题面自己提示的“可转化为线性方程组”的方向。

这可能比花大量篇幅继续设计通用矩阵求逆算法更贴合本题实际规模。

# 11. 为什么它仍然是一篇很值得学的顶级样本

即便存在上述问题，这篇仍然能让评审产生很强的“算法设计感”。

它的优势包括：

1. **不是套算法，而是在拆计算图。**
2. 从“减少调用次数”和“减少单次成本”两个方向同时优化。
3. 会利用相关性、低秩、Hermitian 等结构。
4. 意识到理论复杂度和实际 runtime 有 crossover。
5. 同时关注运行时间和中间内存。
6. Q2 不是只报压缩率，而是把不同 block size 做了比较。

这说明它的真正获奖价值来自：

> **整体算法路线丰富、有针对性、工程实现充分、问题递进清晰。**

而不是每个公式和程序都无误。

# 12. 指导老师会要求我们补的实验

如果这是我们队的论文，我会要求补至少以下 6 组：

## 12.1 统一复杂度账本

所有方法按官方权重换算成同一个“complexity unit”。

## 12.2 代表元消融

```text
ordinary SVD
randomized SVD only
representative reuse only
representative + randomized SVD
```

比较：complexity / rho_min / runtime。

## 12.3 相似阈值扫描

横轴 `R_critical`，报告：

- 代表元数量；
- 总复杂度；
- `rho_min(V)`；
- `rho_min(W)`。

直接看到 Pareto 前沿。

## 12.4 randomized SVD 稳健性

固定多个 seed，报告均值、最差值和标准差。

## 12.5 block size × rank 选择

比较：

```text
whole matrix
512 block
256 block
128 block
64 block
...
```

同时报告存储 + 编解码 complexity + err。

## 12.6 inverse vs solve

至少比较：

- explicit inverse；
- LU solve；
- Cholesky solve；
- 作者 hybrid Strassen inverse。

且在**相同语言、相同精度、相同硬件**上比较。

# 13. 这一篇最值得我们记住的 8 条

1. **先找结构，再上算法。**
2. 总成本 = 调用次数 × 单次成本，两个方向都可优化。
3. 近似算法必须有官方指标兜底。
4. 渐近复杂度 ≠ 实际 runtime ≠ 题目规定的 complexity score。
5. Hermitian / PSD / low-rank / sparse 不是“性质描述”，而是算法设计入口。
6. 压缩 rank 应直接由官方误差约束决定，而不是靠经验“贡献率”。
7. 指标函数应该有数学不变量断言：`rho ∈ [0,1]`。
8. 开放式 Q3 最好做真正的 end-to-end co-design，而不是机械串联前两问。
