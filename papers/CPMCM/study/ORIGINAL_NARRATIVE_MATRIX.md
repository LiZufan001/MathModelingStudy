# 0. 使用纪律

矩阵严格分三层：

- `ORIGINAL`：原论文实际做了什么、怎样写；
- `RESEARCH_MOVE`：我们对该段研究动作的编码；
- `RECOMMENDED`：结合技术审计后，正赛怎样更严谨地使用。

不要把后两层重新说成作者原话。

另外：**不要在盲做训练前翻本矩阵。** 它用于盲做后的对照、写作训练和赛后复盘。

# 2. 八篇“研究动作卡片”

## 2.1 2022 C｜规则先落成可执行动作，再谈求解器

### ORIGINAL

- 摘要开头先交代：涂装与总装约束不同，因此需要 PBS 重排；随后把调度明确拆成进车入口与出车出口两类动作（PDF p.2）。
- 正文问题一分析先说明车型动力/驱动规律、返回道的现实用途，再写“总体来看”分别确定进车侧和出车侧应关注的量（约 p.10）。
- 当完整模型被表述为混合整数非凸、规模随车辆数增长后，才“针对于此”引出贪心式启发算法（约 p.18）。
- Q2 摘要直接使用“根据问题一中……”和“基于问题一中所述的贪心原则”，不是另起一套算法。
- 结果段不仅给评分，还把附件车型比例、返回道次数与 Q1/Q3/Q4 指标变化联系起来解释（约 p.27）。

### RESEARCH_MOVE

`real rules → executable decisions → computational difficulty → heuristic → comparative interpretation`

### RECOMMENDED

规则型/调度题可模仿这个顺序，但不要把“贪心局部最优”直接表述成连续空间或完整问题的全局最优；应该另给 lower bound / reference / 多策略对照。

---

## 2.2 2020 F｜“新增条件”是连接多问最直接的方式

### ORIGINAL

- 摘要明确写“下面针对每个问题给出方法与结果”（p.2），并且每问同时交代几何/优化方法、关键数值和验证。
- Q1 不是先讲某算法，而是从油面随俯仰角形成矩形/三角形/梯形/五边形等几何状态入手，再分类推导质心公式（p.2 及正文）。
- Q2 先列可行供油组合，指出 7200 s 下枚举规模呈指数增长，“由于问题的计算规模是指数级别，因此设计贪心策略”（p.2）。
- Q4 摘要直接写“问题四与问题二有两方面的不同”，逐项说明目标质心和俯仰角条件变化，再说因此综合使用 Q1 质心公式与 Q2 供油模型（p.3）。

### RESEARCH_MOVE

`base physical evaluator → identify added condition → reuse previous model → modify only affected interface`

### RECOMMENDED

多问题物理题不要强行发明统一口号；比赛过程中维护一张“Q_i 相对 Q_{i-1} 新增/删除条件表”，论文过渡会自然得多。

---

## 2.3 2024 B｜失败结果可以公开推动“改研究对象”

### ORIGINAL

- 问题一分析先写数据集观察、2AP/3AP 系统差异和通信门限含义，再进入数据清洗和 RF（约 p.8–9）。
- 摘要 Q2 特别指出：样本的 SINR 不仅与本行有关，还与同一次实验其他样本有关，因此处理时考虑多行之间影响（p.2）。
- Q2 初版直接预测 `(MCS,NSS)`，正文观察到训练停滞、预测几乎塌缩到同一类别，并明确判断这种模型无法使用；随后重新观察 PHY Rate 与 `(MCS,NSS)` 的映射并改变建模路线。
- 结尾会写 95%+ 验证准确率并直接上升到“良好的泛化能力”（p.2）。

### RESEARCH_MOVE

`data/mechanism diagnosis → first model → visible failure → reframe target → second model`

### RECOMMENDED

这是八篇里最值得保留的失败叙事之一。我们比赛时应进一步补：majority baseline、confusion matrix、group-aware split；然后再说明“为什么改变预测目标”。失败证据越具体，换模型越不显得拍脑袋。

## 2.4 2023 B｜约束本身直接生成研究问题

### ORIGINAL

- 正文先指出原 RMSE 写法若把 β 作为变量可能产生趋零的无意义解，因此直接重新定义目标函数（约 p.7）。
- Q1：“由于仅在非零元素相乘时需要使用乘法器……因此希望 A_k 为稀疏矩阵”（约 p.7/10）。
- 随后指出无额外限制时矩阵搜索空间近乎无穷，“因此”引出 BSVD 结构化近似（约 p.11）。
- Q3 由于稀疏和量化同时改变矩阵，作者把执行顺序本身变成研究对象，比较 Q-S 与 S-Q。
- Q5 并没有把未满足 RMSE 门槛抹掉，而是承认大量测试后仍困难，再讨论补偿/改进。

### RESEARCH_MOVE

`metric pathology → redefine evaluator → constraint semantics → structural method → trade-off experiment`

### RECOMMENDED

算法题最值得学的是“约束语义生成方法”，而不是背 BSVD。每一个新算法前先写清楚：**哪个硬件/计算事实使它必要？**

## 2.5 2022 B｜先改变数据结构，再做组合优化

### ORIGINAL

- 摘要开头先陈述组批现实矛盾：批次小降低利用率/效率，批次大提高利用率但增加交付风险（p.2）。
- Q1 根据三阶段切割规则和大量相等边，先把产品项构造成 2-items，再合成 stack，以 stack 为单位完成最后阶段切割，再组成 stripe/plate（p.2 起）。
- 作者明确说明这样可把三段切割转为两段排样，降低复杂度。
- Q2 直接写“在问题一的基础上”增加订单不可分、材料、数量/面积等约束，把 Q1 排样能力作为后端复用（p.3）。
- 摘要同时给原片数、利用率和运行时间，技术路线几乎在摘要中闭环。

### RESEARCH_MOVE

`real manufacturing constraints → representation redesign → dimensionality reduction → heuristic → upstream batching`

### RECOMMENDED

组合优化题盲做时先问“能否重定义最小决策单元”。如果找到 stack/stripe 这类中间对象，往往比先换 GA/SA/ACO 更有价值。

## 2.6 2020 C｜先构造一个“朴素反例”，再说明为什么要改数据处理

### ORIGINAL

- 摘要 Q1 明确说“考虑到发生 P300 事件和不发生的样本数不平衡”，然后才引出随机排列抽样和平衡训练集（p.2）。
- 正文进一步计算正事件比例很低：若全部预测为负类，表面 accuracy 仍可非常高；这个反例实际削弱了原始 accuracy 的说服力。
- Q2 写“在问题一数据处理的基础上”进行通道选择；Q3 又写“在问题一数据处理和问题二通道选择的基础上”做半监督（p.2）。
- Q3 的方法选择来自资源事实：有标签数据标注耗时，无标签容易取得。

### RESEARCH_MOVE

`naive counterexample → expose misleading metric/data issue → redesign sample construction → resource-aware extension`

### RECOMMENDED

数据题非常适合主动构造“傻瓜 baseline / 反例”：全预测多数类、均值预测、上一时刻预测等。它们不是凑表格，而是用来证明当前评价指标是否真的有信息量。

## 2.7 2024 F｜显式画出“问题分析→模型→求解→验证”，但验证强度要重新校准

### ORIGINAL

- 摘要先说明从理想二体运动切入，再逐步考虑参考系、时间系统和脉冲辐射过程，并宣称采用“问题分析、模型建立、模型求解与结果评估”流程（p.2）。
- Q1 的整体框架图把已知轨道根数、GCRS、二体模型、位置速度和反算验证明确串起来（约 p.9）。
- Q2 明确指出卫星使用地心参考系，而脉冲星星历参数位于太阳系质心参考系，且 TT/TDB 不同，因此必须转换坐标系与时间系统（约 p.22）。
- Q4 观察到低流量情形不满足相邻光子时间间隔趋近 0 的条件，于是提出逆变换采样作为改进（p.3/50）。

### RESEARCH_MOVE

`frame/time semantics → explicit pipeline → forward solve → inverse/internal check → assumption-triggered sampler change`

### RECOMMENDED

可以学它“把问题结构画出来”的能力，但不能照搬“完全相等/有力证明/很高精度”的结论强度。正反算主要证明内部一致，不能自动替代独立外部验证。

## 2.8 2024 E｜从 measurement 一直写到 decision，后一问由前一问暴露的状态缺口产生

### ORIGINAL

- 摘要 Q1 从 YOLOv10m + ByteTrack 提取流量 q、速度 u、密度 ρ，再做交通关系和 10 min 预警（p.2）。
- Q2 不直接凭瞬时点值开应急车道，而是定义区间占用率 K(t)，并结合上下游状态构造启用依据（p.2）。
- Q3 使用前问启用流程做前后情景量化；Q4 从已有监控无法充分描述的区间位置出发增加监控点。
- 正文问题一目录就体现“视频提取→数值特征→基本图关系→拥堵预警→密度预测→视频验证”的连续流水线（p.4 起）。

### RESEARCH_MOVE

`measurement → state → forecast → rule → counterfactual → sensing redesign`

### RECOMMENDED

长链应用题要维护“接口表”：每一层到底向下一层输出什么、误差多大、在哪些条件下有效。Q3 的情景模拟只能写“在假设下预测/估计效果”，不能当成真实道路因果实验。

# 3. 横向学习结果：真正反复出现的 7 个研究动作

八篇原文并没有统一句式，但反复出现以下动作。

## A. 先给会约束方法选择的事实

不是“为了提高精度”，而是：

- 枚举空间指数增长；
- 非零乘法才消耗乘法器；
- 正样本极少；
- 两套参考系/时间系不同；
- 三阶段切割限制组合方式；
- 同一次实验的多行彼此有关。

这类事实一出现，后续方法就有了理由。

## B. 把朴素方案的失败暴露出来

最典型：

- 2024 B：直接多分类塌缩；
- 2020 C：全预测负类也有很高 accuracy；
- 2023 B：原 RMSE 定义允许无意义趋零。

正赛里，一个有说服力的反例常常比多写一页算法介绍更值钱。

## C. 让问题之间通过“对象/条件”相连

常见真实写法不是宏大主题，而是：

- 在问题一基础上；
- 相比问题二新增……；
- 取消某约束；
- 使用前问得到的状态/公式/组合。

## D. 先重表达问题，再换算法

2022 B 的 `item → stack → stripe`、2024 B 的 `直接类别 → PHY Rate → 类别映射` 都说明：

> 改变表示通常比盲目换求解器更重要。

## E. 结果不仅要报数字，还要解释“为什么呈现这个趋势”

2022 C、2020 F、2023 B、2024 E 的结果段都不同程度地把数值变化重新连回车型比例、供油时长、精度-复杂度或交通阶段。

## F. 真正改变路线的失败值得保留

只保留会改变判断的失败，不保留全部调参历史。

## G. 一等奖原文也会过度宣称

因此学习单位必须是：

```text
ORIGINAL expression
+ actual evidence
+ our audit
```

而不是“这句话出现在国一里，所以我们也这么写”。

# 4. 正赛可直接使用的“研究动作检查表”

每一问写正文前，检查下面 8 项：

1. **起点事实**：本问有没有至少一个题意/数据/机理事实，足以限制方法选择？
2. **朴素参照**：有没有 baseline、反例或规模估计，说明为什么不能停在最简单方案？
3. **方法理由**：方法第一次出现前，评委是否已经知道“为什么需要它”？
4. **变量接口**：本问是否明确继承前问哪些量，又新增/删除哪些条件？
5. **路线改变**：如果曾换模型，是否有可观察失败证据，而非“为了提高精度”？
6. **结果解释**：核心表/图是否回答了“发生了什么、为什么、它改变什么判断”？
7. **证据等级**：内部一致、当前验证集、外部对象、真实干预分别写到相应强度了吗？
8. **下一问桥梁**：本问最后有没有明确留下下一问要用的状态、模型或未解决缺口？

如果前 6 项中有两项答不上来，正文大概率会变成“算法说明书”，而不是研究论文。

# 5. 用于盲做后的对照模板

完成 60–90 min Blind Modeling Drill 后，再打开本矩阵，对每篇/每题只填：

```text
我们观察到的关键事实：
国一原文先观察到的事实：

我们第一版 baseline：
国一第一版/最简单路线：

我们为什么选择方法：
国一原文如何引出方法：

我们有没有可见失败：
国一有没有因为失败改变路线：

我们各问之间的接口：
国一各问之间的接口：

最大的“事后看来很自然、盲做却没想到”的点：

下一轮要专项训练的能力：
```

这里最后一项最重要：**把“看懂”转成“下次能自己想到”。**
