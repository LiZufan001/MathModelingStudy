# 华为杯论文叙事与科学论证指南｜让研究过程本身成为核心竞争力

> 本文件不是“写作技巧大全”，而是从前期精读论文中反推：**优秀数模论文如何把一个没有标准答案的问题，研究得科学、有理有据、可追问、可审计。**  
> 核心判断：**“让评委信服”是结果，不是方法。真正的方法是构建一条证据充分、逻辑连续、结论不过界的研究链。**

---

# 0. 我们对“数模拿奖逻辑”的最终修正

数模不是：

```text
选一个高级模型
→ 算出一个漂亮答案
→ 想办法解释
```

也不能只理解成：

```text
把答案验证得很严
```

更准确的是：

```text
开放现实问题
   ↓
提出一个有依据的问题理解
   ↓
把关键机制/结构数学化
   ↓
选择与该判断匹配的方法
   ↓
用实验、理论、对照和边界证据检验
   ↓
形成与证据强度匹配的结论
```

因此最高层对象不是“模型”，也不是“答案”，而是：

\[
\boxed{\text{Defensible Research Chain / 可辩护、可审计的研究链}}
\]

## 科学性具体意味着什么

至少包含六件事：

1. **可操作化**：抽象概念能落到变量、状态、事件或指标；
2. **假设显式**：知道哪些是题目给的，哪些是我们加的；
3. **方法有针对性**：每个方法解决一个已经识别的问题；
4. **证据可区分**：实验能区分“这个解释对”与“其他解释也可能对”；
5. **结论校准**：证据只能支持到哪里，就说到哪里；
6. **可复核**：别人能够沿着公式、数据、代码、表格追回结论。

“说服力”来自以上六件事的共同结果，而不是修辞。

# 1. 回顾：优秀论文最常见的八种叙事骨架

这些骨架比具体算法更值得记。

## 1.1 基础模块逐问复用型｜2020 F、2024 F

### 2020 F

不是四问四模型，而是：

```text
倾斜油箱几何
→ 单油箱质心
→ 整机质心 evaluator
→ 供油控制
→ 初始油量设计
→ 姿态变化场景复用
```

叙事优势：Q1 不是“前菜”，而是后续所有优化的地基。

### 2024 F

```text
轨道状态
→ 时间/参考系转换
→ 传播时延
→ 脉冲相位
→ NHPP 光子流
```

叙事优势：前一问产出的物理状态自然成为后一问输入。

### 可迁移原则

如果 Q1 能构造一个高质量的 `state/evaluator`，后面优先**复用并加层**，不要每问另起炉灶。

---

## 1.2 复杂性拆解 / 结构降维型｜2022 C、2022 B、2023 B

### 2022 C

作者真正的判断是：这不是“318 辆车排序”，而是**带设备运动与资源冲突的动态离散系统**。

于是叙事自然变成：

```text
规则复杂
→ 显式状态机
→ 合法动作
→ 局部调度策略
→ 规则变化后重新设计策略
```

### 2022 B

真正有价值的不是“MIP”三个字，而是：

```text
直接二维排样太大
→ 利用三阶段切割工艺
→ item → stack → stripe → plate
→ Q1 变 packing oracle
→ Q2 只优化订单组批
```

### 2023 B

```text
DFT 精确乘法硬件代价高
→ butterfly 结构
→ 稀疏约束
→ 量化约束
→ 二者联合
→ Kronecker 再降维
→ 残差修正
```

### 可迁移原则

好的叙事不是“我们用了启发式”，而是先让评委看到：

> **原始自由度为什么太大？题目里有什么结构允许我们合法地缩小搜索空间？**

---

## 1.3 瓶颈连续追问型｜2021 A

这篇最像算法研究论文的地方，是每一问都在继续追问“真正贵在哪里”：

```text
有没有重复计算？
→ 相关矩阵复用

单次 SVD 还能不能更便宜？
→ 随机低秩

矩阵内核还能不能更便宜？
→ 优化计算/求解

数据能不能少存？
→ 压缩

计算与存储能否一起设计？
→ 端到端
```

### 可迁移原则

算法题最强叙事之一：

> **不是不断换算法，而是不断定位新的主导成本。**

每次升级都应能回答：

\[
\text{当前瓶颈是什么？本方法减少了哪一项成本？}
\]

---

## 1.4 机理 → 特征 → 预测型｜2024 B

论文不是从“随机森林适合回归”开始，而是先解释 WLAN 的：

- PD / ED / NAV；
- RSSI 门限；
- 同步/异步干扰；
- AMC / PHY Rate。

然后才构造门限越界比例、干扰关系等特征，再进入预测。

### 可迁移原则

数据题的高水平叙事不是：

> “我们尝试 RF、XGBoost、CNN，最终 RF 最好。”

而是：

> “根据系统机制，我们判断原始量需要这样重表达；模型只是负责学习剩余关系。”

即：

\[
\boxed{\text{Mechanism-informed representation} > \text{algorithm shopping}}
\]

---

## 1.5 资源约束统一主题型｜2020 C

四问表面不同：轮数、通道、标签、训练样本。

但更好的统一叙事是：

```text
保持任务性能
vs
减少实验轮数 / 通道 / 标签 / 样本
```

也就是：

\[
\boxed{\text{Resource-efficient learning}}
\]

### 可迁移原则

当多问看起来很散时，尝试寻找一个更高层共同矛盾：

- 性能 vs 资源；
- 精度 vs 成本；
- 收益 vs 风险；
- 信息量 vs 部署复杂度。

一旦找到，整篇论文会从“三四个模型”变成“一项研究”。

---

## 1.6 Measurement → State → Forecast → Decision 型｜2024 E、2025 D

### 2024 E

```text
视频
→ 车辆检测/跟踪
→ q/u/rho
→ 区间积累状态 K(t)
→ 10 min 预测
→ 应急车道滞回控制
→ 反事实效果
→ 传感器重布置
```

### 2025 D

```text
多源观测
→ reference / state estimation
→ 三维场
→ NWP / 短临预报
→ risk field
→ route
```

### 可迁移原则

这类长链题最重要的叙事句式是：

> **上一层输出的不是最终答案，而是下一层需要的状态。**

同时必须把 uncertainty / valid-domain 一起往后传，否则后问会显得比上游证据更确定。

---

## 1.7 对象不断升级型｜2025 C

这篇真正好看的地方不是 Frangi 或 Monte Carlo，而是研究对象不断升级：

```text
pixel
→ fracture mask
→ sinusoidal geometry
→ roughness
→ 3D plane
→ uncertain plane
→ connectivity
→ uncertainty field
→ drilling decision
```

### 可迁移原则

复杂视觉/空间题可以问：

> **这一问结束后，我得到的“对象”比上一问丰富了什么信息？**

如果只是换一个算法，没有对象升级，问题链通常会显得散。

---

## 1.8 主观概念 → 可观察机制型｜2025 F

最值得学习的是先不问“AHP 权重怎么定”，而问：

> “趣味、幻境、有法无式”在空间和游览过程中究竟如何发生？

于是：

```text
软概念
→ 状态 / 变化 / 结构 / 行为机制
→ 局部可观测量
→ 路径/园林级聚合
→ 优化/评分
→ 理论关系 + 外部对象验证
```

### 可迁移原则

综合评价题最核心的一句话：

> **Concept → Mechanism → Metric，绝不是 Concept → AHP。**

# 2. 优秀叙事的最小单元：不是“首先其次最后”，而是五步因果链

一段真正有研究味的正文，建议尽量形成：

```text
观察 / 困难
   ↓
判断
   ↓
方法选择
   ↓
证据
   ↓
结论边界 / 下一步
```

记作：

\[
\boxed{O\rightarrow J\rightarrow M\rightarrow E\rightarrow B}
\]

- `O` Observation：我们看到了什么；
- `J` Judgment：因此如何理解问题；
- `M` Method：所以选择什么数学方法；
- `E` Evidence：什么结果支持这个选择；
- `B` Boundary/Bridge：结论边界，或如何进入下一问。

## 示例：数据模型升级

差：

> 为提高预测精度，本文进一步采用 XGBoost 模型。XGBoost 具有较强的非线性拟合能力……

好：

> 线性基线的残差随输入强度呈明显弯曲趋势，并在高值区域系统低估，说明剩余误差具有非线性结构。因此采用树提升模型拟合残差项。与线性基线相比，高值区 MAE 下降 X%，而普通区间变化有限，说明改进主要来自对该失败模式的修正。

后者让评委知道：**方法不是凭空出现的。**

# 3. 每一问建议按“七段研究链”写，而不是按算法章节写

推荐顺序：

## 3.1 本问核心矛盾

一句话回答：

> “这一问真正难在哪里？”

不是复述题目。

## 3.2 数据 / 机理诊断

展示导致你做出建模判断的事实：

- 数据分布；
- 结构特征；
- 物理规律；
- 计算复杂度；
- baseline failure；
- 资源约束。

## 3.3 建模判断

明确写：

> “因此我们把本问抽象为……”

这是最体现建模能力的一段。

## 3.4 数学模型

公式出现前先解释它**代表什么现实对象**。

公式出现后解释它**测量了什么、什么增大会导致什么**。

不要连续堆三页公式后再统一解释。

## 3.5 求解 / 算法

算法只回答：

> “怎样高效求这个已经定义好的模型？”

不要让求解器反过来定义问题。

## 3.6 验证与反例

至少回答：

- 比最简单 baseline 好在哪里；
- 是否满足 hard constraints；
- 哪些场景最差；
- 参数换一点是否还成立；
- 是否存在独立验证。

## 3.7 本问结论 + 向下一问传递什么

结尾不要只写“模型效果良好”。

而写：

> “本问得到的 X 将作为下一问的状态/特征/reference/evaluator。”

这样整篇自然连起来。

# 4. 多问之间怎么过渡，决定整篇是不是“一项研究”

最差过渡：

> “针对问题二，我们建立……”

更好的过渡必须说明**上一问为什么不足、下一问为什么必要**。

常用四种桥：

### 输出桥

```text
Q1 得到状态 x
→ Q2 需要 x 作为输入
```

### 限制桥

```text
Q1 假设 A 已知
→ Q2 取消 A 已知条件
```

### 资源桥

```text
Q1 高精度但昂贵
→ Q2 研究低成本 surrogate
```

### 决策桥

```text
Q1/Q2 给出预测
→ Q3 真正关心的是如何据此行动
```

如果四问之间没有任何桥，优先重新寻找统一主线，而不是靠“首先其次最后”强接。

---

# 5. 模型选择怎么写，才能显得科学而不是“会什么用什么”

统一模板：

```text
现象/限制
→ 候选方法的适配原因
→ 最简单 baseline
→ 方法升级
→ 对比证据
```

## 五类合法理由

1. **结构理由**：低秩、稀疏、图、层次、守恒；
2. **统计理由**：非线性、异方差、类别不平衡、时序依赖；
3. **计算理由**：精确算法规模不可承受；
4. **信息理由**：单源信息不足、标签不足；
5. **决策理由**：平均误差不足以保证安全，需要 tail risk。

“某算法性能优秀、应用广泛”本身不是充分理由。

---

# 6. 失败模型怎么写：失败不是污点，是研究证据

2025 C 和 2025 D 给了很好的启示。

推荐模板：

> 我们首先尝试 A，因为……。但在严格验证下出现 B（给数字/图），尤其在 C 场景表现失效，说明原假设 D 不成立。因此后续改用 E，并通过 F 验证该调整确实针对上述失效模式。

失败实验只有在满足下面条件时值得写：

1. 它改变了后续路线；
2. 它揭示了一个机制或数据事实；
3. 它不是单纯“参数没调好”。

这会让论文更像研究，而不是成品展示。

---

# 7. 创新怎么表述：创新通常不在算法名

最稳的创新来源依次是：

1. **新的问题表示**：把现实问题抽成更合适的数学对象；
2. **新的变量/状态**：如区间积累量、机制特征；
3. **新的结构利用**：分块、层次、可复用 oracle；
4. **新的模型接口**：上一问输出真正服务下一问；
5. **新的验证设计**：更合理的 group split、下界、反事实；
6. **已有算法的针对性组合**；
7. 最后才是“改进某算法”。

因此摘要里少写：

> “提出改进遗传算法、改进随机森林、改进 AHP……”

多写：

> “利用 X 工艺结构将原始决策空间压缩为 Y 层级”；

> “根据 Z 物理机制构造状态变量”；

> “建立从测量误差到最终决策不确定性的传播链”。

这种创新更容易被评委理解和记住。

# 8. 公式怎么叙事：公式前后各承担一个任务

## 公式前

回答：

> 为什么需要这个量？

例如不是直接写：

\[
K(t)=\cdots
\]

而是先说：

> 单点密度受瞬时噪声影响较大，而应急车道决策更关心整个区间是否持续积压，因此根据车辆守恒构造区间归一化积累状态。

## 公式后

回答：

> 它怎么解释？

例如：

> 当流入长期大于流出时，K(t) 单调增大；当扩容使下游出流提高时，K(t) 的下降速度加快，因此它能直接连接交通测量与控制效果。

**公式是论证节点，不是装饰。**

---

# 9. 图表怎么叙事：一张图只回答一个研究问题

不要用图证明“我们画图能力很强”。

每张图标题旁边应该能写一个问题：

- 这个变量是否真的非线性？
- 高级模型比 baseline 好在哪里？
- 参数是否有稳定平台？
- 模型在哪些样本失败？
- 两个目标如何权衡？
- 哪里最不确定？
- 这一层输出如何影响下一层决策？

正文解释采用：

```text
看到什么
→ 为什么会这样
→ 对模型意味着什么
```

而不是：

> “由图可知，曲线整体呈上升趋势，与预期一致。”

---

# 10. 摘要真正应该讲什么

摘要不是“算法名目录”，而是一份压缩研究故事。

推荐顺序：

```text
现实问题 + 关键困难
→ 核心建模洞察
→ 各问如何沿同一主线推进
→ 最关键证据/结果
→ 一句边界或决策意义
```

每一问尽量形成：

> **任务 → 判断 → 方法 → 证据**

而不是：

> “首先采用 A，其次采用 B，最后采用 C。”

## 30 秒测试

把摘要中的所有算法名删掉。

如果评委仍然能看懂：

- 你认为问题本质是什么；
- 各问怎么连接；
- 做出了什么有意义的判断；

说明摘要有建模思想。

如果删掉算法名后只剩空话，说明叙事还没建立。

# 11. 结论必须和证据强度匹配

建议维护一个 claim ladder：

| 证据 | 合法表述 |
|---|---|
| 内部自洽 | “结果与模型内部关系一致” |
| baseline 更好 | “在当前数据与协议下优于基线” |
| 独立测试 | “对未参与建模的数据具有泛化能力” |
| 反事实仿真 | “在假设 X 下模型预测改善 Y” |
| 实测干预 | 才能更强地说“实施后改善” |

禁止把：

```text
assumption → simulation
```

写成：

```text
empirical causal fact
```

也不要把：

```text
score / index
```

无校准地称为：

```text
probability
```

评委真正容易信服的论文，往往不是结论最猛的，而是**知道自己能说到哪里**。

# 12. 从前期论文反推：哪些表述最有“研究味”

## 12.1 先重新定义题目本质

- “这不是普通排序，而是带设备运动和缓存结构的在线重排。”
- “真正困难的不是整机加权，而是倾斜油箱中的液体质心。”
- “Q1 不是单纯二分类，而是准确率与信息传输效率的共同问题。”

这种句子非常有价值，因为它告诉评委：**我们不是按表面题型做题。**

## 12.2 明确区分官方要求与作者简化

优秀写法应该主动列：

```text
官方约束
vs
为计算可行性增加的假设
```

这会显著提升可信度，也避免近似结果被误写成原问题全局最优。

## 12.3 把方法说成“解决某障碍的工具”

- 由于原始组合空间过大，因此利用工艺层级降维；
- 由于单点状态噪声大，因此引入守恒积累量；
- 由于标签昂贵，因此研究半监督与标签预算；
- 由于 NWP 存在系统偏差，因此先校正再规划。

## 12.4 结果后必须解释“为什么”

不要停在：

> “XGBoost 的 R² 更高。”

要继续：

> “提升主要发生在高强度区，说明模型补偿了线性关系对极值的系统低估。”

这一步才把“结果”变成“认识”。

# 13. 最常见的十种叙事失败

1. **算法展览**：章节按 RF/XGBoost/LSTM/GA 排，而不是按问题判断排；
2. **伪因果**：“为了提高精度，因此采用……”却没有失败诊断；
3. **四问割裂**：每问重置变量和体系；
4. **公式先行**：先堆公式，再补现实含义；
5. **验证装饰化**：只说“与实际一致”；
6. **只展示成功路线**：模型选择显得像拍脑袋；
7. **过度承诺**：仿真结论写成实证因果；
8. **术语堆叠**：创新点全是模型名字；
9. **数字无来源**：摘要/正文/表格不同步；
10. **结论不传递**：Q1 得到的东西对 Q2 没任何作用。

---

# 14. 正赛可直接使用的“研究叙事检查表”

每一问写完后，问自己：

- [ ] 我是否用一句话重新定义了本问的核心困难？
- [ ] 方法出现前，是否已经给出选择它的理由？
- [ ] 是否有一个简单 baseline / 反例证明高级方法有必要？
- [ ] 公式前后是否解释了现实含义？
- [ ] 结果是否不仅“报数”，还解释了机制？
- [ ] 失败实验是否提供了有价值的研究信息？
- [ ] 本问输出是否明确传给下一问？
- [ ] 结论是否严格匹配证据级别？
- [ ] 把所有算法名删掉后，这一问仍然有“思想”吗？

如果最后一项答案是否定的，这一问大概率还只是“算法实现”，不是“建模研究”。

# 15. 最终要让评委看到的，不是答案，而是研究者的判断力

一篇强论文读完以后，评委真正应该形成的印象是：

> 这支队伍知道什么信息重要；  
> 知道为什么做这个简化；  
> 知道什么时候该换模型；  
> 知道什么证据足够、什么证据不够；  
> 知道自己的结论能说到哪里。

因此最终最高原则是：

\[
\boxed{\text{研究判断} \rightarrow \text{数学化} \rightarrow \text{证据} \rightarrow \text{边界}}
\]

**评委的“信服”只是这条链建立成功后的自然结果。**
