# 0. 指导老师先给结论

这篇最值得学习的，并不是论文反复强调的“混合整数规划”，而是一个很典型、也很实用的竞赛工程思想：

> **面对大规模 NP-hard 排样/组批问题，不直接把所有离散变量一次性塞给求解器，而是先利用工艺结构把问题降维，再用快速启发式构造高质量可行解。**

作者的真正求解链条是：

```text
Q1：单批排样
原始 item
   ↓
寻找同边 item，构造 2-Items 候选
   ↓
进一步形成 stack
   ↓
stack 作为最小排样单元
   ↓
把三阶段切割降成“stack → stripe → plate”
   ↓
Improved-Stripe / Best-Fit 类启发式
   ↓
完整坐标排样方案

Q2：订单组批 + 排样
订单
   ↓
按共享材料构造订单相似度
   ↓
递归合并相似订单形成 batch
   ↓
每批再按 material 拆分
   ↓
调用 Q1 排样器
   ↓
得到总板数、利用率和坐标方案
```

从训练角度看，这条链非常值得保留：

- **先找结构，再优化；**
- **先构造可行解，再谈改进；**
- **让 Q1 变成一个可复用 packing oracle，Q2 只负责决定“哪些订单放在一起”。**

但对原题、46 页论文、附录代码和仓库原始 CSV 交叉检查后，也必须明确：

1. 论文所谓 Q1“混合整数规划”没有真正编码二维非重叠、方向、板材选择、三阶段/齐头切等关键约束，不能视为完整可求解 MIP；
2. Q2 的形式化同样没有把 batch assignment 与实际 plate count / packing 子问题联结起来，更像“组批约束骨架 + 下游启发式”；
3. Q1 启发式结果本身很不错：A1–A4 仅比最乐观的纯面积下界多 4–6 张板；
4. Q2 的论文表格中 `dataB2=12 批` 与官方批次面积上限存在数学矛盾：仅总面积就至少需要 23 批；
5. Q2 公开附录按字面不能直接复现：CSV 的订单号是 `order539` 这类字符串，而代码却拿它与整数 `1,2,...` 比较；
6. 相似度正文、公式和代码存在权重/阈值不一致；
7. 论文给出的复杂度 `O(nLW)`、`O(nLWK)` 与实际双重循环、重复两两相似度计算并不相符；
8. 正文中还存在 2240/2440、166/229、B2 订单数、B1 材料数等结果版本不同步。

因此这篇正确的学习方式是：

> **重点学“结构化预处理 + 分层启发式 + 可复用排样器 + 工程结果交付”；不要照搬其 MIP 表述、复杂度公式和公开附录代码。**

# 1. 原题究竟是什么问题

## 1.1 固定工艺条件

官方条件包括：

- 原片尺寸：`2440 mm × 1220 mm`；
- 只允许 guillotine cut（一刀切）；
- 切割阶段数不超过 3；
- 同一阶段方向一致；
- 精确排样；
- 不计锯缝；
- 同一 stack 内 item 的宽度或长度应相同；
- item 必须完整，不能拼接。

这意味着它不是普通 2D bin packing，而是一个带**工艺树结构**的二维 cutting stock / packing 问题。

## 1.2 子问题一

目标：

> 对数据集 A 排样，在满足工艺约束的前提下尽量减少原片数。

如果设总 item 面积为 \(A_{tot}\)，原片面积为

\[
A_p=2440\times1220=2,976,800\ \text{mm}^2,
\]

最简单但有效的理论下界是：

\[
LB_{area}=\left\lceil\frac{A_{tot}}{A_p}\right\rceil.
\]

它忽略 guillotine / stage 等工艺限制，因此只是**乐观下界**，但非常适合评价启发式结果离绝对理论极限有多远。

## 1.3 子问题二

除了 Q1 所有约束，还要求：

- 一个 order 只能属于一个 batch；
- 一个 batch 内，同材质 item 才能共用一块板；
- 每批 item 数量不超过 1000；
- 每批 item 总面积不超过 250 m²。

所以 Q2 实质上是：

\[
\boxed{
\text{batch partition}
+
\text{material partition}
+
\text{guillotine packing}
}
\]

三个离散组合问题叠加。

这正是为什么“全部一次性精确优化”会迅速变得非常困难。

# 2. Q1：作者真正做对了什么

## 2.1 2-Items：利用“同边”结构降维

作者观察到 stack 的最终切割要求 item 有一条边相同，因此先把具有相同长度或宽度的两个 item 组合成候选 `2-Items`。

这个动作的价值不是“把两个矩形粘起来”这么简单，而是：

```text
原始数百个 item
     ↓
候选局部组合
     ↓
把工艺约束提前嵌入结构
     ↓
后面不再从任意矩形布局空间搜索
```

这是典型的 **constraint-driven preprocessing**。

正式比赛遇到类似题，可以先问：

> 有没有某些局部结构一旦满足，就可以提前封装成 super-node / block / pattern？

## 2.2 stack → stripe → plate

作者进一步把 stack 当作最小单元。

因为 stack 内已经完成最终一阶段切割，所以剩余排样从三阶段问题转成：

```text
stack
  ↓ 第2阶段
stripe
  ↓ 第1阶段
plate
```

这是全文最有价值的建模思想之一：

> **不要把“最多三阶段”仅写成几个约束；应该把它直接变成算法的数据结构。**

## 2.3 Improved-Stripe

作者使用大块优先、Best-Fit 风格的规则构造条带，再把条带装入板材。

尽管论文对 \(F_1,F_2\) 的解释和公开代码并没有完全严格对应，但宏观策略合理：

- 大面积/长尺寸块优先；
- 先利用相等边形成完整 stack；
- 再利用小块填补余量；
- 逐条带形成完整板。

这种方法本质上是：

\[
\text{constructive heuristic}
+
\text{local best fit}.
\]

它的优点是：

- 可行性容易控制；
- 坐标结果天然可生成；
- 速度快；
- 对大规模实例比直接元启发式搜索整个二维排列稳定得多。

# 4. 论文所谓 Q1 MIP：为什么不能照搬

论文给出的主要约束类似：

\[
\sum l_j\le L,
\qquad
\sum w_j\le W,
\]

以及“剩余长度小于最短 item 长度”。

问题在于，真正的二维排样至少需要表达：

- item 属于哪块 plate；
- item 是否旋转；
- item 的 \(x,y\) 坐标；
- 两个 item 之间的 non-overlap disjunction；
- guillotine pattern / stage structure；
- plate 是否启用；
- 每个需求 item 是否恰好被满足。

而论文公式中都没有。

因此这些式子不能构成一个可直接交给 MILP solver 的完整二维三阶段排样模型。

更合理的定位是：

> **目标函数与若干容量约束的概念表达。真正求解依赖后面的结构化启发式。**

这点对于我们自己的论文非常重要：

> 如果实际算法并没有求你写出的 MIP，就不要把 MIP 写成“我们的求解模型”。可以把它明确标成“原问题形式化 / theoretical formulation”，再说明实际采用 decomposition heuristic 求近似解。

这样评委更容易接受。

# 5. Q2：相似订单为什么应该放一起

作者 Q2 最有价值的想法是：

> **同一材料如果被拆散到多个 batch，会产生更多无法跨 batch 共享的余料，因此共享材料多的订单更值得合并。**

这是有明确因果链的：

```text
batch boundary
    ↓
相同 material 不能跨 batch 共板
    ↓
material 被切得越碎
    ↓
每个小子问题独立产生尾料
    ↓
总板数增加
```

于是作者定义：

- \(M_1\)：两个订单共享的材料种类；
- \(M_2\)：共享材料上的 item 数量；
- \(M_3\)：不同材料种类。

利用变异系数法得到权重：

\[
0.4780,\quad0.4955,\quad0.0265.
\]

然后舍弃 \(M_3\)，用前两个指标构造 similarity。

这个“**用 packing downstream cost 的代理特征指导 batching**”的思想是正确方向。

# 6. 但 Q2 不能只看利用率：先做硬约束验算

这是本篇最重要的评审教训。

每批官方要求：

\[
N_b\le1000,
\qquad
A_b\le250\times10^6\text{ mm}^2.
\]

因此不管你怎么组批，总批次数都有下界：

\[
LB_{batch}
=
\max\left(
\left\lceil\frac{N_{all}}{1000}\right\rceil,
\left\lceil\frac{A_{all}}{250\times10^6}\right\rceil
\right).
\]

原始数据重算：

| 数据 | item 数 | 面积批次下界 | 数量批次下界 | 必须至少批次 | 论文批次 |
|---|---:|---:|---:|---:|---:|
| B1 | 26811 | 36 | 27 | **36** | 42 |
| B2 | 17952 | 23 | 18 | **23** | **12** |
| B3 | 18028 | 24 | 19 | **24** | 27 |
| B4 | 18526 | 25 | 19 | **25** | 30 |
| B5 | 27901 | 37 | 28 | **37** | 45 |

B2 是无法回避的矛盾：

\[
12<23.
\]

也就是说，如果论文表 6-4 的“12 批”是最终实际组批数，就不可能满足官方 250 m²/批约束。

目前不能仅凭论文确定是：

- 表格抄写错误；
- 实际程序约束没生效；
- 或最终附件与正文版本不同。

但评审结论很明确：

> **论文公开结果无法证明 B2 的组批可行性。**

这比利用率高低严重得多。

正式比赛应先输出：

```text
feasible = true/false
max_batch_items
max_batch_area
order_split_count
```

硬约束全部通过以后，才报告利用率。

# 8. 一个更有意义的 plate lower bound：按 material 分开算

Q2 中不同 material 不能共板。

因此比纯总面积更强的下界是：

\[
LB_{mat}
=
\sum_m
\left\lceil
\frac{A_m}{A_p}
\right\rceil.
\]

原始数据得到：

| 数据 | 总面积 LB | material LB | 论文板数 |
|---|---:|---:|---:|
| B1 | 2979 | **3051** | 3462 |
| B2 | 1927 | **2006** | 2270 |
| B3 | 1934 | **2026** | 2298 |
| B4 | 2031 | **2108** | 2392 |
| B5 | 3090 | **3193** | 3733 |

但要注意：

- `material LB` 仍然允许同一材料跨所有订单/批次自由合板；
- 真实 batch boundary 会进一步切碎 material；
- 还有 guillotine / 3-stage 几何损失。

所以：

\[
N_{paper}-LB_{mat}
\]

不能直接叫“最优性 gap”，只能叫**相对乐观下界的剩余空间**。

这是写论文时非常重要的术语纪律。

# 10. 附录代码的复现风险

## 10.1 order 字符串 / 整数不匹配

原始 CSV：

```text
order539
order317
order392
...
```

公开附录却直接：

```python
for i in range(1, len(set(data[:,4])) + 1):
    index = np.where(data[:,4] == i)
```

如果没有未公开的预处理把 `order539 → 539`，这个比较永远匹配不到。

所以附录 5 **按字面不能直接复现组批结果**。

这只能证明公开附录不完整/有错，不能证明作者比赛时最终运行脚本一定相同。

## 10.2 similarity 权重不同

正文：

\[
0.4780M_1+0.4955M_2.
\]

代码：

```python
s = (similarity1 + similarity2) * 0.5
```

即 0.5 / 0.5。

另外正文算法说“选最高相似度可行订单”，代码又加了：

```python
if similarity > 0.5:
```

这个阈值正文没有明确论证。

## 10.3 官方是 ≤，代码是 <

代码：

```python
if num < 1000 and square < 250000000:
```

官方允许：

\[
\le1000,
\qquad
\le250m^2.
\]

属于保守但不必要地缩小可行域。

## 10.4 “下一个长度最长”并没有显式 argmax

MATLAB 注释说：

> 找下一个长度最长的。

实际：

```matlab
[~,next_ind] = max(all_data(:,3) < m);
```

这是对逻辑向量取 `max`，通常得到**第一个满足条件的位置**，而不是显式选择最长可行组件。

如果数组事先排序恰好保证顺序，可能仍得到预期效果；但实现依赖隐含排序，不应在论文里直接等同于“argmax 最长”。

# 11. 为什么论文的复杂度分析站不住

论文给：

\[
O(nLW)
\]

以及：

\[
O(nLWK).
\]

其中 L/W 被解释成数据“长度总量、宽度总量”。

这不是一个有意义的标准算法复杂度推导。

例如附录 `2-Items` 明确需要比较 item 对，至少存在：

\[
O(N^2)
\]

级候选检查。

Q2 组批代码则不断计算剩余订单的两两相似度：

\[
O(M^2)
\]

每轮合并以后又重新计算，朴素实现总成本甚至可能接近：

\[
O(M^3)
\]

数量级，具体还要乘上 similarity 中材料集合检查的成本。

正式比赛复杂度应该从：

```text
外层循环次数
× 每轮候选数
× 单候选评价成本
```

推导，而不是用物理尺寸 L/W 代替算法循环规模。

“共享材料多 → batch 内更容易共板 → 少碎片”是能解释给工程人员听的。

- plate 数；
- 利用率；
- batch；
- item 坐标；
- 排样示意；

数学建模比赛最终评的是“完整方案”，不是只评一组公式。

# 13. 指导老师会要求我们怎么改

如果今天让我们的队重做这题，我不会推翻作者的结构，而是保留其好处后补上严格性：

```text
1. 官方约束写成唯一 evaluator
2. 建立完整 theoretical formulation
3. 设计 area/material/batch lower bounds
4. Q1 做 stack→stripe→plate constructive baseline
5. 加 local search / multi-start
6. Q2 先做 batch feasible constructor
7. similarity 只作为 surrogate，不当真实目标
8. 调用 packing oracle 反馈真实板数
9. batch swap / move / merge / split 做局部改进
10. 自动生成结果表，防止版本不同步
```

尤其 Q2，最应该升级的是：

> **不要只用 similarity 猜“两个订单合起来好不好”，应该让真实 packing cost 参与反馈。**

可以定义：

\[
\Delta(i,j)
=
C(i\cup j)-C(i)-C(j),
\]

其中 \(C(\cdot)\) 是 Q1 packing oracle 返回的板数。

若：

\[
\Delta(i,j)<0,
\]

才说明合并确实节板。

Similarity 可以用于筛候选，而不是最终决定。

# 14. 本篇最值得迁移的 8 条经验

1. **NP-hard 大题先做结构化 decomposition。**
2. **工艺约束应进入数据结构，而不仅是公式。**
3. **启发式必须配 lower bound，才能知道结果到底好不好。**
4. **formal model 与 actual solver 要明确区分。**
5. **组批问题要先做硬约束下界检查，再看目标值。**
6. **代理相似度最好用真实 downstream cost 校正。**
7. **公开代码必须从原始 CSV 一键复现。**
8. **摘要、正文、表格和附件应由同一结果源自动生成。**
